# Сайт power-grid-env

`web/` — самостоятельный статический сайт: описание проекта, блог и опубликованные
результаты исследований. Конструктор, визуализатор, расчётный API и среда агента
находятся в отдельном приложении [Power Grid Studio](../studio/README.md).

## Локальный просмотр

```sh
npm --prefix web run dev
```

Сайт: `http://localhost:5173`. Нужен Node.js 20+, установка npm-зависимостей не нужна.
Python и работающий сервер Studio для сайта не требуются.

## Проверка и сборка

```sh
npm --prefix web run check
npm --prefix web run check:integration
npm --prefix web run build
```

На хостинг переносится **только `web/dist/`**. Подойдёт обычный статический хостинг;
запускать Node или Python на нём не нужно. В сборке нет инженерных страниц,
сохранённых расчётных сетей, сервера, API или тестов. Сборка работает и после
копирования одного каталога `web/` в отдельный репозиторий.

HTTP-проверка также проверяет сборку из изолированного каталога без исходников
моделера. Сервер локального просмотра отдаёт только опубликованные файлы;
`/api/*`, `/editor.html` и другие маршруты приложения возвращают 404.

## Ссылка на отдельное приложение

По умолчанию адрес Studio не задан. Ссылки ведут на инструкцию запуска в статье
`blog-workbench.html#launch`. Переходы к приложению не привязаны к localhost.

Для своего размещённого приложения задайте `studio_url` в `site.config.json`
или передайте адрес при сборке:

```sh
PGE_STUDIO_URL=https://studio.example.org/ npm --prefix web run build
```

Ссылка сохраняет подкаталог, например `https://example.org/tools/studio/`.
Размещение и сетевая конфигурация приложения настраиваются отдельно.
URL используется **только для навигации**:
сайт не вызывает API приложения, не читает проекты и не подключается к моделям.
В конфигурации нельзя хранить токены; допускается только публичный HTTP(S) URL
без учётных данных, query и fragment.

Для локальной проверки двух процессов:

```sh
PGE_STUDIO_URL=http://localhost:5174 npm --prefix web run dev
PGE_PYTHON=python npm --prefix studio run dev
```

Команды запускаются в разных терминалах. Переменная для локального просмотра
не изменяет исходную конфигурацию и не попадает в следующую обычную сборку.

## Страницы и данные

- `index.html` — описание моделера, обзор инструментов и иллюстративные сценарии.
- `blog.html` — список материалов с фильтрами по темам.
- `blog-training.html` — эксперимент Qwen/SFT, методика и ограничения результатов.
- `blog-physics.html` — способы проверки численных результатов.
- `blog-workbench.html` — запуск и использование отдельного инженерного приложения.
- `site-links.js` — ссылки на Studio, если указан её адрес.
- `assets/learning-experiment.json` — датированный снимок агрегированных результатов.

Первый закрытый тест 4B дал5/6; поздняя проверка28/30 — повторная оценка уже
просмотренного набора. Это не общий промышленный результат. На сайте нет скрытых
заданий, ответов или обученных весов. Опубликованные результаты не означают,
что сайт выполняет обучение или что модель подключена к Studio.

Графики главной страницы — иллюстрации. Их JSON-экспорт содержит
`illustration_only: true` и `physical_solver_used: false`.

Текст статей доступен без JavaScript; `journal.js` добавляет RU/EN и фильтрацию.
Сборка включает локальные шрифты и assets без внешних CDN. Проверяются ссылки,
anchors, уникальность IDs, отсутствие стрелок и корректность снимка результатов.

## Обновление опубликованного статуса

Сайт собирается по сохранённым assets и не зависит от каталогов моделера.
Для явного обновления снимка статуса из полного репозитория:

```sh
npm --prefix web run sync:evidence
```

Команда копирует `plans/CURRENT_STATUS.md` и лицензию. Она не требуется для сборки
и не обновляет результаты обучения автоматически: JSON, статья и проверка снимка
должны оставаться согласованы.

Код — Apache 2.0. Локальные шрифты — OFL-1.1; атрибуция в `assets/FONT-LICENSE.txt`
и `assets/FONT-NOTICE.txt`.

## Визуальные примеры обучения

Статья об SFT содержит два выбранных **TRAIN** примера: одинаковая исходная сеть,
неудачные вызовы базовой4B и успешная последовательность после decision240.
Схемы показывают напряжения и загрузку до/после действий агента; начальные измерения
получены при первом расчёте обученной модели, поскольку базовая модель не сумела
вызвать решатель. Это не новые тестовые результаты и не произвольная иллюстрация.

`assets/learning-examples.json` содержит только выбранные учебные случаи,
сохранённые действия, показатели и hashes источников. Доступны native JSON
исходной и изменённой сети. Они воспроизводят изображённые измерения, но сами
по себе не являются полным исходным агентским эпизодом с каталогом и бюджетами.
SVG — статические схемы для статьи; Studio и Python сайту не требуются.

Обновление из полного локального checkout с sealed reports:

```sh
python -m benchmarks.engineering_blog_examples
python -m benchmarks.engineering_blog_render
npm --prefix web run build
```

Генератор не публикует dev/test, проверяет manifest sources и переигрывает
модельные действия. Физические проверки скачиваемых сетей:
`tests/test_engineering_blog_examples.py`.

Примеры в статье показывают разные решения одного ограниченного профиля: проверку
исправной сети без правок и подбор кабеля с отклонением неподходящего варианта
по реальному preview-расчёту. В `learning-examples.json` сохранены типы решений,
агрегаты 15/15 и 13/15 прежней регрессии, исходные действия и результаты previews.
Они не означают обучение сборке, диагностике аварий или переключениям.
