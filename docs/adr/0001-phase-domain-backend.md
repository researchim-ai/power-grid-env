# ADR 0001. Phase-domain backend

Статус: принято.

Первый расчётный контур — OpenDSSDirect.py 0.9.4 поверх dss-python 0.15.7 (DSS-Extensions). Свой Newton–Raphson не пишется: для заявленного оборудования пробела backend нет, а независимые эталоны (квадратное уравнение, MNA постоянных Z, определение ZIP, сдвиг Dyn11, запирание нулевой последовательности) проверяют отображение, а не заменяют решатель.

Каждый экземпляр промышленного прогона живёт в отдельном процессе `power_grid_env.backend_worker`. Контексты OpenDSS не считаются доказанно потокобезопасными. In-process вызов сериализован замком и используется численными тестами того же кода отображения.

Порог невязки KCL для хорошо обусловленных случаев — `1e-8` о.е. на `s_base` сети, абсолютный пол тока `1e-6` А и мощности `1e-3` Вт. Сравнение с эталоном: `1e-5` о.е. по модулю напряжения и `1e-4` рад после выравнивания опорного угла. Если OpenDSS ставит флаг сходимости, но уставка PQ не выполнена лучше чем на `1e-5` о.е., статус меняется на `numerically_not_converged`. Это не коллапс.
