# Фазная сеть, преобразователи и физически проверяемые исследования

B11 реализован как отдельный ограниченный SI-профиль `phase-network/v1`.
В нём узел — отдельный проводник; `0` — явная опорная земля. Моделируются
R, C, полная симметричная положительно определённая матрица взаимных L,
монотонная магнитная нелинейность, гармонические источники, конечные изменения
сопротивлений, усреднённые GFL/GFM-порты, прямые Γ-двигатели и V/f-приводы.
Все примеры авторские; параметры контроллеров не являются паспортами OEM.

## Запуск

```sh
python -m power_grid_env.cli phase-study run --study cases/studies/phase_four_wire.json --out /tmp/four-wire
python -m power_grid_env.cli phase-study run --study cases/studies/phase_unbalanced_motor.json --out /tmp/unbalanced-motor
python -m power_grid_env.cli phase-study run --study cases/studies/phase_drive.json --out /tmp/vf-drive
python -m power_grid_env.cli phase-study run --study cases/studies/phase_harmonics.json --out /tmp/harmonics
python -m power_grid_env.cli phase-study initialize --study cases/studies/phase_harmonics.json --out /tmp/periodic.json --duration .02 --sample .0002 --max-step .0004
python -m power_grid_env.cli phase-study run --study /tmp/periodic.json --out /tmp/periodic-run
```

Каждый выходной каталог/файл должен быть новым. Источник и результат сохраняются
с хешем производителя и точным manifest. Команды `verify` и `export` проверяют
целостность и создают data-only ZIP. Хеши не удостоверяют авторство отправителя.

## Физика и границы

Единицы — V, A, Ω, H, F, s, W, var, J. Источники и спектры используют **RMS
косинусные фазоры**. DC-тон порядка 0 задаёт постоянное значение; фазовый угол
для него запрещён. Огибающая напряжения непрерывная кусочно-линейная; мгновенных
скачков напряжения на идеальных конденсаторах и скрытых импульсных токов нет.

Ёмкостное динамическое подпространство строится по связности, а не удалением
малых собственных значений. Малый физический C сохраняется. Алгебраические
напряжения восстанавливаются из KCL; плавающие резистивные блоки и чисто
индуктивные cutsets с более высоким индексом отклоняются. Идеальные источники
разрешены только между известным узлом и землёй; произвольные контуры идеальных
источников не поддержаны. Предел API — 128 узлов, 256 индуктивных ветвей и 512
динамических состояний, а не утверждение о проверке всех сочетаний этих размеров.

Нелинейная ветвь: ψ = L·i + ψsat·tanh(i/Isat). Инкрементальная L положительна;
энергия вычисляется как интеграл i·dψ. Проводимость, работа источников, энергия
магнитного поля и C согласованы. Работа и потери интегрируются отдельными
квадратурными состояниями, а не оцениваются только редкими выходными отсчётами.
Топологические события имеют отдельные pre/post-отсчёты, одинаковые события
упорядочены по типу и ID; состояния C/L и накопленная энергия сохраняются.

Прямой машинный порт использует полные обмоточные Γ-уравнения в αβ, механическую
скорость, 1–4 клетки, насыщение и необязательный тепловой баланс. **Изолированная
звезда блокирует нулевой ток**, но обратная последовательность воздействует на
роторную динамику и потери. Размещение задаётся внешними `nodes`; внутренний
паспорт Γ предоставляет коэффициенты. Положительный Gc в новом текущем
координатном порте отклоняется; отдельная прежняя потоковая Gc-модель сохраняется.
Мгновенное размыкание самого обмоточного порта без физической коммутационной
схемы не подменяется обнулением тока.

GFL включает нормированную SRF-PLL, PI, dq-токи и их фильтр. GFM включает
собственный угол, P/Q-droop и ограниченную токовую реализацию виртуального
сопротивления. Это усреднённые трёхпроводные порты; насыщение вектора тока
явное. Поддерживаются остров без внешнего источника, отключение порта и
восстановление. Конкретные параметры защит и OEM-контроллеры не угадываются.

Привод: активный двунаправленный выпрямитель с ограничением тока → DC-C с
PI-регулированием энергии → ограниченный напряжением V/f-инвертор → Γ-двигатель.
Учитываются явно заданные КПД, bleed, медные/механические потери и тепловая
энергия. При исчезновении AC-порта мотор может питаться от DC-C; при глубокой
просадке DC напряжение непрерывно уменьшается до нуля (это усреднённый
нулевольтовый выход, не физический разрыв обмотки). Это не модель полупроводников, PWM или FOC.

Гармонический расчёт сохраняет фазные и нейтральный проводники, взаимные L,
оба направления вращения и нулевую последовательность. THD относится только
к явно запрошенным порядкам. Нелинейные, переключаемые и активные временные
модели не допускаются к линейной суперпозиции. `sequence_neutrals` задаёт
нейтраль монитора; без него измеряются напряжения относительно земли.

Мост `initialize` восстанавливает начальные мгновенные V/I из **всех** объявленных
AC-гармоник линейной схемы. На нелинейные модели этот мост не распространяется.
Финальный фазор EMT — проекция последнего окна на базовую частоту, а не
сертификат установившегося режима при дрейфе частоты. Экстремумы результата
относятся к выходным отсчётам и сторонам событий; это не гарантированные
непрерывные максимумы. Выход ограничен 2 млн скаляров, интеграция — бюджетом
вызовов RHS; библиотечный вызов не является ОС-песочницей или hard real-time.

## Поиск и приближённые модели — B12

```sh
python -m power_grid_env.cli phase-study search --protocol cases/studies/phase_search.json --out /tmp/search-part --max-points 7
python -m power_grid_env.cli phase-study search --protocol cases/studies/phase_search.json --out /tmp/search-full --resume-from /tmp/search-part
python -m power_grid_env.cli phase-study train /tmp/search-full --out /tmp/surrogate --max-error 1
python -m power_grid_env.cli phase-study predict /tmp/surrogate --point '[20,1]' --out /tmp/verified-prediction
```

Детерминированная сетка: 1–3 оси, до 729 физических сценариев. Есть электрические
параметры, уставки DER и параметры V/f. Все неудачные варианты сохраняются;
они делают оценку неокончательной и запрещают обучение. Критический вычисленный
сценарий повторяется физическим решателем с сохранением полной трассы. Область
между точками не объявляется безопасной, непрерывный глобальный оптимум не заявляется.
`--cancel-file` и `--max-points` проверяются между вариантами; продолжение создаёт
новую неизменяемую попытку. После аварийного уничтожения незапечатанного процесса
нужен отдельный разбор; автоматическое восстановление из такого каталога не заявлено.

Surrogate — JSON-полином фиксированной степени с масштабированием координат,
проверками ранга/обусловленности, отдельной заранее определённой holdout-выборкой
и заданным пользователем порогом ошибки в единицах цели. Повторные координаты
запрещены: одна физическая точка не попадает одновременно в train и holdout.
Изменение holdout-меток не меняет коэффициенты модели. Вне выпуклой оболочки
обучения предсказание отклоняется. Историческая версия решателя не принимается
как текущий производитель.

По умолчанию `predict` **повторяет физический расчёт**. `--screen-only` возвращает
непроверенную оценку с `accepted=false` и кодом 2; это фильтрация кандидатов,
не инженерное одобрение. Эмпирическая ошибка holdout не является глобальной
или вероятностной гарантией. Пакетная фильтрация `predict_surrogate_batch`
ускоряет только оценивание, а физическая проверка всех точек добавляет время
полных расчётов. Не загружаются pickle, пользовательский Python и удалённые модели.

## Проверка

```sh
python -m pytest tests/test_phase_network.py tests/test_phase_research.py
python -m benchmarks.phase_research_validation --out /tmp/phase-acceptance
python -m benchmarks.phase_workflow_comparison --out /tmp/cold-comparison --repeats 9
python -m benchmarks.phase_cli_acceptance --python /absolute/venv/bin/python --source . --out /tmp/installed-phase
python -m benchmarks.dae_resource_comparison --out /tmp/dae-resource --repeats 3
```

Есть отдельные точные RL/RLC-решения, независимые SI-ODE в потокосцеплениях для
несимметричного двигателя и V/f, матрица терминальных уравнений четырёх проводов,
проверки PLL, droop, тока, событий и полной энергии. Для типового четырёхпроводного
авторского случая дополнительно используется неизменённый OpenDSS. Сравнение
latency ограничено **cold compile+fundamental solve** этого входа, отдельными
процессами и чередованием порядка. Python startup не включён во время solve,
но входит в lifetime RSS. Это не сравнение cached warm solvers и не доказательство
общего превосходства над OpenDSS. Время измеряется последовательно после других
тяжёлых проверок агента. Отдельный DAE/Radau-профиль измеряет два ранее закреплённых
больших кольцевых случая на коротком окне 0.25 s при зарегистрированной
уставке nominal_1p0; исходная 0.995 проверяется отдельно и её отказ инициализации
сохраняется диагностикой, а не исчезает после смены уставки; память J·v и RSS процесса
учитываются раздельно, результаты долгих режимов из этого не выводятся.

## Два внешних QSTS-фидера B10.1

```sh
python -m benchmarks.acquire_second_smartds

```

Второй фидер p1uhs0_1247--p1udt942 выбран по минимальному Master.dss из
существующего no-loadshapes-кэша до решения; первый исключён. Его собственные
LoadShapes и 56 CSV получены из [официального OEDI S3](https://oedi-data-lake.s3.amazonaws.com/SMART-DS/v1.0/2018/SFO/P1U/scenarios/base_timeseries/opendss/p1uhs0_1247/p1uhs0_1247--p1udt942/LoadShapes.dss).
Фиксация: `requirements/smartds-second.lock.json`, URL, размеры и SHA-256 каждого
из 65 файлов, общий объём 37 537 390 байт. Проверка отличающегося кэша прекращает
работу; существующие файлы не подменяются. Без `--download` только чтение кэша.

Для каждого фидера сравниваются первые 96 и 672 четвертьчасовых отсчёта: прямой
исходный OpenDSS, канонический адаптер, сценарный Engine и весь хвост после
восстановления JSON-снимка посередине окна. Сохраняются сами Engine checkpoints.
Сверка относится к публикационным синтетическим профилям и одной семье решателей;
это не годовой прогон и не полевые измерения. Совместимость второго фидера не
выдаётся за произвольный импорт всех SMART-DS-схем.
