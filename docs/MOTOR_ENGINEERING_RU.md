# Проверяемый пакет пуска и самозапуска: энергия, I²t и три шага

Команда `motor-engineering` объединяет существующие расчёты motor_start с
инженерными ограничениями, отдельным физическим аудитом и уточнением шага.
Поддерживаются действующие Radau и network DAE. Новая физика двигателя не
подменяется упрощённой моделью; проверяются уже рассчитанные состояния и
независимо восстановленные уравнения.

## Расчёт и решения

Каждый случай выполняется заново в изолированном доверенном worker на шагах
`h`, `h/2`, `h/4`. У этих параметров одновременно меняются output grid и
ограничение шага интегратора; rtol/atol остаются исходными. Все три расчёта
должны завершиться и пройти аудит. Два последних сравниваются по конечной
скорости, I²t, электромагнитной работе и работе нагрузки. Инженерный вердикт
по скорости, току, напряжению, восстановлению и защитам должен быть одинаковым
на всех трёх сетках. Пограничное расхождение — неквалифицированный результат,
даже если самый мелкий шаг выглядит благоприятно.

`completed` означает завершённые расчёты. `numerically_qualified` означает
прохождение объявленного численного протокола. `engineering_acceptable`
требует также выполнения ограничений режима. Для `purpose=regression`
ожидаемый затяжной разгон/тепловое отключение может дать
`validation_passed=true`, сохранив `engineering_acceptable=false`.
Таким способом отрицательный инженерный исход не превращается в допуск.

Профиль v1 ограничен balanced RMS, single-cage, motor_start/scipy,
максимум 8 двигателями, 8 случаями и 10 секундами на случай. На самом мелком
шаге допускается не больше 16000 интервалов. Эти верхние bounds не являются
опубликованным измерением всех сочетаний размеров. Независимая приёмка ниже
проверяет конкретные одно- и двухдвигательные схемы. Полные потокосцепленные,
насыщенные и многоклеточные компоненты проекта этим аудитом не квалифицируются.

## Что проверяется физически

Параметры каждого двигателя имеют собственную базу `rated_va` и собственный
`inertia_s = H`. На валу:

`E_kin = H × rated_va × speed_pu²`

`ΔE_kin = ∫ rated_va × (Te_pu − Tload_pu) × speed_pu dt`.

Сравнивается максимальная накопленная невязка **по всем префиксам** траектории,
а не только разность в конце: ошибки противоположного знака не могут скрыться
за компенсацией. Отдельно проверяются непрерывность скорости на коммутациях,
покой при cold start либо уравнения начального равновесия при operating point.

По паспортным сопротивлениям/reactances и комплексным `V`, `E` восстанавливаются
ток, момент и P/Q. Они сверяются с записанными каналами. Проверяются напряжение
на замкнутых/разомкнутых контактах, независимая формула механической нагрузки
и хронологический load-torque schedule. Production RHS и `motor.constants()`
для этих проверок не вызываются. Это аудит согласованности уравнений;
независимая SI-интеграция — отдельный следующий уровень проверки.

`I²t` вычисляется для RMS-огибающей в `pu²·s`, также выдаётся интервалный RMS
ток в амперах. Произведение двух линейных интерполянтов интегрируется точно.
Дублированные pre/post-event точки имеют нулевой временной интервал: скачок
не усредняется через событие. Неполные стороны события и дискретные изменения
между обычными точками отвергаются.

Для тепловой реплики дополнительно проверяется интегральное уравнение
`Δθ = (∫ I_pu² dt − ∫ θ dt) / τ`, исходное тепло, непрерывность θ и
защёлка отключения у порога. Это dimensionless stator-current replica,
не температура обмотки, ротора или hot spot. Электрическая запасённая энергия
статора/ротора этим shaft-аудитом не проверяется. Токи и минимумы напряжения
остаются sampled RMS; мгновенный ударный EMT-ток не оценивается.

## Неизменные критерии и найденный отрицательный пример

По умолчанию допуск баланса вала — `2 J + 5e-4 × energy_scale`.
Тепловое интегральное уравнение имеет абсолютный допуск `5e-4`;
тонкая пара интегралов — относительный `0.002`; конечная скорость — `1e-5 pu`.
Полный набор записан в input artifact до запуска.

В thermal_cold_trip шаги 10/5/2.5 ms дали невязки теплового уравнения около
0.01870/0.003848/0.0009233, хотя сама траектория совпала с независимым SI-решателем.
Причина — недостаточная частота выборок для интеграла, не ошибка ODE.
Допуск не ослаблялся: пример переведён на 1/0.5/0.25 ms. Негативная регрессия
с исходным редким sampling сохранена в тестах.

## Независимая проверка

`benchmarks/motor_engineering_acceptance.py` покрывает восемь законченных случаев:
прямой пуск; затяжной одновременный пуск; ступенчатый пуск;
провал питания нагруженной группы; выбег/повторное замыкание;
тепловое отключение; автоматический ступенчатый самозапуск;
слишком поздний самозапуск без полного восстановления.

Эталоны — существующие независимые SI rotor-flux/stator-rotor circuit equations,
DOP853, отдельная тепловая state/root-задача. Таймеры контакторов для выбранных
глубоких source plateaus выводятся из входных паспортов и времён 0.2/0.5 s,
а не из production event log. Это не универсальный oracle произвольного
порогового детектора или дребезга напряжения. Тепловая точка отключения
находится независимым root solver, не копируется из результата моделера.

Сверяются скорость, ток, напряжение, комплексные E, P/Q, а для теплового
случая θ и время срабатывания. I²t также пересчитывается по SI-токам отдельной
midpoint+slope формулой. Нужны точное покрытие корпуса и прохождение всех
исходных лимитов. Независимый эталон — авторский software reference,
не натурные измерения и не сертификат OEM.

## Использование

```bash
power-grid motor-engineering --input cases/motor-engineering/dol-restart-three-grid.json --out reports/motor-engineering
power-grid verify-motor-engineering reports/motor-engineering
PYTHONPATH=. python benchmarks/motor_engineering_acceptance.py --out reports/motor-engineering-acceptance
python -m pytest tests/test_motor_engineering.py
```

Выходной каталог должен быть новым. Сохраняются input, три study/result/audit
для каждого случая, consensus summary и bounded SHA256 manifest.
Verifier заново вычисляет аудит и выводы по сохранённым трассам и исходному
плану; это не повторный запуск ODE и не аутентификация автора артефакта.
Неполные/отменённые/просроченные расчёты не получают допуск. Локальный worker
имеет deadlines и лимит результата; он не является OS sandbox.

Это физическая основа для последующих LLM-задач. Экспорт multimodal SFT,
предъявление Qwen только разрешённых наблюдений и VLM GRPO остаются отдельной
реализацией; скрытые результаты и gold-вердикты нельзя просто вложить в prompt.
