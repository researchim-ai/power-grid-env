# Локальная приёмка B03.3b / B04.1b / B05.3b

Эти профили проверяются без оборудования, GitHub и CI. Корпус описывает
конкретные модели и режимы; он не подтверждает все возможные сочетания API.
Итоговое свидетельство: `reports/blocks-final-root-fix-2026-11-06/summary.json`.
Статус принимается только при `passed: true` и совпадении отпечатка пакета.

## Сквозные производные

`power_grid_env.study_sensitivity` заново валидирует, инициализирует и решает
полное исследование для каждого возмущения параметра. Три центральные разности
с шагами h, h/2, h/4 проверяют сходимость; отдельно проверяются односторонние
производные и порядок событий. При касании, изломе или смене последовательности
выдаётся `available: false` с причиной. Численный градиент нельзя использовать
как доказательство существования производной за пределами проверенной окрестности.

Пять приёмочных направлений: параметр сопротивления источника в нагруженной
PV-инициализации, выдержка АВР, задержка контактора, верхняя граница возбуждения
и активная граница UEL. Для PV используется независимая неявная SI-производная;
для выдержек и присваивания границы — точные производные. Входы, шаги,
возмущённые результаты и их идентичности сохраняются в JSON.

`hybrid_resets` дополнительно предоставляет разреженные действия производных
локальных аффинных сбросов, включая несколько направлений и явные параметры.
Порядок некоммутирующих операций сохраняется. Это не общий аналитический adjoint:
таймеры, согласованная инициализация и полный каскад учитываются повторным решением.
Неизвестный локальный сброс отклоняется.

```sh
python -m power_grid_env.cli sensitivity-study \
  --study cases/sensitivity/ats-study.json \
  --protocol cases/sensitivity/ats-request.json --out /tmp/ats-sensitivity
```

Каталог назначения должен быть новым. Сохраняются входы, результаты и манифест
SHA-256. Неопределённая производная даёт код выхода 2.

## Длительная сеть и острова

Четыре исследования длительностью 45 с: Radau и network DAE, каждый с допустимым
и недопустимым соединением. Сеть разделяется на два нагруженных генераторных
острова и остров внешнего источника; учитываются реальные задержки выключателей,
механические возмущения, повторное разделение и контроль синхронизма. Независимый
эталон решает собственные SI MNA-уравнения и динамику GENCLS методом DOP853.
Идемпотентная команда выключателю проверяется как `already_in_requested_state`.

Дополнительная точка: 30 с, 512 узлов, 32 двухклеточных двигателя, 8 GENROU,
активные PSS/OEL2C/UEL, несколько провалов питания и изменений задания.
Для длительного профиля задано 900 с интеграционного времени; исходный
лимит 1024 пакета событий сохранён. Диагностика обнаружила повторную отмену
уже принятого корня OEL2C при неизменном состоянии в тот же момент из-за
округления времени. Принятый переход теперь сохраняется для той же пары
время/значение критерия и принятого дискретного состояния. Изменение состояния
или времени разрешает обычную повторную проверку. Дополнительный гистерезис
и изменение точностных допусков этим исправлением не вводятся. Попытки с
лимитами 1024 и 8192 до исправления сохранены как неуспешная диагностика.
Оба интегратора сравниваются с независимым FMI Model Exchange master/CVODE:
оригинальные закреплённые блоки Dynawo OEL2C и PSS, независимая сеть/машины.
Сравниваются каналы машин, клеток, тепловых и управляющих состояний и баланс сети.
Режим `event_trace=sampled_controls` сохраняет все журнальные события и состояния
на регулярной сетке, но не добавляет полную копию всех состояний на каждом
внутреннем корне регулятора. Физические коммутации сохраняют обе стороны скачка.
Шаги интегрирования и физика этим режимом не меняются.

Для локального запуска нужны исходные FMU из сохранённой квалификации и
закреплённый wheel FMPy 0.3.27. `requirements/joint-long-fmu.lock.json` содержит
хеш каждого файла, происхождение и компилятор. Проверка готового кэша:

```sh
python -m benchmarks.precompiled_joint_reference \
  --cache data/external/joint-long-fmu --runtime /tmp/pge-fmi-runtime
```

Опции `--archive` и `--wheel` восстанавливают новый кэш из локальных артефактов.
Нужны также LICENSE/AUTHORS исходного Dynawo; их SHA-256 закреплены. Кэш исключён
из Git. Повторное использование FMU не называется новой компиляцией. Паспорта
сравниваются строго, начальные состояния независимо переустанавливаются и
проверяются оригинальным FMI master. Без локальных исходных артефактов такой
прогон не объявляется воспроизведённым. Существующий путь компиляции остаётся
в `benchmarks.oel2c_model_exchange`.

Процессы сохраняют время и максимальный RSS. Некоторые проверки исполняются
параллельно: это свидетельство выполнимости, а не честное сравнение скорости.
Проверенные большие точки предыдущего этапа остаются отдельными свидетельствами.

## Полный потокосцепленный двигатель с защитой

Три набора Aalto: линейный и насыщенный вентилятор, насыщенный вязкий привод
с температурными сопротивлениями. Восемь случаев: пуск с провалом/восстановлением
и заторможенный ротор для каждого набора, температурное отключение, охлаждение
со сбросом и повторным включением. По два повтора первичного расчёта, независимый
оригинальный motulator 0.19.0 и отдельно написанная фазная RC/MOV-сеть/защита.

Трёхполюсный контактор имеет конечное сопротивление в отключённом состоянии,
параллельные ёмкости и пассивные ограничители перенапряжения MOV. Все токи,
потоки и напряжения ёмкостей сохраняются при коммутации. Проверяются KCL и
электромагнитный/механический/тепловой баланс энергии. Это явно заданный
RC/MOV-профиль, а не идеальная гальваническая развязка или модель дуги OEM.
При замыкании заряженных конденсаторов возможен большой локальный импульс:
токи полюсов и конденсаторов экспортируются отдельно; пригодность контактора
по его коммутационной способности этим корпусом не устанавливается.

Реле: I²-реплика первого порядка, уставка, гистерезис сброса, реальная задержка
размыкания и дополнительный температурный порог для теплового набора. Пока
отключение ожидается или защита не сброшена, включение блокируется. Уставки,
механика и тепло — явно авторские тестовые параметры, не заводская калибровка.
Тепловая граница применимости паспорта проверяется отдельно.

```sh
python -m power_grid_env.cli protected-motor \
  --catalog aalto-saturated-fan --mode restart --out /tmp/protected-restart
python -m power_grid_env.cli protected-motor \
  --study cases/protected/restart.json --out /tmp/protected-json --require-acceptable
```

Результат содержит разгон, токи, напряжение во время провала и при доступном
питании, нагрев, срабатывания, сохранённый JSON и автономный HTML-отчёт.
Максимумы токов — по экспортированным отсчётам; RMS-equivalent αβ-величина
не называется измеренным скользящим RMS или гарантированным непрерывным пиком.
Без `--require-acceptable` корректно рассчитанное защитное отключение успешно
как расчёт; с этим флагом инженерное отклонение возвращает код 2.

## Повторение корпуса

```sh
OPENBLAS_NUM_THREADS=1 \
PYTHONPATH=.:/tmp/pge-network-native MPLCONFIGDIR=/tmp/pge-mpl \
PGE_MOTULATOR_WHEEL=/tmp/pge-network-native-wheels/motulator-0.19.0-py3-none-any.whl \
python -m benchmarks.closure_acceptance --out /tmp/new-block-acceptance
```

Указанные временные пути — подготовленное локальное окружение, не встроенные
зависимости пакета. Отчёт проверяет неизменность исходников, замораживает входы
и хеши артефактов. Ошибка любого worker не превращается в успешную приёмку.
Обязательные тестовые файлы закреплены в
`requirements/release-balanced-dol-linux-py312.json`.
