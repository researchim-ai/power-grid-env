# OEL2C: равновесие с регулированием тока возбуждения

Дата реализации: 2026-11-03. Это продолжение [инициализации с исчерпанным PID](OEL2C_ACTIVE_EQUILIBRIUM_RU.md): теперь доступна отдельная внутренняя ветвь PID, на которой начальный регулируемый ток равен `ILimPu`.

## Как задать задачу

В паспорте OEL2C обязательны:

```json
{
  "generator_id": "g2",
  "model": "OEL2C_Dynawo_equilibrium_guard_v2_SEXS_summation",
  "initialization": "current_regulating_equilibrium",
  "avr_reference_initialization": "specified_for_current_regulation",
  "specified_avr_reference_pu": 1.10,
  "regulating_voltage_bounds_pu": [0.85, 1.10],
  "rated_field_reaction_pu": 0.8,
  "ILimPu": 1.3,
  "KpOel": 0.1,
  "KiOel": 0.1,
  "KdOel": 0.002
}
```

Нужны GENROU, SEXS и совместная загруженная начальная точка. Пример: `cases/studies/generator_oel2c_regulating_voltage_up.json`.

```bash
python -m power_grid_env.cli run-study cases/studies/generator_oel2c_regulating_voltage_up.json --out reports/regulating.json
```

Задание активной мощности генератора сохраняется. Вместо начального PV-уравнения напряжения решается `KAct*KScale*abs(field_reaction)/rated_field_reaction_pu = ILimPu`. Напряжение становится результатом совместного решения сети, двигателей и генераторов; оно должно строго лежать в заданном интервале. Прежний `v_set_pu` используется как начальное приближение. Для других генераторов PV-ограничение сохраняется. Нормировка тока остаётся входным физическим параметром. Ток здесь — нормированная реконструкция реакции поля GENROU; перевод в амперы требует данных машины.

`specified_avr_reference_pu` — заданный вход AVR, он не подбирается алгоритмом. Требуемая сумма OEL равна `baseline_AVR_reference - specified_AVR_reference` и должна лежать строго внутри диапазонов PID и обоих lead-lag. Если это невозможно, расчёт отклоняется. В `operating_point.initial_voltage_constraints` и `oel2c_AVR_reference_initialization` записаны ограничения и их фактические значения. Диагностика не выдаёт исходное PV-задание за решённое напряжение.

## Начальные состояния и устойчивость

Все восемь состояний OEL решаются с проверкой исходных производных до `1e-8 1/с`. Измеритель получает фактический ток, токовая уставка и её фильтр — `ILimPu`; PID и lead-lag воспроизводят требуемое ненасыщенное воздействие. Тепловой таймер должен находиться строго в горячей ветви. Верхний предел таймера допустим только при строго направленной наружу свободной производной. Произвольные точки на границах режимов пока отклоняются.

Проверка начальной устойчивости включает непрерывные состояния регулирующего OEL вместе с машинами, двигателями и регуляторами. Удерживаемые ограничителем координаты токовой уставки и, при необходимости, таймера исключены. Выбираются конечные разности, сохраняющие ветви ограничителей. Неустойчивая либо почти нейтральная точка отклоняется; коэффициенты автоматически не перенастраиваются. Старые коэффициенты `KiOel=2, KpOel=0.3, KdOel=0.01` для этого нового примера действительно дают неустойчивый контур — это отдельная отрицательная проверка.

Спектр условный: горячая ветвь и фиксированные дискретные режимы. Это не доказательство общей гибридной устойчивости и не поддержка OEL в публичном `coupled_small_signal`.

## Почему отдельный equilibrium-guard-v2

При равенстве токов исходные строгие сравнения Modelica могут запускать часы из-за округления независимых алгебраических решателей. Явно названный v2 наследует cap-guard-v1 и добавляет только численный интервал сравнения `ICmpTolPu` (по умолчанию `1e-8 pu`) к условиям запуска и сброса часов. Формулы PID, lead-lag, тепловой памяти и ограничителей не меняются. Это объявленная модификация источника, а не утверждение о побайтовом совпадении с исходным Dynawo.

В Python параметр называется `current_comparison_tolerance_pu`; проверяются представимость и малость относительно диапазона токовых пределов. V1 сохраняет прежние точные сравнения и прежнее поведение. Скопированные исходные замыкания v1/v2 проверяются побайтово относительно зафиксированного исходного дерева. Файл Dynawo остаётся под MPL-2.0; исходники и лицензии сохраняются рядом с нативными артефактами, лицензия включена в wheel.

## Независимая сверка

```bash
python -m benchmarks.dynawo_reference_setup --root /tmp/pge-oel2c-reference
PGE_DYNAWO_REFERENCE_ROOT=/tmp/pge-oel2c-reference python -m pytest tests/test_oel2c_regulating.py
python -m benchmarks.generator_oel2c_regulating_validation --root /tmp/pge-oel2c-reference --out reports/oel2c-regulating
```

Эталон самостоятельно решает SI-сеть с неизвестными напряжениями регулирующих генераторов, восстанавливает ток возбуждения и инициализирует нативный OEL2C. В FMI 2 Model Exchange/CVODE работают исходные Modelica-компоненты с явно объявленным v2. Начальные состояния, RHS, матрицы сети и часы производственного решателя в эталон не передаются. Дополнительный тест запрещает вызовы производственных методов инициализации/восстановления поля.

12 случаев: удержание, шаг AVR вверх/вниз, механический шаг, отключение двигателя, два регулирующих OEL, смесь с неактивным OEL, насыщение GENROU, другая заданная уставка AVR, масштабирование входа, верхний предел таймера, тепловая память поля. Для каждого выполняются три нативных расчёта `1e-8/1e-10/1e-12`. Проверяются все обязательные каналы, комплексные узловые напряжения, стороны физических событий, начальный аудит AVR и сходимость. Часы сравниваются с допуском `1 мкс`, дискретные флаги — точно; численные критерии не ослабляются при провале грубого допуска.

Дополнительно независимо дифференцируются SI-растение и нативный FMU. Все условные полюса сопоставляются взаимно-однозначно; нормированная ошибка `abs(lambda_primary-lambda_native)/(1+abs(lambda_native)) <= 1e-4`, обе спектральные абсциссы строго отрицательны. Удаление одного полюса считается ошибкой инвентаря, а не допустимым улучшением результата.

12 отрицательных задач проверяют отсутствие явных входов, несовместимую политику/модель, холодную ветвь, недоступное воздействие, выход за диапазон напряжения/Q, неустойчивые коэффициенты и отсутствие загруженной начальной точки. Ошибка не возвращает частично успешную траекторию.

## Границы результата

Начальное равенство регулируемого тока не означает соблюдения лимита во всём переходном процессе. Отдельно остаются критерии допустимого тока/температуры на всём интервале, выбор произвольных граничных ветвей, takeover-подключение AVR, расширенная OEL/UEL/PSS/fault-матрица, удалённая CI и сравнение на одинаковом публичном наборе задач с другими симуляторами. Проверяется отдельный нативный OEL в независимой SI-сети; целая штатная сеть Dynawo не квалифицирована. Собственное лабораторное оборудование для этого протокола не требуется.
