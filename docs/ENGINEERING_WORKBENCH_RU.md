# Локальное инженерное рабочее место

`workbench` объединяет версионированное определение StudySpec, предварительную
проверку, отдельный процесс решателя, сравнение, графики и перенос результатов.
Все действия локальные. Сервисы, GitHub и CI не нужны.

## Первое исследование

После установки пакета из корня исходников:

```sh
python -m power_grid_env.cli workbench create cases/studies/flux-saturated_dol.json --dir /tmp/my-grid-project
python -m power_grid_env.cli workbench check --dir /tmp/my-grid-project
python -m power_grid_env.cli workbench run baseline --dir /tmp/my-grid-project --timeout 120
python -m power_grid_env.cli workbench run repeat --dir /tmp/my-grid-project
python -m power_grid_env.cli workbench compare baseline repeat --dir /tmp/my-grid-project --out /tmp/comparison.json
python -m power_grid_env.cli workbench export baseline --dir /tmp/my-grid-project --out /tmp/grid-study.zip
python -m power_grid_env.cli workbench restore /tmp/grid-study.zip --dir /tmp/restored-grid
python -m power_grid_env.cli workbench run replay --dir /tmp/restored-grid
```

Каталоги проектов и выходные файлы должны быть новыми. Отчёт находится в
`runs/baseline/report.html`: его можно открыть без сервера и сети. Есть выбор
канала с единицами, график, экспорт CSV/SVG, схема исходной топологии, события,
происхождение запуска и редактор JSON. Изменённый JSON сохраняют в файл и
передают `workbench revise study.json --dir ...`, затем выполняют `check` и новый
`run`. Редактор не запускает Python или решатель внутри браузера.

Поддерживаются режимы мощности и QSTS/OpenDSS, RMS и малые колебания/ANDES,
пуск двигателя, связанная RMS-динамика и полные потокосцепления/SciPy в пределах
существующих профилей моделей. Для результатов малых колебаний без временных
каналов сохраняется исходный результат; временной график не выдумывается.

## Длительные исследования

Для QSTS можно задать `--max-steps 10 --checkpoint-every 1`. Остановка с
`status=paused` имеет код выхода 2 и не означает завершённое исследование.
Продолжение выполняют с новым ID: `workbench run continued --resume-from part
--dir ...`. Исходный запуск остаётся неизменным. Перед продолжением проверяются
хеши и совпадение определения исследования. Команды `cancel` и `clear-cancel`
управляют локальным флагом: QSTS получает время на запись checkpoint, остальные
задачи останавливаются вместе с группой процесса. Таймаут, отказ и отмена не
получают статус успешного расчёта. Максимальный таймаут — 3600 секунд.

## Обмен и полнота

`workbench import --source model.dss --dir ...` использует существующий импортёр;
`--sidecar` передаёт его дополнительные параметры. В проекте сохраняется отчёт
о переносе: неподдержанные команды, пропуски, допущения и аппроксимации.
Неполный перенос не объявляется полным. Неудачный импорт не подставляет старую
сеть. Полнота переноса и пригодность физического профиля проверяются отдельно.

Ревизии и завершённые попытки неизменяемые по API. SHA-256 manifest фиксирует
точный состав, входы, результат, журналы и отчёт. Проверка отклоняет добавление
файлов, подмену и символьные ссылки. ZIP переносит только данные: запрещены
выход за каталог, дубли путей, ссылки, шифрование; ограничены размер и число
файлов (64 MB на файл, 256 MB на набор, 4096 файлов). Хеши подтверждают
целостность, но не авторство и не доверие к отправителю.

Сравнение требует совпадения каналов, единиц, времён и сторон событий. Нет
скрытой интерполяции; пропущенные измерения не становятся нулями. Порог:
`absolute + relative * abs(baseline)`. Сравнение не заменяет критерии выбора
оборудования. Схема в отчёте показывает исходное состояние, а не анимацию событий.

## Воспроизводимая локальная приёмка

```sh
python -m pytest tests/test_engineering_project.py
python -m benchmarks.engineering_workbench --python /absolute/installed/venv/bin/python --source . --out /tmp/workbench-acceptance
```

Вторая команда выполняет сквозные CLI-процессы установленного пакета из пустого
каталога, включая экспорт, восстановление, повторение, отказ перезаписи и
продолжение QSTS. Нужен установленный пакет с зависимостями; сеть не используется.
Это проверка на одном host, не внешняя аттестация.

## Локальный корпус длительных режимов

`python -m benchmarks.local_qsts_acceptance --out /tmp/qsts-acceptance`
выполняет сутки (96 интервалов) и неделю (672 интервала) первого уже сохранённого
SMART-DS. Данные не скачиваются. Сохраняются хеши исходников и каждого входного
файла, сверки native OpenDSS/адаптер, checkpoint/replay, Engine/direct. Нет данных,
ошибка продолжения или изменение входов означают провал приёмки. Это синтетические
открытые профили и проверка переноса в одном семействе решателей; второй внешний
фидер и независимый физический решатель этим не квалифицируются.
