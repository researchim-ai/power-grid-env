# NA-10: независимая проверка восьми генераторов и 32 двигателей

## Область проверки

Профиль `eight_machine_v1` расширяет независимую физическую SI-схему до восьми
GENROU/TGOV1, 32 double-cage двигателей и 512 узлов. Три исходных сценария
NA-09 сохранены без изменения входов: `max_genrou_8_32`, `max_esst_8_32`,
`max_genrou_long_8_32` (0,8 / 0,8 / 6 секунд). Их SHA-256 закреплены в
`benchmarks/eight_machine_validation.py`. Отдельный `motor_trip_latch` проверяет
тепловое отключение двигателя и блокировку повторного включения.

Это независимая проверка динамики, а не только сравнение плотного и разреженного
якобианов одного решателя. Производственные уравнения этим блоком не меняются. Исправлен входной
валидатор: тепловая защита, как и автоматический контактор, может разомкнуть
двигатель между командами. Повторное включение теперь доходит до обработчика,
который явно сообщает `blocked_thermal_latch` или `already_in_requested_state`.
Для двигателя без автономной защиты избыточные операции по-прежнему отклоняются.
Legacy-профили эталонов сохраняют прежние ограничения; расширение включается явно.

## Устройство эталона

Сеть рассчитывается собственной SI MNA-схемой и физическими обмотками, без импорта
производственных штампов и правых частей. Восемь PSS работают через отдельно
скомпилированные MSL-блоки. Возбуждение использует либо восемь нативных Dynawo
OEL2C с SEXS, либо восемь OpenIPSL ESST1A с восемью MSL PI OEL. Исходные
PSS в базовой SI-машине декомпозируются в эти подключённые блоки, а не исключаются
из обратной связи. UEL реализован независимо через SI circle/lag; он **не**
является нативным MNLEX2 FMU. Полный stock-сетевой решатель Dynawo/OpenIPSL
здесь не используется.

Обязательны состояния и выходы PSS/UEL, нагрев двигателей и генераторов,
токи и потери обеих клеток ротора, напряжения узлов и физические события.
Удаление обязательного канала, отсутствие аудита баланса и отрицательная
невязка проверяются отдельными негативными проверками.

## Воспроизведение

```bash
python -m benchmarks.modelica_reference_setup --root /tmp/pge-native --fetch
python -m benchmarks.dynawo_reference_setup --root /tmp/pge-native --fetch
python -m benchmarks.eight_machine_validation --root /tmp/pge-native --out /tmp/pge-eight-machine
python -m pytest tests/test_eight_machine_reference.py -q
```

Зависимости фиксируются `requirements/pilot-linux-py312.lock` и
`requirements/fmi-subset-linux-py312.lock`; модели и компилятор проверяются
закреплёнными manifest/hash-контрактами. Ручной workflow
`.github/workflows/eight-machine-native.yml` сохраняет отчёты и лицензии.
Наличие workflow не означает состоявшийся удалённый запуск.

Каждый из четырёх сценариев выполняется в двух новых нативных процессах с
точностями 1e-12 и 1e-13, затем в новом производственном процессе и двух
процессах сравнения: всего 8 + 4 + 8. Эталон запускается первым и не получает
производственную траекторию. Сохраняются полные выходные трассы, без прореживания.
Бюджеты: 480 секунд нативной работы, 900 секунд процесса, 2 миллиона сохраняемых
скаляров; превышение завершает проверку ошибкой.

Допуски: KCL/баланс мощности 1e-8 pu, состояния OEL2C 1e-5, ESST1A 2e-5,
нагрев 1e-6, события 1 мкс, дискретные состояния без расхождения. Для новых
каналов мощности допуск 100 W/var; остальные проверки сохраняют более точные
критерии соответствующих компараторов. Сравнение выполняется на заданной сетке
и согласованных физических событиях, а не доказывает равенство всех внутренних
clock-переходов.

## Доказательства и ограничения

Текущий запуск: `reports/na10-qualified-v2-2026-11-05/protocol.json` и
`summary.json`. Положительным результатом считается только `passed: true`
при совпадении отпечатков кода, входов и закреплённых эталонов. Рабочий или
ошибочный отчёт квалификацией не является. Первый запуск
`reports/na10-qualified-2026-11-05` сохранён как отрицательный: статический
валидатор отклонил повторное включение защищённого двигателя. Исправление
валидатора проверяется новым запуском v2 на тех же входных данных.

Эти четыре схемы не квалифицируют произвольные топологии, неограниченный масштаб,
EMT/несимметрию, OEM-регуляторы и реальный промышленный объект. Независимый
подписанный release-host EX-04 остаётся отдельным незакрытым условием.
