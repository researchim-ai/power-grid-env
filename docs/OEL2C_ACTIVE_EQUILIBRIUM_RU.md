# Активное равновесие OEL2C при исчерпанной регулирующей способности

## Реализованный режим

`active_limited_equilibrium` задаёт загруженную рабочую точку GENROU/SEXS,
в которой тепловой таймер OEL2C уже находится в горячей ветви, задание тока
удерживается на `ILimPu`, а PID выдаёт максимально отрицательный сигнал.
Ток при этом **остаётся выше задания**. Это воспроизводимый режим недостаточной
управляющей способности, а не успешное ограничение тока или допуск оборудования.
Он нужен для изучения перегрузки, взаимодействия AVR/OEL и действия защиты.

Режим требует явной политики согласования начального задания AVR:

```json
{
  "generator_id": "g2",
  "rated_field_reaction_pu": 0.8,
  "initialization": "active_limited_equilibrium",
  "avr_reference_initialization": "derive_from_operating_point_with_OEL"
}
```

Нужна явно заданная загруженная `operating_point`. Значение нормализации
в примерах авторское; оно не измерено и не является паспортным током в амперах.
Без указанной политики активный режим отклоняется. Для прежних
`dynawo_startup` и `inactive_equilibrium` разрешена политика `unmodified`.
Омиссией нового поля сохраняется прежнее поведение.

## Восемь состояний и условия ветви

Пусть `m=KScale*abs(XadIfd)/rated_field_reaction_pu`, `a=KAct*m`.
Требуются строгие `m>ITfPu`, `a>ILimPu`, отрицательная скорость свободного
движения задания вниз и стационарный тепловой таймер `q>tFcl`:

```
v = clip(K2*((m/ITfPu)^C2-1), VInvMinPu, VInvMaxPu)
q = clip((v+FixedRd)/KFb, tMin, tMax)
r = ILimPu
e = r-a < 0
y3 = VOel3MinPu
y2 = clip(y3, VOel2MinPu, 0)
y1 = clip(y2, VOel1MinPu, 0)
x = [m, q, r, r,
     y3+(0.9-KpOel)*e, KdOel/tDOel*e,
     (1-tB2Oel/tC2Oel)*y2, (1-tB1Oel/tC1Oel)*y1]
```

Здесь `0.9` — коэффициент anti-windup закреплённой MSL 3.2.3.
Неограниченный PID равен `y3+0.9*e < y3`; интегратор имеет нулевую
производную благодаря обратной связи anti-windup. Памяти lead-lag
вычисляются из **ограниченных** выходов исходных звеньев Dynawo.
Их нельзя обнулять или заменять памятью неограниченного линейного фильтра.
Самая узкая по воздействию ступень может находиться в PID, втором lead-lag
или на конечном выходе; в корпусе есть отдельные такие случаи.

Задание удерживается на нижнем пределе, таймер — в своём стационарном
значении либо на верхнем пределе. Все восемь проекционных производных
проверяются с пределом `1e-8 / s`. Неправильная тепловая ветвь, нулевая
скорость движения задания, неподходящий ток или превышение остатка дают отказ.

Таймер активации уже выдержан: его начальная эпоха явно равна
`-(tEn+1 s)`. Возвратный таймер неактивен. Это объявленная начальная память,
а не восстановленная история сети или запись оборудования до начала расчёта.

## Явное согласование с AVR

Сначала существующий решатель загруженной точки получает сеть, скорости,
потоки GENROU и необходимые поле/механическую мощность. Его базовое задание
SEXS равно `Vbaseline=|Vterminal|+Efd/K`. При активном OEL оно согласуется как

```
Vref_initial = Vbaseline - OEL_output_initial
AVR_error = Vref - |Vterminal| + UEL + OEL2C
```

Согласование выполняется **один раз**, только для генераторов с явной
активной политикой. В дальнейшем задание меняют только предусмотренные команды;
изменение выхода OEL не компенсируется автоматическим движением `Vref`.
Исходные сетевые P/V-цели, нормализация поля и уставки ограничителя не подгоняются.

В `operating_point.oel2c_AVR_reference_initialization` сохраняются базовое
задание, фактический выход OEL, полученное задание, ток управления,
его превышение `ILimPu` и признак исчерпания PID. Проверяется тождество
между этим аудитом и реальными начальными каналами регулятора.
Смешанный случай активного и неактивного ограничителей меняет задание
только запрошенного генератора.

`additional_validation.oel2c_limits` проверяет численные границы выходов и
интеграторов. `within_limits=true` здесь **не означает допустимый ток**.
Это уточняется `limits_scope`, `current_acceptance_evaluated=false`,
превышением тепловой уставки и числом сохранённых отсчётов с отрицательной
ошибкой PID при нижнем пределе. Число отсчётов, включая стороны событий,
не является длительностью перегрузки.

## Тепловая память и область применения

Электромеханическое равновесие и тепловая начальная память задаются отдельно.
Для защиты поля `initialization="equilibrium"` проверяет стационарное тепло;
уже достигнутый порог отключения отклоняется до расчёта. `specified` может
задавать холодную память и положительную производную нагрева в начале.
Эта производная экспортируется отдельно, а не маскируется названием
загруженной рабочей точки. Аналогично экспортируется остаток тепловой защиты
статора. В корпусе проверены нагрев до отключения и стационарная тепловая память.

Проверка локального спектра существующих машин/двигателей не становится
доказательством устойчивости гибридных ограничителей. Публичный малосигнальный
анализ с OEL2C по-прежнему отклоняется. Режим с нулевой ошибкой тока и
внутренним, ненасыщенным PID, общий выбор пограничных равновесий и
AVR takeover/min-selector ещё не реализованы этим профилем.

## Независимая проверка

Сохраняется [закреплённый источник Dynawo cap-guard-v1](OEL2C_VALIDATION_RU.md)
с MSL 3.2.3, OpenModelica 1.27.2 и FMPy 0.3.27. Уравнения библиотек не меняются.
Скомпилированный ограничитель через FMI 2 Model Exchange/CVODE работает
в независимой SI-сети с обмотками GENROU и TGOV1/SEXS.

Эталон самостоятельно решает физическую загруженную точку, алгебраические
начальные состояния ограничителя и согласование AVR. Начальное воздействие
читается из **нативного FMU**, а не из производственного Python-ограничителя.
Тест запрещает вызовы производственных инициализаторов OEL и AVR, затем
успешно запускает нативный контур в том же процессе.

Для выдержанного таймера используется индивидуальное соответствие
`native_time=study_time+tEn+1 s`. Нативный нижний предел задания выбирается
одним ULP наружу через `nextafter(ILimPu,-inf)`; при удержании таймера на
верхнем пределе аналогично используется `nextafter(tMax,+inf)`.
Это явно объявленный численный выбор строгой ветви MSL, без изменения
уставок и без заявления о точном классическом решении на границе.
Все нативные начальные производные проверяются до интегрирования сети.

Сопоставляются также фактическое задание и ошибка SEXS — совпадения поля
при потерянном канале задания недостаточно. Проверяются полнота аудита,
разность двух независимо полученных заданий и все обязательные каналы.

Корпус включает удержание, повышение/понижение задания, реальный выход из
ограничения, обратнозависимую ветвь, два активных ограничителя с разными
часами, смешанные режимы, насыщение, верхний предел таймера, разные ступени
исчерпания воздействия и две начальные памяти защиты поля. Это 12 авторских
случаев при трёх точностях `1e-8`, `1e-10`, `1e-12`.

Выход из ограничения прослеживается на полном интервале **5 s**.
Расширение горизонта независимой SI-сети передаётся явно только нативным
драйвером: прежние standalone-профили сохраняют предел 3 s. Траектория
не обрезается до прежнего предела. Численные допуски остаются теми же, что
у предыдущего OEL2C: состояния/узловые напряжения `1e-5`, мощности `100 W/var`,
физические события/часы `1e-6 s`, дискретные каналы — точное совпадение.

```bash
export PGE_DYNAWO_REFERENCE_ROOT=/tmp/pge-reference-ex01
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
python -m pytest tests/test_oel2c_active_equilibrium.py
python -m benchmarks.generator_oel2c_active_validation \
  --root "$PGE_DYNAWO_REFERENCE_ROOT" --out reports/oel2c-active
power-grid run-study cases/studies/generator_oel2c_active_field_trip.json \
  --out /tmp/oel2c-active-field-trip.json
```

Подготовка закреплённых зависимостей описана в предыдущем документе.
Нативным здесь является ограничитель, а не вся штатная сеть Dynawo.
Своё оборудование для этой проверки не требуется; параметры примеров
не являются заводскими настройками и не доказывают пригодность реального привода.
