# Проверка открытого моделера без собственного оборудования

Цель проекта — воспроизводимый открытый моделeр с проверенными уравнениями,
объявленной точностью, устойчивой реализацией и измеренным диапазоном масштаба.
Наличие у разработчиков электродвигателя, лаборатории или промышленной площадки
не является условием выпуска проекта.

## Что означают прежние термины

«Натурная валидация» — сопоставление с измерениями физической установки.
Измерения могут быть опубликованы университетом, изготовителем или авторами
статьи; собственное оборудование для этого не требуется. Такой опыт подтверждает
те величины и режимы, для которых известны параметры, единицы и условия записи.
Отсутствие скорости не отменяет корректную проверку калиброванного тока, но
не позволяет объявить проверенным время разгона.

«Промышленная квалификация» в прежних документах — внутреннее обозначение
подтверждённой пригодности для конкретного расчётного профиля. Это не название
полученной сертификации. Приёмка расчёта конкретной площадки относится к будущему
пользователю или интегратору. Её нельзя превращать в обязательное условие развития
и выпуска универсального открытого инструмента. Исторические `field_validated:
false` сохраняются как честное описание выполненных опытов, а не как запрет релиза.

## Проверяемая цепочка доказательств

1. Аналитика: схемы замещения, баланс токов/мощности, знаки, единицы,
   предельные случаи, временные постоянные, сохранение непрерывных состояний.
2. Численная проверка: сходимость по шагу и допуску, корректная обработка событий,
   отрицательные случаи, отказ при неподдержанной физике, воспроизводимость.
3. Независимые программы: одинаковые исходные параметры и схема, явные
   преобразования координат и базисов; сравнение каналов на неизменной шкале времени.
4. Опубликованные измерения: дополнительная проверка физической применимости
   по доступным каналам с известной калибровкой и погрешностью. Параметры для
   идентификации и контрольные опыты разделяются до оценки результата.
5. Эксплуатационное качество: тесты API, совместимость форматов, документация,
   контролируемый расход памяти/времени и заявленная область масштаба.

Совпадение программ не доказывает правильность всех физических предположений.
Поэтому аналитика, различные реализации и опубликованные эксперименты дополняют
друг друга. Ошибка программы, разница порядка модели и неопределённость параметров
учитываются отдельно. Слово «эталон» всегда сопровождается указанием происхождения.

## Новый внешний эталон: опубликованный двигатель Aalto 2,2 кВт

Официальный пример motulator:
https://aalto-electric-drives.github.io/motulator/drive_examples/grid_connection/plot_2kw_im_dol.html

В нём заданы параметры обратной Γ-схемы: две пары полюсов, Rs=3,7 Ом,
RR=2,1 Ом, Lσ=0,021 Гн, LM=0,224 Гн; паспортные величины 400 В, 5 А,
50 Гц и 2,2 кВт. Нагрузка вентилятора и J=0,03 кг·м² опубликованы вместе
с примером. Они перенесены в паспорт преобразования, но динамический разгон
этой секцией не квалифицируется.

Проверяется неизменённая библиотека motulator 0.19.0, лицензия MIT. Wheel
зафиксирован SHA256 в `requirements/motulator-reference.lock`. Проверяется не
только строка версии: каждый установленный Python-исходник сопоставляется с
содержимым wheel, чей хеш проверен. Библиотека остаётся необязательным внешним
эталоном, не зависимостью основного решателя; ей нужен Python >=3.12.

**Это новый корпус установившихся режимов опубликованного двигателя, а не
воспроизведение пусковой осциллограммы из примера.** Для проверки сетевого
сопряжения добавлено явно авторское последовательное сопротивление внешней сети
0,05+j0,10 Ом. Сравниваются:

- наша сетевая RMS-модель в координатах внутренней ЭДС;
- аналитическая физическая T-схема замещения;
- установившееся решение исходных дифференциальных уравнений motulator
  в Γ-координатах, без изменения или удаления его уравнений статора.

В последнем случае решается условие `rhs(ψ)=jωψ`: потокосцепления вращаются
с частотой сети. При фиксированной скорости это линейная система для двух
комплексных потокосцеплений, а не результат интегрирования во времени.
Пиковые пространственные векторы переводятся в фазные RMS через √2;
трёхфазная мощность вычисляется на фактических выводах двигателя.

168 точек: 50/60 Гц × 0,8/1,0/1,1 о.е. напряжения × семь скоростей
0/0,2/0,8/0,97/1/1,03/1,2 о.е. × два эквивалентных приведения ротора
× два базиса мощности сети. Проверяются заторможенный ротор, двигательный
режим, синхронизм и генераторный режим. Разделение рассеяния между ветвями
T-схемы — точное эквивалентное преобразование, а не подбор под результат.

До расчётов записывается протокол: абсолютные пределы ошибки фазного напряжения
и тока 1e-7 В/А, момента 1e-7 Н·м, мощности 1e-5 Вт/вар; невязка исходных
уравнений motulator не более 1e-9. Фиксируются исходники, входы и хеш основного
пакета. Проверены все 168 точек: наибольшая ошибка мощности менее 3e-11 Вт/вар,
момента менее 1,3e-13 Н·м. Это численная согласованность эквивалентных моделей,
не оценка погрешности реального двигателя.

### Воспроизведение

```bash
python -m pip download --no-deps --require-hashes \
  -r requirements/motulator-reference.lock --dest /tmp/motulator-wheels
python -m pip install --no-deps --no-index --find-links /tmp/motulator-wheels \
  --require-hashes -r requirements/motulator-reference.lock
OPENBLAS_NUM_THREADS=1 python -m benchmarks.motulator_motor_validation \
  --wheel /tmp/motulator-wheels/motulator-0.19.0-py3-none-any.whl \
  --out reports/motulator-new-run
PGE_MOTULATOR_WHEEL=/tmp/motulator-wheels/motulator-0.19.0-py3-none-any.whl \
  python -m pytest tests/test_motulator_motor_validation.py
```

Требуются обычные зависимости motulator (numpy, scipy, matplotlib, tqdm).
Вместо установки в основную среду можно использовать отдельную venv либо
`pip install --no-deps --target /tmp/motulator-deps <wheel>` и передать
`--dependency-dir /tmp/motulator-deps`; тестам — `PGE_MOTULATOR_REFERENCE_DIR`.
В CI добавлен отдельный job с проверкой хеша wheel и запуском всего корпуса.

## Остальные доступные опоры и дальнейшие этапы

ANDES 2.0.0 уже используется для динамических пусков, регуляторов генератора,
контакторов и тепловых событий в объявленных схемах. Продолжаем матрицу
«пуск → провал → выбег → восстановление → самозапуск» и отрицательные случаи
блокировки. Сначала фиксируются критерии, затем выполняются внешние расчёты.

В Modelica Standard Library найден официальный `IMC_DOL`:
https://git.openmodelica.org/Documentation/Modelica.Electrical.Machines.Examples.InductionMachines.IMC_DOL.html

Он включён в очередь, но ещё не исполнен. Перед сравнением нужно зафиксировать
версию MSL/OpenModelica, параметры, фазные/линейные величины и способ получения
RMS-каналов. Для мгновенных пусковых токов отдельно нужна проверенная модель
переходных процессов статора: сглаживание чужой осциллограммы не заменяет такую
модель. Совпадение установившихся режимов не закрывает этот этап.

Опубликованные экспериментальные архивы LIAS, AGH/Zenodo и Korea остаются
дополнительным треком; их ограничения перечислены в
`PUBLIC_DOL_DATA_ACQUISITION_RU.md`. Не ждём личных данных пользователя,
не подставляем неизвестную калибровку и не повышаем неподтверждённые статусы.

Машиночитаемые критерии: `plans/open-reference-validation.yaml`.
Следующие обязательные задачи продукта: расширение независимой матрицы моделей,
масштабирование разреженных расчётов, переносимость и автоматический CI.
Отсутствие собственного стенда их не блокирует.

Итоговая регрессия секции: 51 тест (22 новых теста внешнего эталона и политики,
а также существующие проверки рабочих точек и якобиана двигателя), без пропусков.
Полная текущая коллекция содержит 986 тестов и целиком в этой секции не запускалась.
Сырые результаты и контрольные суммы: `reports/motulator-steady-final-v2-2026-11-02/`.
Предыдущая динамическая поставка с 15 расчётами ANDES и 232 целевыми тестами
сохраняется отдельно; 168 точек нового корпуса — алгебраические установившиеся
решения, их нельзя складывать с числом динамических интегрирований.
