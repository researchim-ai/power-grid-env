# Нагруженная рабочая точка и механические нагрузки двигателя

`motor_start/scipy` теперь может начинаться с работающей группы двигателей.
Это дополнение к [моторной динамике](INDUCTION_MOTOR_RU.md) и
[тепловой реплике](MOTOR_THERMAL_AND_VALIDATION_RU.md).

## Рабочая точка

В `StudySpec.induction` задаётся необязательный паспорт:

```json
"operating_point": {
  "method": "high_speed_equilibrium",
  "minimum_speed_pu": 0.8,
  "tolerance": 1e-8,
  "thermal_state": "equilibrium"
}
```

Без него сохраняется холодный запуск: нулевые поток ротора и скорость.
С ним ищется совместное электрическое и механическое равновесие **всех
включённых двигателей** при исходном напряжении источника и фоновом импедансе.
Отключённые машины остаются с нулевым потоком и скоростью; их свободные состояния
не используются для проверки устойчивости работающей группы.

При заданном скольжении внутреннее напряжение исключается аналитически:

```text
E = j*(X-X')*I / (1 + j*wb*T*(1-omega))
Zeq = Rs + j*X' + j*(X-X') / (1 + j*wb*T*(1-omega))
```

Далее решается разреженная сеть с этими эквивалентами, а ограниченный
нелинейный поиск сводит `Te - Tload` к нулю для каждой машины. Скорости
ограничены диапазоном `[minimum_speed_pu, 1]`. Используются несколько
детерминированных начальных приближений; бюджет поиска — 2000 вычислений
невязки. Точка на границе, включая свободную машину при ω=1, принимается
только после вычисления её фактической невязки.

Перед интегрированием проверяются:

- невязка исходной, а не только редуцированной, динамической системы;
- конечность всех производных;
- локальная устойчивость подключённых электрических/механических состояний:
  центрально-разностный Якобиан, шаг порядка 1e-6, все действительные части
  собственных значений строго меньше −1e-7 с⁻¹;
- заданная тепловая рабочая точка не находится на/выше порога trip.

Результат `operating_point` содержит число вычислений, скорости, напряжения,
максимальную динамическую невязку, тепловые производные и спектральную
абсциссу подключённых машин. Это локальная проверка машинной динамики,
не доказательство глобальной/переходной устойчивости и не анализ всей
гибридной системы защиты.

При `thermal_state="passport"` сохраняется начальный θ из паспорта защиты:
электрическая и механическая части могут быть стационарны, а нагрев — продолжаться.
Это отражено в `thermal_residual_per_s`. При `"equilibrium"` задаётся
`theta=abs(I_motor_pu)^2`; если уровень достиг порога, расчёт отклоняется
до временного интегрирования с `initial_thermal_limit`.

Неудача поиска возвращается как `initialization_failed`, с конкретной причиной.
`no_qualified_operating_point_found` означает, что поиск не подтвердил
допустимую ветвь в заданном диапазоне. Она **не доказывает отсутствие любой
физической рабочей точки**, невозможность пуска или физический collapse.
Уникальность найденной ветви также не заявляется.

## Механическая нагрузка

Можно сохранить старое поле `fan_torque_pu`, либо вместо него задать:

```json
"mechanical_load": {
  "model": "polynomial_with_smooth_friction",
  "viscous_torque_pu": 0.2,
  "quadratic_torque_pu": 0.4,
  "friction_torque_pu": 0.2,
  "smoothing_speed_pu": 0.01
}
```

Это синтетический пример, не паспорт заводского привода. Требуется **ровно
одно** из `fan_torque_pu` и `mechanical_load`, чтобы не удвоить момент.

```text
Tload(omega) = Cv*omega + Cq*omega*abs(omega) + Cf*tanh(omega/epsilon)
```

Все коэффициенты неотрицательны на собственной моментной базе двигателя.
При `Cf>0` ε задаётся явно; без трения параметр сглаживания отклоняется.
Момент направлен против вращения, `Tload*omega>=0`. Квадратичная часть
эквивалентна прежней вентиляторной нагрузке.

Сглаженная фрикционная составляющая приближается к постоянному по модулю
моменту вдали от нулевой скорости, но **не является точной моделью сухого
трения/заклинивания**: около нуля она непрерывно уменьшается. Гравитационная
нагрузка, постоянная мощность, упругий многомассовый вал и конвейер с точным
моментом страгивания не заявлены.

Событие `load_torque_scale` задаёт неотрицательный абсолютный множитель всей
исходной механической характеристики конкретного двигателя:

```json
{"time_s":0.2,"kind":"load_torque_scale","equipment_id":"m","value":1.25}
```

Два последовательных значения 1.25 и 1.0 означают увеличение на 25% и возврат
к исходной характеристике, без накопительного умножения. Состояния потока,
скорости и нагрева не сбрасываются. Скачок механической нагрузки не создаёт искусственного скачка тока или
электромагнитного момента: меняется ускорение, затем откликается динамика.
Сохраняются `<motor>.load_scale`, `load_torque_pu` и событие с заданным значением.
Контакторная команда и изменение нагрузки одному двигателю могут применяться
одновременно; конфликтующие команды одному и тому же воздействию отклоняются.

## Запуск и доказательства

```bash
python3 -m power_grid_env.cli run-study cases/studies/operating_group_sag.json --out /tmp/loaded.json --isolate --wall-timeout 30
python3 -m benchmarks.motor_operating_point --out reports/motor-operating-point-2026-10-30
python3 -m pytest -q tests/test_motor_operating_point.py
```

Примеры:

- [Стационарный вентиляторный режим](../cases/studies/operating_fan_hold.json).
- [Смешанная нагрузка и провал напряжения](../cases/studies/operating_mixed_sag.json).
- [Скачок механической нагрузки](../cases/studies/operating_load_step.json).
- [Провал на работающей группе](../cases/studies/operating_group_sag.json).
- [Тепловое равновесие](../cases/studies/operating_thermal_hold.json).
- [Выбег/повторное включение работавшей машины](../cases/studies/operating_contactor_restart.json).

[Независимая сверка](../reports/motor-operating-point-2026-10-30/reference.json)
решает исходную физическую Т-образную схему и баланс моментов, затем интегрирует
потокосцепление ротора в SI через DOP853. Эталон не вызывает рабочие штампы
сети, `load_torque`, константы двигателя или его RHS. Сопоставляются обе
компоненты E, скорость, ток, напряжение, P/Q; для нагретого равновесия отдельно θ.
Все шесть сценариев синтетические, без данных целевого оборудования.

Дополнительно проверяются отсутствие ложного разгона, граничный режим без
нагрузки, отключённый член группы, разные системные MVA-базы, превышение
теплового порога, исчерпание бюджета и отказ до интегрирования. Нагруженные
снимки с трансформаторами `Dyn11`, `YNd1`, `Dyn5` сопоставлены с независимым
фазным OpenDSS по модулю и углу напряжений. CLI и отдельный worker входят
в регрессию.

Реализационные бюджеты и ограничения исходного motor study сохраняются.
Начальная сеть должна быть связной, с одним источником за импедансом;
совместная DAE с синхронными генераторами, изменение частоты источника,
LTC/islanding и VFD остаются отдельными задачами. Матрица локальной машинной
устойчивости плотная; произвольный масштаб её анализа не подтверждён.
Промышленная и натурная квалификация не выданы.

Добавлен [параметрический runner](MOTOR_SENSITIVITY_RU.md): каждый вариант заново проходит эту инициализацию; заданные диапазоны требуют обоснования данными целевого оборудования.

Добавлен отдельный [совместный профиль GENCLS + motor](COUPLED_GENERATOR_MOTOR_RU.md) через `coupled_rms/scipy`. Его ограничения отличаются от этого профиля; GENROU/регуляторы в совместную версию пока не входят.
