# NA-09: точная сборка CSC по блокам столбцов

## Что завершено

Встроенные аналитические callbacks `motor_start`/`coupled_rms` получили протокол
текущего сетевого контекста и производных по выбранным столбцам. В режиме
`jacobian_format: csc` Radau получает CSC, собранную непосредственно из блоков
шириной не более 32 столбцов. Полная плотная state×state единичная матрица и
полная плотная матрица результата для размерностей более 32 не создаются.
Для маленькой системы один ограниченный блок может совпадать со всей матрицей.

Плотный режим сохранён как прежний путь и независимый от новой сборки численный
baseline. Для стороннего callback без column protocol остаётся явно обозначенная
`dense_conversion`. Встроенные поддержанные профили используют `column_blocks`;
ошибка блока не запускает скрытый повторный расчёт через dense/FD.
Отчёт содержит `integration.jacobian_assembly`.

Поддержаны моторы single/double cage и тепловые состояния, GENCLS/GENROU и смешанные
машины, TGOV1/SEXS, IEEEST MODE=1, авторский droop OEL, ESST1A, PI takeover,
MNLEX2, OEL2C и действующий opt-in многолимитерный профиль NA-07. Структурные запреты
профилей и legacy multi-OEL FD остаются прежними. Физический RHS, уставки и правила
гибридных событий не менялись.

## Структура и память

Базисный блок имеет размер state×min(32,state). Комплексные чувствительности сети
имеют port×block размер. Электрический контекст фиксируется один раз на полную
сборку; сетевые response caches по-прежнему привязаны к текущему LU. Моторные строки
собираются с полными глобальными токовыми производными, включая генераторные
столбцы. Все ненулевые элементы передаются в CSC без численного thresholding.

Итоговая CSC может иметь квадратичный nnz. Портовый Schur-response также может
быть плотным. Эта работа устраняет плотные промежуточные state×state массивы,
но не отменяет физическую глобальную связность, не вводит DAE и не является
matrix-free решателем. При высокой плотности CSC может требовать много памяти.
Накопители CSC и их объединение включены в измеряемый assembly peak.

Протокол памяти использует отдельные свежие процессы, прогретые одинаковым
16-столбцовым запросом response caches. Это пик **сборки**, а не всей симуляции.
Измеряются NumPy/tracemalloc peak, current-exec VmHWM и assembly wall time.
Tracemalloc не включает все аллокации сторонних библиотек. Уменьшение памяти
сопровождается дополнительным Python/block overhead: ускорение не обещается.

## Сценарии и границы доказательств

12 профилей × два повтора × legacy dense-conversion / streamed CSC дают
24 сравнения и 48 процессов интегрирования. Оба пути используют CSC/SuperLU,
то есть сравнивается именно сборка, а не одновременно два LU-backend.
Сравнение полных каналов, сторон, переходов и часов остаётся прежним:
2e-5 состояния, 100 W/var мощности, 1 µs времени, 1e-8 балансов.
Каждое сравнение выполняется в отдельном процессе; родитель не держит полные
трассы и все StudySpec одновременно. Файлы входов и полные traces сохраняются.

Корпус включает прежние GENCLS/GENROU/ESST1A/UEL/OEL-trip и scale профили NA-08,
а также три новых авторских случая на 512 узлах, 8 генераторах и 32 двигателях.
В новых случаях все моторы double-cage с тепловой репликой; присутствуют PSS,
UEL, статорная/роторная защита и либо восемь OEL2C, либо восемь ESST1A/PI.
Размерности — 424 и 400 состояний. OEL2C имеет явно выбранный inactive-equilibrium
старт; отдельные IThOff-пороги различаются по заранее заданному правилу.
Окна новых сценариев — 0,8 и 6 секунд, не часы и не квалификация любого разгона.
Число оборудования не выходит за прежние ограничения паспортов.

Три connected-transient snapshot дают шесть memory comparisons и 12 свежих
процессов. Все моторы подключены, потоки и скорости заданы явно; это не заявка
на стационарное равновесие. Предел различия матриц — 2e-10. Unit tests дополнительно
сверяют полные RHS-coordinate derivatives для обеих 8-машинных конфигураций,
контролируют отсутствие полной identity/result и отсутствие вызова dense callback.

Три независимых native-профиля (current-regulating OEL2C, четыре OEL2C и ESST1A
field trip) выполняются при 1e-12/1e-13: шесть процессов. Используются закреплённые
Dynawo-derived и OpenIPSL компоненты в независимой SI-сети. Нативный адаптер имеет
предел четыре машины: **восемь машин нативно не квалифицированы**. Для них приведены
алгоритмическая проверка и полные производные RHS, что не подменяет внешний oracle.
Каждый внутренний native clock, OEM curve, saltation и произвольные масштабы также
не объявляются проверенными.

## Воспроизведение

```bash
OPENBLAS_NUM_THREADS=1 python -m pytest tests/test_sparse_jacobian.py -q
OPENBLAS_NUM_THREADS=1 python -m benchmarks.sparse_jacobian_validation --out reports/na09-algorithm
OPENBLAS_NUM_THREADS=1 python -m benchmarks.sparse_jacobian_native_validation --root /tmp/pge-native --out reports/na09-native
```

Для runtime нужны прежние hash-pinned Modelica/Dynawo/FMPy setup-команды.
Исторический `reports/na09-qualified-2026-11-05/` был остановлен внешним SIGTERM
и остаётся незавершённым, не положительным результатом. Причина сигнала не доказана;
тот же большой legacy-сценарий отдельно завершился успешно. После уменьшения памяти
стенда итоговый корпус выполняется в `reports/na09-qualified-v2-2026-11-05/`;
соответствующий native — `reports/na09-native-v2-2026-11-05/`.
Результаты читаются по bound fingerprint, не по наличию этого документа.

Дальше остаются DAE/block formulations для большого числа электрических портов,
более широкие сетевые/длительные внешние корпуса и hybrid sensitivities.
Локальные проверки не заменяют подписанный release gate EX-04 на другом хосте.
