# TGOV1 и SEXS в совместной модели генераторов и двигателей

В `study=coupled_rms`, `backend=scipy` классический GENCLS теперь поддерживает
необязательные `governor: TGOV1` и `exciter: SEXS` в паспорте машины.
Регуляторы, генераторы и асинхронные двигатели интегрируются совместно;
каждый вызов RHS использует одно общее разреженное сетевое решение.
Можно смешивать машины без регуляторов, только с governor или только с AVR.
Это расширение [совместного профиля](COUPLED_GENERATOR_MOTOR_RU.md),
а не замена GENCLS полноценной электромагнитной моделью ротора.

## Уравнения и базы

Мощности TGOV1 заданы на собственной VA-базе генератора, независимо от
системной и моторной баз. Пусть `dw=omega-1`, `v` — положение клапана,
`z` — состояние турбинного фильтра, `c=clip(v,VMIN,VMAX)`:

```text
u = pref - dw/R
T1*dv/dt = u-v                 (anti-windup у границ)
T3*dz/dt = c-z
Pm = (T2/T3)*c + (1-T2/T3)*z - Dt*dw
```

VMIN/VMAX ограничивают клапан; они не являются пределами всего Pm с
частотной обратной связью. Паспортное демпфирование GENCLS действует отдельно.

Для SEXS `e=vref-|V|`, `q` — состояние фильтра, `f` — поле:

```text
TB*dq/dt = e-q
TE*df/dt = K*(TATB*e + (1-TATB)*q)-f   (anti-windup у границ)
|Eg| = clip(f,EMIN,EMAX)
```

Таким образом реализовано звено `(1+s*TATB*TB)/(1+s*TB)` и выходное K/TE.
В этом профиле поле напрямую задаёт модуль внутренней ЭДС GENCLS; это не
GENROU. TB, TE положительны, EMIN неотрицателен. PSS отклоняется. [GENROU имеет отдельное расширение](GENROU_COUPLED_RMS_RU.md),
где поле действует через роторные состояния.
При отсутствии AVR модуль Eg фиксирован; без governor фиксирован Pm.

## Инициализация, события и ограничители

После совместного PV/shaft equilibrium `pref=Pm0`, `v=z=Pm0`,
`vref=|V0|+Eg0/K`, `q=Eg0/K`, `f=Eg0`. Невязка проверяется по исходным
уравнениям, включая регуляторы. При нагруженном равновесии локальный
Jacobian включает регуляторы; центральная разность остаётся внутри ветви
ограничителя. Это локальная проверка, без доказательства глобальной устойчивости.
Начальные клапан и поле должны лежать строго внутри границ с запасом
`max(1e-8,10*operating_point.tolerance)` (без operating_point tolerance=1e-8).
Граница и выход за неё дают отказ, параметры автоматически не подгоняются.

События адресуются через `equipment_id` генератора:

- `governor_step`: добавляет `value` к pref, pu мощности на базе машины.
- `voltage_reference_step`: добавляет `value` к vref, pu напряжения.
- `generator_mechanical_step`: прямой шаг Pm разрешён только без governor.

Gov/AVR шаги на одной машине в один момент допустимы; конфликтующие команды
одного типа отклоняются. В отчёте сохранены обе стороны события.

На границе ограничителя внешняя производная состояния блокируется,
внутренняя допускает восстановление. Физический выход ограничен через clip.
Неограниченное численное состояние также сохраняется: `valve_state_pu`,
`field_state_pu`. Максимальное превышение проверяется по принятой сетке Radau
и сохранённым отсчётам, включая точки, не попавшие в выходной шаг.
Допуск превышения фиксирован:
`max(20*atol,20*rtol*max(1,abs(lower),abs(upper)))`.
Превышение допуска даёт `additional_validation.ok=false` и `completed=false`.
Малое численное превышение видно в отчёте; clip его не скрывает.
Проверка сетки не доказывает отсутствие экстремума между точками.

## Воспроизведение

```bash
python3 -m power_grid_env.cli run-study cases/studies/regulated_coupled_limits_recovery.json --out /tmp/regulated.json --isolate --wall-timeout 30
python3 -m benchmarks.regulated_coupled_reference --out /tmp/regulated-reference --check-andes
python3 -m pytest -q tests/test_coupled_controls.py tests/test_coupled_rms.py
```

Шесть синтетических случаев: [покой](../cases/studies/regulated_coupled_hold.json),
[нагрузка мотора](../cases/studies/regulated_coupled_motor_load.json),
[провал](../cases/studies/regulated_coupled_voltage_sag.json),
[уставки](../cases/studies/regulated_coupled_setpoint_steps.json),
[ограничение и восстановление](../cases/studies/regulated_coupled_limits_recovery.json),
[тепловое отключение](../cases/studies/regulated_coupled_thermal_trip.json).

[Независимый эталон](../benchmarks/regulated_coupled_reference.py) решает
физическую SI-схему stator/rotor/generator, независимо ищет начальный режим,
реализует lead-lag через `scipy.signal.tf2ss` в других координатах и использует
DOP853 с более строгими допусками. Он не вызывает production stamps,
инициализацию или производные регуляторов. Область эталона — один источник,
линия, генератор и мотор, без фоновых нагрузок/трансформаторов.
Пороги: 100 W/var для мощности, 1e-5 для скоростей/угла, 1e-4 остальных
каналов, 1e-6 s для времени thermal trip; каждый канал имеет явный допуск.

Отдельно отключённый мотор сверяется с ANDES на шагах 4/2/1 ms:
угол, скорость, клапан и поле, с разными системной и машинной VA-базами.
Сравнение ANDES подтверждает только предельный случай без моторного тока.
[Сохранённая поставка](../reports/regulated-coupled-rms-2026-10-31/delivery.json)
включает регрессию, исходные траектории, ошибки, raw-state guard и hashes.

## Что остаётся

Сохраняются пределы совместного профиля: до 8 генераторов, 32 моторов,
2000 шин, один внешний slack, фиксированная топология, без отключения
генераторов/островов. В GENCLS нет роторного насыщения; [GENROU с насыщением](GENROU_COUPLED_RMS_RU.md)
добавлен отдельно. Нет совместного PSS и динамического ограничения тока/Q. Motor-only CSV/sensitivity workflow не принимает этот
профиль. Isolated worker даёт deadline/cancel и ограничение результата,
но не является OS security sandbox.

Синтетические траектории и совпадение уравнений не заменяют OEM-параметры,
измерения предприятия и независимую приёмку. Industrial qualification,
field validation и превосходство над другими симуляторами не подтверждены.
Следующий этап — совместный PSS, внешний динамический корпус и
квалификация на заявленном оборудовании/масштабе.
