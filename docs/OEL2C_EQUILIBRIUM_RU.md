# Стационарная инициализация OEL2C

## Что изменилось

`oel2c_limiters[].initialization="inactive_equilibrium"` разрешает начинать
`coupled_rms` с загруженной рабочей точки генераторов и двигателей.
Предыдущий `dynawo_startup` сохранён отдельно и по-прежнему отклоняется
при запросе полной загруженной точки: его задание тока может двигаться сразу.

Поддержан строгий неактивный режим варианта
`OEL2C_Dynawo_cap_guard_v1_SEXS_summation`. Сначала решаются сеть, мощности,
напряжения, скорости двигателей, обмотки GENROU и TGOV1/SEXS. Затем из
фактической реакции поля строится стационарное состояние ограничителя.
Задание напряжения и паспортная нормализация поля для получения допустимой
точки не подгоняются. Активная перегрузка, граница тепловой ветви, граница
таймера возврата и неединственная ветвь с нулевой скоростью задания
отклоняются явно. Это не полный решатель всех активных равновесий OEL/AVR.

## Условия и состояния

Пусть `m=KScale*abs(XadIfd)/rated_field_reaction_pu`, `a=KAct*m`.
Требуются строгие `m < ITfPu`, `a < IInstPu`, отсутствие границы
`IInstPu-a=IThOffPu` и положительная свободная скорость задания вверх. Стационарное значение
теплового таймера должно быть строго ниже `tFcl*(1-Kzru)`: положительный
нижний предел таймера или необычный предел inverse-time не могут маскировать
активную ветвь фиктивным удержанием задания.
На границах используется лишь защита от машинного округления,
а не инженерный запас, расширяющий область допуска.

```
r = IInstPu
v = clip(K2*((m/ITfPu)^C2-1), VInvMinPu, VInvMaxPu)
q = clip((v+FixedRu)/KFb, tMin, tMax)
bias = IResetPu, если возвратный таймер активен и tEn != 0; иначе 0
e = r - a + bias
x = [m, q, r, r, (0.9-KpOel)*e, KdOel/tDOel*e, 0, 0]
```

`r` удерживается на верхнем пределе. Значение PID до ограничения равно
`0.9*e > 0`, его выход равен нулю. Интегратор учитывает anti-windup,
а не обнуляется. Памяти lead-lag нулевые. Таймер перегрузки имеет
нулевую свободную производную либо удерживается на нижнем пределе.
Все восемь проекционных производных проверяются вместе с производными
исходной загруженной системы. Недопустимый остаток даёт отказ до расчёта.

Если `r > a+IThOffPu`, возвратный таймер считается уже выдержанным:
его начало явно задаётся `-(tOff+1 s)`. При неактивном условии часов нет.
Это объявленная начальная память, а не восстановленная история оборудования.
Выводятся `oel2c_stationary_residual_per_s`, `oel2c_clock_history_s` и
обычные каналы всех состояний/таймеров.

Проверка спектра `connected_machine_spectral_abscissa_per_s` относится
к существующей редукции связанных машин/двигателей/регуляторов. Полная
гибридная устойчивость OEL/UEL и модальный анализ нового ограничителя
этой начальной точкой не доказываются; публичный OEL2C small-signal
по-прежнему возвращает явный отказ.

## Независимый нативный эталон

Сохраняются закреплённые Dynawo, Modelica 3.2.3, OpenModelica 1.27.2,
FMPy 0.3.27 и исходный cap-guard-v1. Уравнения библиотек не изменяются.
Общая независимая SI-сеть самостоятельно получает загруженную точку.
Отдельный модуль эталона решает алгебраические начальные условия и задаёт
их в скомпилированном FMU через FMI 2 Model Exchange. Производственный
Python-инициализатор и RHS ограничителя не вызываются и не передаются.

Для начальной памяти часов вводится явное соответствие
`native_time = study_time + tOff + 1 s`. Нативный таймер стартует при нуле
собственного времени; в физическом `study_time=0` его выдержка уже истекла.
Все дальнейшие вызовы времени и плановые события FMU переводятся через
это соответствие, индивидуальное для каждого блока. Реальная предыстория
сети при этом не симулируется и не заявляется.

В MSL 3.2.3 `LimIntegrator` удерживается строго при `y > outMax` или
`y < outMin`. Ровно на пределе свободная производная ещё ненулевая.
Для численного выбора удерживающей ветви нативное состояние смещается
**на один ULP наружу**, через `nextafter`; сами уставки остаются прежними.
Это относится к верхнему заданию и, когда нужно, нижнему таймеру.
После FMI event iteration проверяются все восемь нативных производных
с пределом `1e-8 / s` и нулевой выход. В отчёте сохраняются остаток,
смещение начала времени и способ выбора удерживающей ветви.
Нельзя трактовать это как доказательство существования точного классического
решения на границе строгого неравенства исходной MSL.

## Корпус и воспроизведение

Авторские случаи: удержание загруженной точки, ступень задания, возврат задания до вмешательства OEL,
обратнозависимая ветвь, два независимых ограничителя с разными часами,
насыщение, удержание нижнего предела таймера и совместная работа с MNLEX2. Дополнительно проверяются отсутствие
возвратного таймера, нулевая выдержка активации, масштабирование входа и
начальный ток ниже тепловой уставки при допустимом неактивном равновесии.
Применяются те же заранее заданные физические допуски, что в
[сетевой проверке OEL2C](OEL2C_VALIDATION_RU.md), при трёх точностях
`1e-8`, `1e-10`, `1e-12`. Нативные расчёты выполняются до основного решателя.
Сравниваются состояния, часы, мощности и комплексные напряжения всех узлов.

```bash
python -m benchmarks.modelica_reference_setup --root /tmp/pge-reference --fetch
python -m benchmarks.dynawo_reference_setup --root /tmp/pge-reference --fetch
export PGE_DYNAWO_REFERENCE_ROOT=/tmp/pge-reference
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
python -m pytest tests/test_oel2c_equilibrium.py
python -m benchmarks.generator_oel2c_loaded_validation \
  --root /tmp/pge-reference --out reports/oel2c-loaded
power-grid run-study cases/studies/generator_oel2c_loaded_voltage_step.json \
  --out /tmp/oel2c-loaded-voltage-step.json
```

Своё оборудование не требуется. Нативный ограничитель в независимой SI-сети
не означает запуск полной штатной сети Dynawo или промышленную квалификацию
всех режимов. Активные равновесия с ненулевым воздействием OEL, takeover/AVR,
PSS/КЗ и длительные мешанные режимы остаются следующими блоками.

пограничных режимов остаются отдельными задачами.
