# Серийные инженерные исследования

Профиль B13 объединяет ограниченную серию расчётов, критерии приёмки,
восстановление и переносимые результаты. Поддерживаются `protected_motor`,
RMS `motor_start`/`coupled_rms`, `flux_network` и сквозные чувствительности
этих исследований. Графическое редактирование схемы и QSTS checkpoint остаются
в существующем рабочем месте; новый механизм их не заменяет.

## Запуск и критерии

```sh
python -m power_grid_env.cli campaign run \
  --plan cases/campaign/industrial-21.json --out /tmp/campaign-run
python -m power_grid_env.cli campaign verify /tmp/campaign-run
```

Каталог результата должен быть новым. План — строгий JSON
`power-grid-env.campaign/v1`, максимум 64 случая, уникальные ASCII ID.
Каждый случай содержит `kind`, полный `study`, `rules` и свои лимиты.
Для чувствительности нужен `protocol` с `isolate: false`: внешний campaign
worker уже изолирован, вложенные процессы расчёта не создаются.

Правило выбирает скаляр по JSON Pointer, задаёт `operator: eq|le|ge` и `value`.
Например, `/engineering/classification == protected_trip` проверяет ожидаемое
защитное отключение; `/engineering/engineering_acceptable == true` требует
инженерно допустимый разгон. Несуществующая величина, объект вместо числа,
незавершённый расчёт и недоступная производная не засчитываются. Boolean не
превращается в число. Равенство чисел допускает JSON integer/float, но точное;
для допуска задайте две границы `ge` и `le`.

`completed` означает, что все численные расчёты завершились; `passed` дополнительно
требует доступности производных и всех явно заданных критериев. Корректно
полученный нежелательный инженерный исход не становится численной ошибкой.
Код выхода — 0 только при `passed`, иначе 2.

## Сетки параметров

```sh
python -m power_grid_env.cli campaign grid \
  --input cases/campaign/relay-grid.json --out /tmp/relay-plan.json
python -m power_grid_env.cli campaign run \
  --plan /tmp/relay-plan.json --out /tmp/relay-results
```

Вход сетки содержит шаблон случая и до четырёх осей: JSON Pointer относительно
`study`, численные значения и единицу. Развёртка детерминирована, декартово
произведение ограничено 64 случаями. Единица оси служит метаданными: значения задаются в единицах целевого поля,
автоматического пересчёта нет. Каждый полученный паспорт проходит полную
проверку до начала расчётов. Это конечная авторская сетка, а не статистическая
доверительная оценка, доказательство робастности во всей непрерывной области
или поиск глобального оптимума.

## Остановка и продолжение

```sh
python -m power_grid_env.cli campaign run --plan /tmp/relay-plan.json \
  --out /tmp/first --cancel-file /tmp/campaign-cancel
# Появление /tmp/campaign-cancel останавливает текущую группу процессов.
python -m power_grid_env.cli campaign run --plan /tmp/relay-plan.json \
  --out /tmp/continued --resume-from /tmp/first
```

`--resume-from` требует целостный завершённый пакет предыдущей серии.
План и отпечаток пакета должны совпадать. Завершённые доступные расчёты,
включая инженерно отрицательные, копируются с проверкой манифеста. Незавершённые
и недоступные повторяются. Это продолжение списка исследований, а не сохранение
внутреннего состояния ODE-интегратора посреди траектории.

Если главный процесс аварийно завершился до общего манифеста:

```sh
python -m power_grid_env.cli campaign run --plan /tmp/relay-plan.json \
  --out /tmp/recovered --recover-from /tmp/interrupted
```

Восстановление рассматривает только запечатанные завершённые попытки с точными
входами и текущим производителем. Незавершённые каталоги игнорируются; чужой
продолжающий работу процесс не присоединяется и не объявляется завершённым.
Подмена файлов и противоречащая физическому результату оценка отклоняются.
Новый результат самодостаточен: удаление старого каталога не ломает его.
Режимы resume/recover взаимоисключающие; результат нельзя размещать внутри
исходного пакета. При `stop_on_failure: true` непрошедший случай останавливает
дальнейшую серию, в том числе при повторном использовании результата.

## Ресурсы и отчёт

Linux-профиль: последовательное исполнение, отдельная группа процессов на
случай, адресное пространство 256–8192 MiB (по умолчанию 4096), wall deadline
до 600 с на случай и до 3600 с на серию. Потоки BLAS ограничены одним.
`maximum_rss_kib` сохраняется отдельно от лимита виртуального адресного пространства.
Действуют файловые лимиты и ограничение общего вывода; превышение не превращается
в успешный архив. При внезапном сбое файловой системы может остаться незапечатанный
каталог, который общий `verify` не принимает.

Итоги: `summary.json`, `comparison.csv`, автономный `report.html` и отдельные
входы/выходы/журналы/критерии/манифесты попыток. Для полного двигателя дополнительно
создаётся подробный HTML. Текст экранируется, потенциальные CSV-формулы передаются
как текст. Внешние скрипты и сетевые ресурсы для просмотра не нужны.

```sh
python -m power_grid_env.cli campaign export /tmp/continued --out /tmp/campaign.zip
python -m power_grid_env.cli campaign import /tmp/campaign.zip --out /tmp/imported
```

ZIP детерминирован, содержит только данные, проверяет размеры, имена, дубликаты,
символические ссылки, контрольные суммы и смысловую согласованность оценок.
SHA-256 подтверждает целостность, но не аутентичность автора. Python/pickle/код
из архива не исполняются. Для нового расчёта нужны зависимости выбранного решателя.

## Приёмочный корпус

`benchmarks.campaign_acceptance`: 21 случай, 12 полных защитных моторных режимов
(включая четыре вариации уставок), пять чувствительностей, четыре островных
исследования Radau/DAE. Моторы сверяются с оригинальным закреплённым motulator
0.19.0 и независимой фазной RC/MOV-сетью; острова — с независимыми SI MNA/DOP853.
Производные имеют заранее объявленные аналитические/точные границы.
Проверяются продолжение, точное сохранение результатов, повторяемый ZIP,
импорт и повторное продолжение. Отрицательные случаи и восстановление после
обрыва покрываются `tests/test_campaign.py`.

```sh
OPENBLAS_NUM_THREADS=1 PYTHONPATH=.:/tmp/pge-network-native \
MPLCONFIGDIR=/tmp/pge-mpl python -m benchmarks.campaign_acceptance \
  --wheel /tmp/pge-network-native-wheels/motulator-0.19.0-py3-none-any.whl \
  --out /tmp/new-campaign-acceptance
```

Временные пути обозначают подготовленное окружение, а не встроенные зависимости.
Протокол и итог: `reports/campaign-final-2026-11-06/summary.json`.
Результат учитывается только при `passed: true` и совпадении производителя.
GitHub, CI и собственное оборудование для этого профиля не используются.

## B14: ограниченный параллельный запуск

```sh
python -m power_grid_env.cli campaign run \
  --plan cases/campaign/industrial-21-parallel.json --out /tmp/parallel-study
```

`maximum_workers` задаёт от 1 до 8 локальных процессов, по умолчанию 1.
`memory_budget_mb` — общий бюджет резервов адресного пространства (по умолчанию
8192 MiB). Сумма `memory_limit_mb` одновременно активных случаев не превышает
этот бюджет. Например, при лимите 4096 MiB на случай и общем бюджете 8192 MiB
запускаются максимум два процесса, даже если `maximum_workers` равен восьми.
Недопустимый единичный резерв отклоняется до создания результата.

Диспетчер использует FIFO, не обходит тяжёлый случай ради более лёгкого. Каждый
решатель работает в отдельном процессе, потоки BLAS ограничены одним. Резерв
адресного пространства не равен измеренному RSS и не включает память главного
процесса или других программ на компьютере. Ограничение AS применяется в worker
до физической предварительной проверки входа. Время worker включает его загрузку
и расчёт; общий бюджет исполнения начинается после проверки плана и источника
продолжения. Экспорт, начальная проверка и финальная публикация артефактов не
являются частью этого жёсткого wall deadline.

При `stop_on_failure` новые задачи перестают запускаться; уже запущенные
заканчиваются и сохраняют результаты. Отмена пользователем, общий таймаут и
превышение общего вывода останавливают все активные группы процессов. Завершение
процесса между проверкой состояния и отправкой сигнала корректно обрабатывается,
процессы собираются родителем. Ошибка запуска остаётся отдельным исходом;
непредвиденная ошибка supervisor не оставляет его активные worker без очистки.

`scheduler.json` содержит последовательность запусков, завершений и повторного
использования, а `summary.json.scheduler` — пики числа активных задач и резервов.
Проверка пакета заново вычисляет эти пики и сверяет порядок допуска, память,
число worker и полноту завершений. Строки результата остаются в порядке плана;
фактические времена и порядок завершений отражают выполнение.

Для новых, продолженных и восстановленных попыток действует единая смысловая
проверка входа, производителя, статуса, параметров и критериев. Подмена только
`passed`, даже после пересчёта контрольных сумм, отклоняется. Во время продолжения
также контролируется неизменность исходного пакета. Неожиданные попытки и неверные
типы JSON не засчитываются как успешный результат.

Манифест записывается во временный соседний файл, синхронизируется и публикуется
атомарной операцией без перезаписи существующего манифеста. Конкурирующие
публикаторы не перезаписывают результат; отказ до публикации не создаёт видимость
завершённого пакета. Это гарантия публикации при сбое процесса на локальной Linux
FS с hard links; она не заменяет резервное копирование или гарантию сохранности
всех данных при потере питания.

Приёмка B14: 21 сценарий с двумя процессами и 16 независимых физических сверок;
дополнительно шесть смешанных случаев последовательно и с тремя процессами
с точным совпадением физических каналов, событий, инженерных оценок и производных.
Восемь одновременно допущенных лёгких случаев проверяются отдельно тестом.
Эти точки не квалифицируют восемь максимальных сетей одновременно и не доказывают
ускорение относительно других решателей. Кластерное исполнение в B14 не входит.

```sh
OPENBLAS_NUM_THREADS=1 PYTHONPATH=.:/tmp/pge-network-native \
MPLCONFIGDIR=/tmp/pge-mpl python -m benchmarks.parallel_campaign_acceptance \
  --wheel /tmp/pge-network-native-wheels/motulator-0.19.0-py3-none-any.whl \
  --out /tmp/new-parallel-acceptance
```

Итоговый протокол: `reports/parallel-campaign-qualified-2026-11-06/summary.json`.
