# R01.1: единый локальный протокол внешних сравнений

Реализованы регистрация физической постановки, запуск закреплённых providers
в отдельных процессах, проверка полного набора каналов и переносимый data-only
результат. Это первый конечный профиль сравнений, не рейтинг всех моделлеров.

## Зарегистрированный корпус

`cases/comparison/registered-baseline.json` задаёт 10 позиций:

- Два balanced AC power flow против **pandapower 3.5.6**: радиальная схема
  с tap/phase branch и кольцевая схема с PV-узлом. Сверяются модули и углы
  напряжения всех трёх узлов, включая нетривиальные ID 10/20/30. Branch flows,
  Q-limit transitions и полный IEC short-circuit этим subset не проверяются.
- Четыре RMS cold-start запуска против **ANDES 2.0.0 Motor3**: nominal Radau,
  тот же nominal DAE, другая frequency/base постановка, более слабый фидер.
  Две nominal реализации — варианты одного физического случая, а не две
  независимые топологии. Сверяются скорость, комплексные E, ток, напряжение,
  момент и P/Q. Horizon и физические оси фиксируются до запуска.
- Две full-winding RL-сети против **motulator 0.19.0** и независимо собранной
  SI-сети: радиальная и кольцевая схемы с двумя насыщенными single-cage
  двигателями. Сверяется полный зарегистрированный инвентарь узловых V,
  токов, потоков, скорости, момента и медных потерь. Здесь окно 60 ms:
  это начальный переходный процесс, не весь разгон до рабочего режима.
- Qwen motor VLM workflow — `not_performed`, пока multimodal profile не готов.
- Общий произвольный EMT — `not_applicable` к этому конечному subset.

Итого: 8 обязательных пар, 1 невыполненная и 1 неприменимая позиция.
Даже при 8/8 `required_comparisons_passed=true` поле
`full_declared_inventory_executed=false`. Численное сравнение с другими
неперечисленными продуктами этим протоколом не заявляется.

## Что фиксируется до решения

В каждой позиции: исходные параметры, provider, track, версия reference,
тип независимости, физические преобразования, единицы каналов, абсолютные
допуски, полные ожидаемые оси primary/reference и область отсчётов.
Регистрация включает конечный горизонт: два одинаково обрезанных результата
не получают pass. Выбранный runner принимает только точный зарегистрированный
документ; исключить неудачный обязательный случай или увеличить его допуск
через `--input` нельзя. Другая постановка требует отдельного профиля.

Все source .py benchmarks хешируются до запуска и перепроверяются после
каждого worker; Python-пакет имеет отдельный fingerprint. Версии сторонних
решателей и исходники участвующих модулей записываются вместе с трассами.
У motulator дополнительно сверяется исходный installed source с закреплённым
wheel. Нужны локальные зависимости; автоматических скачиваний нет.

Provider failure, отсутствие зависимости, ошибка версии и timeout дают
`execution_failed` обязательного случая. Они не превращаются в `not_applicable`.
Для declared exclusion заранее требуется непустая причина; незаявленные
запуски в исключённой позиции отвергаются.

## Физические преобразования

AC-case нашего polar Newton использует MW/Mvar, MVA base и **pu-admittance**
bus shunts. В MATPOWER/pandapower GS/BS — MW/Mvar при 1 pu, поэтому они
умножаются на baseMVA. Углы приведены к рад/одному slack; Q-limit policy
выключена с обеих сторон. Tap/phase ветвь имеет нулевой shunt; charging
сохраняется у обычных линий. Capacitive excitation трансформатора через
неэквивалентный converter не объявляется представленной физикой.

ANDES: явно задаются slip=1, E=0 и native G=0 при фиксированном X.
Rotor d/q, Id/Iq, motor/system MVA bases и фактический native polynomial
нагрузки преобразуются явно. Используется исходный native implicit trapezoid
с шагом 0.125 ms. Интерполяция разрешена только для event-free траекторий,
при полном совпадении концов горизонта и ожидаемого native sampling.
Этот профиль использует один выбранный native шаг; не является новым
трёхшаговым convergence-исследованием каждой reference-постановки.

Full windings: primary использует токовые состояния, original motulator —
потокосцепления; независимая сеть не использует production stamps/RHS.
Каналы αβ имеют мгновенные SI V/A/Vs, не скользящее RMS. Сравниваются правые
значения на общей сетке. Предсобытийные пределы и непрерывные пики не входят
в этот выбор каналов. Механика/вариация насыщения — явно авторские входы,
а не дополнительный измеренный паспорт.

## Результат и проверка

На каждом канале вычисляются max absolute error и RMSE. Требуется точное
покрытие заявленных имён и всех отсчётов, конечные числа и завершение обоих
решателей. Совпадение одинакового backend допускается только как
`shared_upstream`, не увеличивая `independent_passes`.

Сохраняются полный input, benchmark-source inventory, environment, raw и
normalized primary/reference, worker logs, outcome, summary и SHA256 manifest.
`verify-comparison` перепроверяет целостность и пересчитывает метрики/coverage
из normalized provider outputs. Это не повторное выполнение чужого solver и
не аутентификация автора. Raw provider outputs и исходники нужны для аудита
самого преобразования данных; generic verifier не исполняет произвольный код
из артефакта. Повтор реальных программ выполняется исходным registered runner.

Ложные summary-флаги, несовпадающие метрики, скрытые неуспехи, неполные оси,
пропущенные/добавленные каналы, неизвестные версии и NaN отвергаются.
Манифест устанавливает целостность артефакта, не авторство.

## Запуск

Генерация выполняется из репозитория с уже подготовленными local references:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MPLCONFIGDIR=/tmp/pge-comparison-mpl \
PYTHONPATH=. python -m benchmarks.comparison_suite \
  --input cases/comparison/registered-baseline.json \
  --reference-dir /absolute/path/to/installed-reference-packages \
  --wheel /absolute/path/to/motulator-0.19.0-py3-none-any.whl \
  --out reports/my-comparison
power-grid verify-comparison reports/my-comparison
```

Reference-dir необязателен, если ANDES/motulator уже установлены в interpreter.
Это явный import overlay доверенного host, не OS sandbox. Версии:
pandapower 3.5.6, ANDES 2.0.0, motulator 0.19.0; закреплённые требования
лежат в `requirements/ex02-pandapower-linux-py312.lock`,
`requirements/ex02-andes-linux-py312.lock`, `requirements/motulator-reference.lock`.
Проверка готового ZIP/каталога требует только основного установленного пакета,
не сторонних решателей и не модуля benchmarks из репозитория.

Каждый worker имеет deadline и лимиты stdout/result; предусмотрен общий
deadline. Существующий каталог не перезаписывается. Ошибка worker остаётся
в sealed отчёте, если parent смог завершить протокол; прерванный/незапечатанный
запуск не считается квалифицированным.

## Почему нет скоростного рейтинга

Измеренные wall times имеют `validation_only_uncontrolled`. Native ANDES
использует более мелкий fixed step; сторонний reference может включать
конвертацию, а primary — только solve. Разные методы/допуски/initialization
делают отношение этих времён непригодным для заявления об ускорении.
Поэтому `timing_comparable`, `speedup_claimed`, `performance_ranking_available`
и `competitive_superiority_proven` всегда false.
Контролируемый performance benchmark — отдельный R03.

## Найденное улучшение моделера

Регистрация целочисленных P/Q/начальных V выявила ошибку `balanced_ac`:
NumPy создавал integer arrays; pu-нормализация могла падать, а запись
дробной slack-мощности — обрезаться. Теперь V/Pg/Qg/Pset/Qset создаются как
float независимо от формы JSON-чисел. Есть отдельная регрессия integer/float
эквивалентности и внешние pandapower-проверки tap/shunt/PV преобразований.

R01.1 не закрывает промышленный охват, все reference-пакеты, runtime ranking
или Qwen. Следующий физический блок — R02, единый motor/network workflow.

## R01.2 / R03.1: общие IEEE-схемы и первый измеренный срез

9 ноября 2026 добавлен `benchmarks.ieee_ac_comparison`: фиксированный набор
IEEE 14/30/118/300 из установленного pandapower 3.5.6. Это распространённые
внешние схемы, а не только наши authored fixtures. По официальной
[документации test cases](https://pandapower.readthedocs.io/en/stable/networks/power_system_test_cases.html)
они происходят из PYPOWER/MATPOWER; в benchmark сохраняется именно packaged
pandapower-вариант и его экспортированная pi-модель, не заявляется побайтовая
тождественность оригинальным MATPOWER-файлам.

Все четыре входа замораживаются до запуска решателей. Сохраняются исходная
pandapower JSON-сеть, каноническая схема нашего решателя, хеши всех Python
исходников обоих путей и явное отображение единиц. GS/BS делятся на baseMVA
при переходе из MATPOWER к нашим pu admittances. Углы обоих результатов
приводятся к своему slack: в case118 исходный общий сдвиг 30° не является
ошибкой решения. Генерация сравнивается по физическому балансу узлов,
распределение Q между несколькими генераторами одного узла не считается
единственным эталонным dispatch.

Профиль: balanced AC, один slack, PQ/PV, fixed topology, pi transformers,
без enforcement Q limits, без ZIP-зависимости и distributed slack, без OPF.
Проверяются полные напряжения и углы всех узлов, все четыре P/Q terminal
flow каждого branch и **отдельный** checker баланса, суммирующий токи ветвей
по исходным R/X/B/tap/phase. Checker не вызывает наши Ybus/Norton функции
или функции сборки pandapower. Точности: V 1e−8 pu, угол 1e−8 rad,
branch power 1e−5 MVA и независимая невязка 1e−6 MVA.

В Newton подаётся одинаковый pu-допуск `1e−8/baseMVA`. У закреплённого
pandapower 3.5.6 параметр с именем `tolerance_mva` в `newtonpf` фактически
сравнивается с pu-вектором F; зафиксированные исходники позволяют это
проверить. Поэтому равенство численных значений разноимённых параметров
не принимается за равенство физической точности. Итоговая невязка всё равно
проверяется независимым checker в MVA.

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MPLCONFIGDIR=/tmp/pge-ieee-mpl python -m benchmarks.ieee_ac_comparison --out reports/ieee-ac-comparison
python -m benchmarks.ieee_ac_comparison --verify reports/ieee-ac-comparison
```

Метрики времени имеют отдельный контракт:

- отдельный процесс для каждой пары backend/case, sequential execution;
- одна CPU affinity, BLAS/OMP/MKL/Numba threads=1;
- два прогрева, затем пять измерений, все физические результаты повторов
  должны иметь одинаковый hash; полный набор сырых времён сохраняется;
- fresh model copy и flat start для каждого вызова; импорт, декодирование
  JSON и копирование подготовленной модели вне таймера;
- таймер охватывает публичный solve API, включая его внутреннюю подготовку
  и диагностику; это не чистое NR kernel время и не agent rollout;
- pandapower использует numba=True и lightsim2grid=False; прогрев JIT исключён;
- CPU time и wall time раздельны; VmHWM измеряется через `/proc/self/status`
  после exec. `ru_maxrss` сохранён отдельно, поскольку может наследовать
  пик памяти launcher. Это footprint процесса с импортами, не инкремент
  памяти исключительно матрицы/решателя;
- частота CPU, turbo, governor и внешняя нагрузка host не контролируются.
  Пять повторов дают локальное наблюдение, не статистический мировой рейтинг.

Финальный последовательный прогон находится в
`reports/ieee-ac-final-qualified-2026-11-09`. Медианы public API wall time:

- IEEE 14: наш 0.703 ms, pandapower 7.182 ms.
- IEEE 30: наш 1.157 ms, pandapower 8.059 ms.
- IEEE 118: наш 5.734 ms, pandapower 8.178 ms.
- IEEE 300: наш 26.498 ms, pandapower 10.224 ms.

Все четыре точностных сравнения прошли. Наибольшее расхождение V около
6.11e−15 pu, terminal P/Q около 1.58e−10 MVA. Это согласование двух
численных реализаций на одинаковых схемах, не ошибка реальной сети.
В локальном public-API срезе быстрее на трёх схемах, медленнее на 300 узлах;
в отчёте не скрываются проигранные точки. Следующее инженерное исследование —
профилирование сборки Jacobian/решения системы и sparse AC путь. Переход
на sparse сам по себе не гарантирует выигрыш до измерения на том же корпусе.
Текущий dense AC профиль ограничен 512 узлами; это не лимит остальных
RMS/DAE/phase моделей проекта.

89 тестов comparison/AC/benchmark прошли без skips/failures. Включены
неверные единицы шунтов, испорченный dispatch, неполные/нечисловые выходы,
подмена медианы, удаление повторов, подмена timing scope и заявления
superiority после reseal. Полный release suite не запускался.
`--verify` пересчитывает ошибки, независимый баланс, медианы и conclusions,
не запускает решатели и не удостоверяет авторство временных измерений.

## С кем и где сравнивать весь проект

Цель — закрывать общую матрицу исследований и показывать преимущество
по каждому заявленному профилю. Один суммарный балл скрывал бы несовместимые
модели, непройденные случаи и разную точность. Для каждого профиля сначала
проходят physics/coverage gates, затем сравниваются ресурсы и workflow.

1. **Статика и размер:** IEEE/MATPOWER packaged cases, pandapower,
   LightSim2Grid и Power Grid Model. Сейчас выполнены только четыре случая
   против pandapower. C++/GPU/batch конкуренты в этом этапе не исполнялись;
   LightSim2Grid и PGM локально отсутствуют. Нужны следующие размеры,
   controlled load variations, Q-limit transitions, islands и failure cases,
   затем cold preparation, warm solve и batch отдельно.
   [PGM](https://power-grid-model.readthedocs.io/en/stable/index.html)
   поддерживает symmetric/asymmetric PF, state estimation и short circuit;
   простого совпадения обычного AC PF недостаточно для покрытия его задач.
2. **Несимметричная распределительная сеть:** публичные IEEE feeders,
   OpenDSS и PGM; напряжения/токи по фазам, нейтрали, потери, ZIP и длительные
   QSTS. [OpenDSS](https://opendss.epri.com/AboutOpenDSSCapabilities.html)
   также имеет fault/harmonic/dynamics режимы. Там, где наш adapter использует
   сам OpenDSS, это shared backend: сверка интерфейса и воспроизводимости,
   а не независимое преимущество вычислительного ядра.
3. **Электромеханическая динамика:** ANDES, его опубликованные IEEE 14/NPCC/WECC
   verification cases, затем совпадающие паспортные модели и возмущения.
   [ANDES verification](https://docs.andes.app/en/latest/verification/index.html)
   описывает сравнения с PSS/E, TSAT и published data. Наш Motor3 subset,
   GENROU профили и конкретные исторические корпуса маркируются по собственным
   receipts; не переносят автоматически qualification на все эти сети.
4. **Двигатели, приводы и преобразователи:** motulator, опубликованные
   DOL/control examples и наши industrial group/restart случаи. Текущие
   воспроизводимые pins используют 0.19.0; актуальная публичная
   [документация](https://aalto-electric-drives.github.io/motulator/) показывает
   0.23.1 и более широкий набор drive/converter workflows. Для актуального
   конкурентного сравнения нужна отдельная совместимость с новым pin,
   с сохранением прежнего эталона. Новые семейства нельзя подменять
   изменением коэффициентов одного опубликованного двигателя.
5. **Phase/EMT:** аналитические RLC и опубликованные matched machine/converter
   cases, независимые RHS, затем доступные воспроизводимые EMT reference runs.
   Сначала одинаковые схемы и frequency/time-scale assumptions: averaged
   converter, PWM, насыщение и zero sequence — разные профили. Промышленные
   EMT инструменты в текущем этапе не исполнялись. Малый energy residual
   не доказывает точность неидентифицированного оборудования.
6. **Среда для AI:** [Grid2Op](https://grid2op.readthedocs.io/en/latest/),
   LightSim2Grid backend и применимые PowerAgentBench задачи; отдельно моторная
   динамика и SFT/GRPO. Сравниваются одинаковые наблюдения, допустимые действия,
   бюджеты what-if/tool calls, horizon и физический evaluator. Время включает
   reset, observations/images, serialization, agent inference и verification,
   с разложением по частям. Нужны topology/machine/disturbance holdouts,
   matched/blank/wrong-image/text-only controls, policy seeds и базовые
   heuristic/search policies. Qwen3.5-4B VLM обучение/оценка не выполнены;
   CPU training smoke не является результатом полезной инженерной модели.

Два полезных внешних ориентира на 9 ноября 2026:

- Препринт [Benchmarking CPU, GPU, and ML Power-Flow Solvers from 14 to 70,000
  Buses](https://arxiv.org/abs/2610.27930), подан 20 октября 2026: авторы
  сравнивают несколько физических и ML решателей под общим независимым
  KCL checker. Их выводы о сравнительной скорости не воспроизведены здесь;
  наш четырёхсхемный pilot не является повтором статьи.
- [LightSim2Grid benchmarks](https://lightsim2grid.readthedocs.io/en/latest/benchmarks.html)
  явно исключают agent и reset из solver timing. Их опубликованные ускорения
  нельзя переносить на полный SFT/GRPO generation/training workflow или
  на наш simulator без такого же matched run.

Порядок следующей работы: профиль sparse AC и расширение размерного ряда;
затем независимый asymmetric corpus; параллельно RMS/drive corpus и полный
agent workflow. Для каждого направления сохраняются входы, source/version
pins, сырые результаты, точность, ошибки, время/память и воспроизводимый
локальный запуск. Публикацию выполняет пользователь; GitHub и CI не требуются.
Победа формулируется точно: конкретный workflow, против конкретной версии,
при одинаковом accuracy gate и условиях. Общее превосходство проекта остаётся
открытым до прохождения всей объявленной матрицы.


## R03.2: разреженный AC путь и измерение вариантов

Реализован `solve_power_flow(..., linear_solver='auto'|'dense'|'sparse')`.
Auto сохраняет dense до 128 узлов включительно и выбирает sparse выше;
порог выбран на текущем пилоте, не является доказанно оптимальным для
всех топологий. Верхний лимит balanced AC остаётся 512, новые большие
размеры не открыты без отдельной квалификации.

Sparse путь собирает Ybus прямо в CSC, аналитические полярные производные
по ненулевым элементам и блочный Jacobian в CSC, решает Newton через SuperLU.
Dense Ybus/Jacobian не создаются и на этапе физического audit: audit заново
собирает разреженную матрицу, не доверяет solved/converged флагу.
Общие оптимизации: проверка membership через sets, заранее сгруппированные
генераторы, однократные комплексные напряжения для branch reports/audit,
линейное агрегирование генерации по узлам. Ограничители, line search,
PV→PQ Q switching, bus identities и смысл within_limits сохранены.

Benchmark теперь имеет v2 контракт с четырьмя backend-вариантами:
`primary` (auto), `primary_dense`, `primary_sparse`, `pandapower`.
Каждый вариант исполняется в своём процессе; все три наших результата
проверяются против эталона. Нормализованный одинаковый physical result
во всех повторах обязателен. Включены размеры хранения Ybus/Jacobian;
это не общий пик памяти процесса и не все временные рабочие массивы.

Финальный последовательный прогон:
`reports/sparse-ac-qualified-2026-11-09`, по пять samples после двух warmups.
Public API медианы, ms:

- IEEE 14: auto 0.633, dense 0.641, sparse 2.076, PP 7.335.
- IEEE 30: auto 1.052, dense 1.046, sparse 2.596, PP 6.824.
- IEEE 118: auto 4.884, dense 4.866, sparse 6.555, PP 8.465.
- IEEE 300: auto 11.306, dense 23.091, sparse 11.958, PP 10.625.

Все физические сравнения прошли прежние допуски. Разница времени auto и
явного sparse на 300 узлах — вариативность отдельных процессов/замеров:
это один численный путь, не два алгоритма. Host load/turbo/governor не
контролировались; статистическое равенство/превосходство на 300 не заявлено.
В этом прогоне PP быстрее. Сравнение dense/sparse относится к текущему коду
с общими оптимизациями postprocessing, не подменяет исходный historical baseline.

На IEEE 300 Jacobian хранит 3,736 значений вместо 280,900, включая CSC
индексы занимает 46,956 вместо 2,247,200 bytes. Ybus: 1,118 вместо 90,000
значений, 23,564 вместо 1,440,000 bytes. Эти числа не означают такое же
снижение полного RSS. Профили cProfile текущих вариантов сохранены в
`reports/sparse-ac-profile-2026-11-09`; profiler times используются для
атрибуции, не как benchmark wall latency.

102 разных теста прошли: основной прогон 100 и дополнительные sparse
проверки с двумя новыми тестами. Проверены конечные разности Jacobian,
независимый точный трёхузловой oracle, все четыре IEEE case, taps/shunts,
перестановка bus order, parallel/offline branches, PV→PQ, islands,
вырождение и отсутствие обращения sparse пути к dense helpers.
Полный release suite не запускался. Следующий этап — дополнительные размеры,
изменения нагрузок и разреженный Q-limit/failure corpus, затем batch/rollout.


## R03.3: крупные sparse PF, нагрузочные точки и открытые отказы

API balanced AC теперь ограничен 2048 узлами для sparse/auto. Явный dense
PF и dense OPF по-прежнему ограничены 512, standalone dense audit также
отклоняет большую сеть до выделения Ybus; `matrix_format='sparse'` доступен
для отдельного audit. AC estimation сохраняет свой прежний предел 128.
Это расширение PF, не автоматическое расширение остальных исследований.
На границе 2048 проверена синтетическая цепь с распределённой нагрузкой,
с независимым суммированием токов концов ветвей; она не выдаётся за реальную
сеть или дополнительное независимое публичное семейство.

`benchmarks.large_ac_acceptance` фиксирует 7 позиций:

- PEGASE 1354: load-table P/Q ×0.9/1.0/1.1, flat start.
- RTE 1888: load-table P/Q ×0.9/1.0/1.1, одинаковый замороженный DC seed.
- RTE 1888: номинал, flat start, заранее выделенный отрицательный regression.

Генераторные расписания и static generation не масштабируются. DC seed
подготовлен pandapower и сохранён для обоих решателей до измерений. Нельзя
считать это независимой проверкой нашего end-to-end initializer, временем
полного получения режима или cold start. Каждый успешный backend/case
выполняет два прогрева и три измерения в отдельном процессе/одной affinity;
неудачные численные точки не получают выдуманных времён успешного solve.

При подготовке крупного корпуса обнаружены две реальные ловушки отображения:
публичный `to_ppc` по умолчанию может выбрать OPF-представление управляемых
static generators; даже `mode='pf'` у pin 3.5.6 принудительно задаёт
`enforce_q_lims=True`. Это не соответствует нашему declared Q-disabled PF.
На RTE проявилось расхождение 2 Mvar в узле с fixed sgen при сравнении
неодинаковых моделей. Допуски не ослаблялись. Adapter теперь явно выбирает
PF и повторяет закреплённый `_pd2ppc` после установки Q-limits-disabled
policy. Private API допустим только с этим pin и source hashes; перенос
на другую версию требует отдельной проверки. Исходные bus-table voltage
bounds сохраняются для diagnostics (у PF export часть bounds не заполняется),
но не являются enforced PF constraints. Regression проверяет конкретную
Q-инъекцию и независимый баланс полной RTE-схемы.

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MPLCONFIGDIR=/tmp/pge-large-mpl python -m benchmarks.large_ac_acceptance --out reports/large-ac
python -m benchmarks.large_ac_acceptance --verify reports/large-ac
```

Итог `reports/large-ac-final-assessment-2026-11-09`:

- Все 3 PEGASE-точки сходятся и проходят V/angle/branch-PQ/balance сверку.
- Номинальная RTE с DC seed сходится и проходит ту же сверку.
- RTE ±10% с DC seed не сходится у обоих решателей. Это две **открытые**
  положительные позиции, не заменённые на N/A или ожидаемые успехи.
- Flat RTE не сходится у обоих; отрицательный regression подтверждён.
- Общий `passed=false`, `all_solved=false`; совпали четыре converged режима.
  Неудачный Newton не доказывает физическую невозможность или collapse.

Public API median wall time, ms (наш sparse / pandapower 3.5.6):
PEGASE 90% 45.67 / 20.25; 100% 45.20 / 20.04; 110% 45.07 / 26.90;
RTE nominal DC seed 63.35 / 30.66. На этих больших точках пока медленнее.
Это локальные наблюдения, не статистический рейтинг: host load/turbo/governor
не контролируются. Исходные labels PEGASE/RTE относятся к packaged variants,
не натурным схемам с подтверждёнными актуальными паспортами.

Сверка артефакта пересчитывает physical comparisons, declared failures,
медианы и список открытых точек. `verified=true` означает корректную проверку
отчёта, не `corpus_passed=true`; проверка не повторяет solver/time execution
и не удостоверяет авторство измерений. Команда расчёта возвращает код 2,
пока две положительные позиции не пройдены. Предел API и перечень реально
квалифицированных режимов разделены явно.

112 разных тестов текущего этапа прошли: основной набор 111 плюс отдельная
2048-bus boundary проверка. Контрольные тесты не допускают dense allocation
на больших PF/OPF/audit, не расширяют estimation, проверяют islands и
не превращают неожиданный отказ в успешный negative regression. Полный
release suite не запускался. Следующая физико-численная задача — bounded
load continuation/начальные приближения и matched RTE stress runs; затем
широкий Q-limit/failure и batch/end-to-end corpus. Условия текущих отказов
и их артефакты сохраняются при последующих улучшениях.


## R03.4: ограниченное продолжение по нагрузке и честный неполный путь

Добавлены `continue_power_flow`, `ac-continuation`, `verify-ac-continuation`
и schema для `ContinuationOptions`. Вход задаёт исходную и целевую схемы:
разрешено менять только bus Pd/Qd. Топология, базы, оборудование,
генераторные расписания, лимиты и PV/slack voltage setpoints должны совпадать.
Перед расчётом входы копируются. Сначала заново решается исходный режим;
его supplied DC guess не принимается за уже доказанное AC равновесие.

Каждый шаг интерполирует нагрузки и выполняет новый sparse Newton. Только
сходящийся и проверенный шаг меняет seed. При отказе — rollback к последнему
принятому режиму и уменьшение шага вдвое; при успехе шаг растёт ограниченно.
Конечные нагрузки берутся точно из target при progress=1.0, без округления
почти достигнутой цели в успех. При исчерпании попыток/шага/времени или
отмене результат остаётся incomplete; final_result отсутствует.

Баланс независимо пересчитывается относительно Newton status из новой
матрицы (по тем же production stamp формулам), но это **не отдельная
независимая реализация физики**. Дополнительно проверяются fixed Pg,
PQ reactive schedules, контролируемые Vm и Q-limit policy. Одного нулевого
баланса недостаточно: изменение Pg могло бы скрыть недостигнутую нагрузку.
PV→PQ при Q limits не должно незаметно менять исходный voltage setpoint
на следующем шаге. Эти случаи покрыты тестами.

Журнал содержит attempted progress, rollback anchor, принятые и отклонённые
шаги, электрические состояния и проверки. Поздний результат после deadline
не принимается. Wall budget кооперативный, проверяется между Newton calls
и после них; не прерывает уже выполняющийся вызов библиотеки. Ограничены
попытки, Newton iterations и размер артефакта. Это natural-parameter load
homotopy, не pseudo-arclength CPF, не поиск всех ветвей и не доказательство
предела устойчивости или физического отсутствия решения.

```sh
power-grid ac-continuation --input cases/ac-continuation/rte-plus-five-percent.json --out reports/rte-continuation
power-grid verify-ac-continuation reports/rte-continuation
```

Stdout содержит короткое заключение; полные состояния находятся в артефакте.
CLI расчёта и native verifier возвращают код 2 для incomplete, сохраняя
`verified=true` при целостном, корректно проверенном неполном журнале.
Проверка пересчитывает баланс/расписания/rollback anchors, не повторяет
Newton и время, не удостоверяет авторство. SHA защищает целостность.

### Совпадающее испытание с pandapower

`benchmarks.ac_continuation_acceptance` использует тот же controller с двумя

**R03.5 — pseudo-arclength continuation, 2026-11-09.**

Реализованы разреженный tangent predictor, Newton corrector с гиперплоскостью,
адаптация шага, откат неуспешных попыток, бюджеты и уточнение поворота ветви.
Метрика координат: ||dx||²/n + dλ²; углы в радианах, напряжения в pu.
Профиль фиксирует PQ/PV и меняет Pd/Qd; переключение по Q-ограничениям не
поддерживается. Действует прежняя граница AC API 2048 узла.

Двухузловой аналитический эталон с точным λ=2/3 проходит, включая нижнюю
ветвь. На RTE1888 независимые электрические уравнения и производные pandapower
3.5.6 подтвердили ветви и оценки поворота при двух шагах. Контроллер продолжения,
координаты и представление результата общие; независимый MATPOWER runcpf не
запускался. Для направления −10% оценка λ≈0.665858414, для +10% λ≈0.565797690;
согласование при делении шага пополам лучше 1e-9. Это наблюдения локальной ветви,
не сертифицированные пределы нагрузки, доказательство отсутствия других решений,
динамической устойчивости или коллапса. Исходные цели ±10% остаются открыты;
точные цели ±5% достигнуты и независимо сопоставлены.

CLI: `power-grid ac-pseudo-arc --input INPUT --out NEW_DIRECTORY` и
`power-grid verify-ac-pseudo-arc DIRECTORY`. Частичная ветвь сохраняется с
явной причиной остановки (код 2); успех требует точного целевого режима.
Проверяются электрические состояния, касательные, гиперплоскости, журнал
откатов и уточнение поворота; SHA-манифест не является цифровой подписью.
Пример: `cases/ac-pseudo-arc/two-bus-fold.json`.

Приёмка: `reports/pseudo-arc-final-qualified-2026-11-09/summary.json`;
155 целевых тестов прошли, полный release-профиль в этой итерации не запускался.
Следующий крупный шаг — переключение Q-ограничений и событий внутри continuation,
затем независимая проверка этого изменяемого состава уравнений.

Методическая опора: [MATPOWER continuation power flow](https://matpower.app/manual/matpower/ContinuationPowerFlow.html)
и [predictor](https://matpower.app/manual/matpower/Predictor.html).


**R03.6 — продолжение ветвей с реактивными ограничениями, 2026-11-09.**

Добавлен профиль `options.enforce_q_limits=true` в существующий
`ac-pseudo-arc`. Неизвестные теперь включают Vm всех нереференсных узлов;
размер системы не меняется при достижении ограничения. Для каждого PV-узла
используется проектируемое уравнение (Q генерации в pu):
`Q - clip(Q - (Vm - Vset), Qmin, Qmax) = 0`.
Внутри диапазона оно удерживает Vset; на верхнем пределе допускает Vm≤Vset,
на нижнем Vm≥Vset. При восстановлении условий автоматически возвращается
регулирование напряжения. Используются аналитические разреженные блочные
производные выбранного активного режима; на изломе выбирается обобщённая
производная. Q нескольких агрегатов одного PV-узла ограничивается суммарно.
Slack сохраняет напряжение и балансирует Q без ограничения: смена slack,
P-ограничения и удалённое регулирование в этот профиль не входят.

Обнаруженные изменения режимов уточняются бисекцией в координате
предикторной гиперплоскости до интервала 1e-7, максимум 20 уточнений.
Сохраняются оба электрических состояния и журнал уточнений. Ограниченный
бюджет оставляет явный `localized=false`; скрытые повторные переключения
между одинаковыми режимами на концах шага не объявляются исключёнными.
Прямой переход между противоположными пределами отклоняется с уменьшением
шага, чтобы сохранить промежуточный режим регулирования. Одновременные
ограничители обрабатываются общей системой, без последовательного изменения
списка неизвестных. Проверяющий заново вычисляет режимы, уравнения,
касательные, балансы, гиперплоскости и интервалы переходов; поддерживается
точный целевой режим, остановка по бюджетам и отмена.

Публичный корпус: `cases/ac-reactive-arc/` — верхний/нижний предел,
возврат и смена противоположных пределов; заморожены IEEE14/30/118 из
pandapower 3.5.6 с происхождением и SHA. Приёмка масштабирует Pd/Qd до +20%
при фиксированных Pg и Vset, сравнивает каждую принятую точку и точную цель,

**R03.8 — ограниченная распределённая балансировка AC, 2026-11-09.**

Реализован самостоятельный профиль `ac-dispatch` / `verify-ac-dispatch`.
Он отделяет опорный фазовый угол от источника балансировки мощности:
`Pg_i = clip(Pschedule_i + alpha_i * delta, Pmin_i, Pmax_i)`.
Все Pg, включая прежний slack, должны быть заданы явно и лежать в пределах;
положительные веса участников нормируются. После достижения P-предела
оставшиеся участники принимают остаток через общую delta. Неучаствующие
генераторы сохраняют расписание; потери сети входят в общий баланс.
Это статическая политика, без экономической диспетчеризации и без динамики
частоты, времени AGC или первичного регулирования.

P-уравнения включают все узлы. Неизвестные: углы кроме одного, Vm всех узлов
и delta (2n). Разреженный аналитический блочный Якобиан включает производную
P-участия по delta с учётом насыщения. Q/voltage-проекция действует на всех
исходных PV и прежнем slack: при Q-пределе напряжение освобождается, при
восстановлении условий регулирование возвращается. Фиксирование угла не
создаёт виртуального неограниченного источника P/Q. Опорный угол можно явно
перенести на любой существующий узел, включая PQ; физическое решение после
выравнивания фазы сохраняется. Классические метки типов входного case не
переписываются: новая семантика заявлена отдельным профилем и собственным аудитом.
Автоматическая обработка островов и коммутации не выполняется.

Newton использует damping, области Vm, лимит итераций, кооперативный deadline
и отмену. Классический PF служит только начальным приближением, не допустимым
ответом нового профиля. Исчерпание активных производных участия даёт
`participating_p_limits_active`, не успешный режим и не глобальное доказательство
отсутствия решения. Неудачные расчёты не публикуют итоговый operating point.
Для успеха проверяются уравнения распределения и Q-проекции, мощности каждого
агрегата, измерения ветвей и заново собранный баланс. Отдельно выдаются остатки
регулировочного диапазона P и соблюдение всех ограничений обычного audit.
Newton-журнал/время не воспроизводятся, SHA не является подписью происхождения.

**R03.9 — распределённый P/Q-профиль подключён к CPF и envelope, 2026-11-09.**

Интеграционный долг R03.8 закрыт в заявленном статическом профиле.
Существующие `ac-pseudo-arc` и `ac-envelope` принимают `options.dispatch`
с теми же участниками и отдельной фазовой опорой, что `ac-dispatch`.
Требуются `enforce_q_limits=true` и совпадающие `tolerance_pu` dispatcher/CPF;
при значениях по умолчанию достаточно указать участников. Только Pd/Qd могут
меняться между start/target, остальные оборудование, расписания и политика
фиксированы. Без dispatch прежние режимы CPF сохраняются, включая отдельно
объявленное неограниченное Q классического slack.

В общий вектор входят углы, Vm всех узлов, delta в pu и λ. Используется
метрика `||[angles_rad, Vm_pu, delta_pu]||²/(2n) + dλ²`. Построены аналитические
разреженные блоки и столбец производной по λ с учётом действующих Q-проекций.
Обычный статический dispatcher даёт начальное состояние; затем шаги, касательные,
откаты, точная цель и envelope используют одну систему уравнений. Snapshot,
turn refinement и ZIP сохраняют delta, участие, режимы P/Q и фазовую опору.
Аудитор проверяет распределение каждого агрегата и баланс всех узлов, включая
прежний slack: физический смысл нового профиля не подменяется старой проверкой
фиксированных Pg и неограниченного slack.

P-переходы отдельно содержат generator_index, before/after и уточнённый
интервал со снапшотами; Q-переходы сохраняют bus_id. Поддерживаются насыщение,
возврат и остановка `participating_p_limits_active` на проверенной точке,
если все производные активного участия исчерпаны. Это локальная причина
остановки, не глобальное исключение других решений. На вырожденной начальной
ветви без свободного участия возможен явный `initial_tangent_failed`.
Нулевые диапазоны P/Q отмечаются `fixed` и не создают ложных переключений;
для нулевой ширины Q-проекции исправлена постоянная производная, в том числе
в прежнем projected-PV профиле. Проверены конечными разностями оба типа.

Envelope использует те же распределённые состояния при уточнении напряжений,
МВА и pu-токов. `timeline_events` ссылается на P-, Q- и сетевые события;
`timeline_groups` упорядочивает их по обходу ветви и группирует перекрывающиеся
интервалы. `timeline_complete` относится только к обнаруженным событиям
сохранённой ветви, не к отсутствию скрытых пересечений. Точная цель, завершение
мониторинга, соблюдение ограничений и полнота уточнённого timeline — отдельные
признаки. Отмена проверяется также в уточнениях и перед публикацией точной цели;
отмена последнего перехода не превращается в успешный итоговый режим.

Примеры:
`cases/ac-pseudo-arc/distributed-participation.json` — чистый CPF;
`cases/ac-dispatch-arc/analytic-entry.json`, `analytic-release.json` и
`case14.json`, `case30.json`, `case118.json` — общий envelope.
Публичные корпуса используют диапазон нагрузки 0.9→1.1, исходные пределы
оборудования и ранее объявленную авторскую политику весов. Токовые пороги —
демонстрационные 1.05 от независимого распределённого исходного тока;
это не паспортные амперы. Ограничения и принятые точки могут включать последнее
превышение λ=1; точная цель проверяется отдельно.

52 локализованных события (6 P, 16 Q, 30 сетевых). Проверены все принятые точки,
оба конца каждого P/Q/сетевого интервала и точная цель. Эталон использует

## R03.10 — масштабирование распределённого CPF/envelope, 10 ноября 2026

## R03.11 — явная подготовка Pg и производный профиль RTE1888, 10 ноября 2026

Добавлен `power_grid_env.ac_schedule`: минимальная взвешенная евклидова
коррекция только объявленных регулируемыми Pg при неизменных P-пределах.
По умолчанию сохраняется исходная суммарная генерация; можно явно задать новую
сумму. Нерегулируемые генераторы неизменны; их недопустимые Pg дают отказ.
Несовместимая с агрегатными пределами сумма возвращает отказ без подготовленной
схемы. Вход не меняется на месте. Это геометрическая подготовка входных данных,
без стоимостей, потерь, сетевых уравнений и обещания AC-допустимости.

`ac-prepare-schedule --input INPUT --out OUTPUT` записывает исходную схему,
настройки, SHA, исходные/новые Pg, изменения каждого агрегата и подготовленную
схему. `verify-ac-schedule OUTPUT` пересчитывает проекцию и протокол; подмена
предела, Pg, общей суммы или признака электрической допустимости отвергается
даже после нового запечатывания. Кандидат передаётся отдельному AC-исследованию.

Сверка `benchmarks.ac_schedule_acceptance` использует неизменный
`cases/ac-scale/rte1888.json`. Исходный вход по-прежнему отвергается:
Pg агрегатов 10/24/26 ниже их Pmin. Производный вход явно меняет расписания,
сохраняя суммарный Pg и все характеристики оборудования/сети. Независимая
проекция решается SciPy brentq; электрические состояния — отдельным разреженным
Newton на исходных PP3.5.6 stamps/производных. Два шага CPF/envelope, три повтора,
все точки и концы событий сверяются; превышения исходных V/MVA-пределов
сохраняются. Завершение ветви не приравнивается к допустимости всех режимов.

Архивы повторов сжимаются только после проверки полного восстановления и SHA;
лимиты безопасной распаковки остаются прежними. `--reuse DIRECTORY` позволяет
повторно использовать уже запечатанные worker-расчёты того же производителя
с тем же входом. В этом режиме сравнения и аудиты выполняются заново, а
поле execution_policy явно сообщает, что нового замера времени не было.
Время/RSS — непроверенные внешне локальные измерения, не рейтинг производительности.

IEEE300 остаётся открытым. Исследовательская residual-homotopy от режима с

системы. Широкие Q-пределы были только экспериментом и не вошли в продуктовую
квалификацию. Это не доказательство отсутствия решения и не основание менять
паспортные ограничения. Следующая очередь: устойчивость projected-Q решения,
независимые альтернативные формулировки, тяжёлые режимы и сценарии топологии.
Исторические R03.10 receipt относятся к прежнему SHA производителя; полный
старый корпус на новом SHA этим блоком не перепроверен.

## R03.13 — разреженные чувствительности и критические узлы, 10 ноября 2026

Добавлен `ac_sensitivity`: прямые производные для направлений изменения Pd/Qd
и сопряжённые градиенты выбранных выходов по всем нагрузкам. Для исходного
состояния J dx = -B dL; для выхода m решается Jᵀ z = ∂m/∂x. Одна LU
исходного Якобиана переиспользуется для всех направлений и сопряжённых задач;
это не утверждение об одной факторизации всего предшествующего Newton.
Плотный Якобиан и его обратная матрица не строятся.

Выходы: Vm, относительный угол в радианах, Pg отдельного генератора, общий
балансирующий delta в МВт, P/Q/MVA и модуль тока с обеих сторон ветви.
Ток — pu на принятой базе, не амперы. Направления задаются в МВт/Мвар за
единицу параметра; сопряжённые производные — выходных единиц/МВт и /Мвар.
Для каждого выхода возвращаются градиенты всех узлов и отдельные рейтинги
по абсолютному влиянию P и Q. Рейтинг не определяет доступность управления
нагрузкой и не является рекомендацией отключения оборудования.

Можно передать сохранённое состояние, но оно заново проверяется по сетевым,
P/Q-уравнениям, распределению генерации и предоставленным потокам. Без состояния
выполняется обычный dispatch. Его отказ не превращается в нулевые производные.
Расчёт допускается вне эксплуатационных V/MVA-пределов, если сетевые уравнения
выполнены; audit отдельно сообщает нарушения. Это математическая локальная
чувствительность выбранного режима, не подтверждение допустимой эксплуатации.

Обычные производные отвергаются возле порогов P-проекции и projected-Q
переключений. Расстояния считаются в пространстве этих проекций, не как
реальный резерв Q. Ненулевая ширина диапазона учитывается; фиксированные
нулевые диапазоны не создают ложный kink. Модуль нулевого тока/мощности
не выдаётся за дифференцируемый. При сингулярном Якобиане нет результата
с производными. Остатки линейных уравнений публикуются, но не являются
оценкой числа обусловленности или гарантией ошибки. Через переключения,
изменения топологии и сертифицированную конечную область доверия производных нет.

Профиль IEEE300: верхняя ветвь при факторах .95/.97/.972/.97207,
исходные P/Q-пределы и Pg сохранены. Выходной узел 235 выбран по минимальному
напряжению независимого начального режима; ветвь 399 — по максимальному
начальному модулю потока. Это внутренние ID закреплённого импорта.
Проверены 12 выходов, P/Q-возмущения выбранного узла, рост всех signed нагрузок

## R03.14 — конечные изменения нагрузок и нелинейная перепроверка, 10 ноября 2026

Добавлен `ac_counterfactual`: явный signed сценарий
Pd_after = Pd_before + amount·dp, Qd_after = Qd_before + amount·dq.
Параметры оборудования, топология, исходные Pg и P/Q-пределы сохраняются.
Допустимы положительный, отрицательный и нулевой amount. Это статический
balanced AC сценарий, не изменение частоты, динамика привода или действие защиты.

Сначала проверяется/решается базовый режим, затем сохраняется локальный прогноз
и выполняется полноценное CPF/envelope-прохождение к конечной нагрузке.
Выход содержит before, linear_after, actual_after, actual_change и linear_error
для каждого выбранного Vm/угла/Pg/delta/P/Q/MVA/pu-тока. Единицы сохраняются
по выходам; ошибки разных физических величин не сводятся в один максимум.
Прогноз не используется вместо физического конечного состояния.

Продолжение получило `initial_state` для native distributed-P/Q профиля:
состояние заново аудируется по сетевым уравнениям, проекциям P/Q и предоставленным
потокам. Начальная сохранённая точка должна точно соответствовать объявленному
аудированному seed. Холодный dispatch при таком запуске не выполняется.
Подменённый seed отвергается до публикации envelope-пакета. Legacy/reference
backend без объявленной distributed-P/Q политики не принимает этот seed.
Это выбор явно заданной ветви, не гарантия её динамической устойчивости.

completed=true означает достижение запрошенной нагрузки и завершённый мониторинг.
requested_change_reached отдельно сообщает о точном конечном режиме: при
неполном мониторинге цель может быть достигнута, но completed остаётся false.
Физическая допустимость по эксплуатационным ограничениям вынесена в target_audit
и target_within_monitored_limits. Сценарий может сойтись с нарушениями V/MVA/
углов/явного pu-тока; сходимость не считается разрешением эксплуатации.

Порог P/Q в начальном режиме или нулевой модуль тока/мощности могут запретить
линейный прогноз, сохраняя возможность нелинейного сценария. Через найденные
P/Q-переключения конечный режим всё равно рассчитывается; прогноз отмечается
observed_control_switch. no_control_switch_observed не доказывает отсутствие
скрытого переключения и не является конечной областью доверия производных.
События за λ=1 сохраняются с явной пометкой outside requested interval.

При развороте ветви до цели actual_after и target_audit отсутствуют:
недостигнутый результат не заменяется экстраполяцией. Признаки глобального
отсутствия решения и устойчивости остаются false. Отмена и бюджеты не создают
ложного конечного состояния; бюджеты базового решения, продолжения и мониторинга
относятся к отдельным этапам, не к общему таймеру всей цепочки.

Проверены шесть зарегистрированных сценариев: IEEE300 .97→.9701, .97→.971
с Q-переключением, .97→.969, .97→1.0 с разворотом до цели; авторские трёхузловые
вход/выход из P-ограничения. Пять целей достигнуты; для шестой сохранён

## R06.8 — прямая импульсная сверка с motulator и ускорение магнитного порта

Реализован `benchmarks.pwm_motor_comparison`: четыре заранее закреплённых
профиля, по 40 ms: linear PWM, saturated PWM, saturated zero-voltage/recovery,
regenerative interval. Используются опубликованные параметры Gamma-машины
из примера Aalto; инерция/нагрузка и PWM fixture — авторская постановка.
Нулевое терминальное напряжение здесь означает заданный zero vector, **не**
открытый выключатель/полную потерю питания. Regeneration имеет интервалы
отрицательной мощности и момента; суммарная энергия источника за окно остаётся
положительной. Не следует называть весь запуск net-рекуперацией.

Primary — рабочий `SwitchingMagnetics`, radial discrete-gradient и связанный
midpoint свободного вала. Reference — оригинальные `InductionMachine` Gamma
outputs/RHS motulator **0.19.0**, отдельно заданное уравнение вала и DOP853.
Оба получают одну независимо созданную кусочно-постоянную двухуровневую PWM
форму: 540 V, 2 kHz carrier, 30 Hz fundamental, modulation .8. Каждый switching
edge является границей интегрирования; не допускается сглаживание импульсов.
Три primary шага — 20/10/5 us; reference rtol=1e-11/atol=1e-12/max_step=50 us.
Это motor+shaft benchmark, **не** native full drive/controller мотулятора:
внешняя RL-сеть, DC-bus, diode network/dead time и FOC в сравнение не входят.
Native motulator не сводится к RMS или собственным переписанным уравнениям.

Зафиксированы колесо SHA256 из `requirements/motulator-reference.lock`,
версия и исходники **всех** установленых Python-модулей reference, producer
и исходник runner. Python reference dependency не нужна runtime-пакету.
Скачивание выполнено из PyPI с проверкой hash; GitHub не использовался.
Неуспех импорта/version/hash/source проверки не превращается в pass/exclusion.

Протоколы — `cases/pwm-motor-comparison/`. В каждом результате явно записаны
8 столбцов: stator/rotor flux αβ, stator current αβ, speed, torque, с SI
единицами в именах. Приёмка требует весь заранее объявленный горизонт/ось,
точный channel inventory, конечные значения и сходимость **каждой** группы
каналов. Два одинаково обрезанных вывода не проходят. Error caps объявлены
до решения: 5e-5 Vs, .005 A, .005 rad/s, .005 Nm; сравниваются fine и finest,
а ошибки всех групп должны уменьшаться coarse → fine → finest.

На 10 us максимальное расхождение с native motulator: 5.55e-7 Vs по потоку,
2.38e-5 A по току, 4.77e-5 rad/s по скорости, 7.24e-5 Nm по моменту.
Во всех четырёх случаях каждая группа ошибок уменьшается при уточнении.
Конечные/максимальные энергетические audits относятся к известным уравнениям,
не измеренному двигателю. У motulator также получена малая энергетическая
невязка; **преимущество по физической точности из этих чисел не следует**.

## R06.9 — актуальный reference, общие accuracy budgets и замкнутый привод

### Актуальный motulator и одинаковые допуски

Из PyPI получен совместимый с Python 3.12 выпуск **motulator 0.23.1**;
точный SHA256 закреплён в `requirements/motulator-current-reference.lock`.
[PyPI release](https://pypi.org/project/motulator/0.23.1/) — источник пакета,
GitHub/CI не использовались. Сверяются байты всех установленных Python-модулей
с wheel, версия и собственные producer/source hashes. Старый lock 0.19.0
сохранён. Адаптер использует native `set_outputs`/`rhs` и native output fields;
четыре reference-траектории 0.19.0 дополнительно пересчитаны без численных
изменений. Исторические receipts остаются привязаны к своим исходникам.

`benchmarks.pwm_accuracy_budget` использует прежние четыре imposed-PWM
motor+shaft постановки, но регистрирует фактические параметры отдельно:
primary h=100/50/20/10 us, DOP853 rtol=1e-4/1e-6/1e-8, atol=rtol*1e-3,
max_step=200 us. Общие caps заранее фиксированы: 5e-5 Vs, .005 A,
.005 rad/s, .005 Nm; ось/горизонт/8 каналов обязательны. Два строгих native
reference (rtol 1e-12 и 1e-13, max_step 20 и 10 us) должны отличаться меньше
1% каждого cap. Это проверка численного reference, не измеренная OEM-истина.

Каждая калибровка выполняется в свежем процессе. Выбирается самый быстрый
прошедший вариант **из конечной сетки**, затем выполняются 3 новых повтора

### Независимая полная замкнутая траектория ограниченного профиля

## R06.10 — ускоренный порт заданного напряжения без редукции клеток

Измеренное отставание R06.9 устранено **в четырёх зарегистрированных
imposed-PWM motor+shaft задачах**. Это отдельный профиль, не утверждение
о скорости всех сетевых/замкнутых исследований или превосходстве продукта.

Профиль CPU показал, что 2752 электрических итерации saturated PWM строили
полный Norton port/gain для уже заданного терминального напряжения. `affine`
и `stage` занимали основную часть времени. Добавлен runtime API
`power_grid_env.prescribed_voltage.voltage_step`: точное исключение всех
роторных неизвестных, два действительных stator unknowns, Newton для
радиального discrete gradient и совместная итерация свободного вала.
Новых runtime dependencies/JIT/скомпилированного backend нет.

При delta=midpoint-old для каждой клетки:
`Dk=2/h+Rk/Lk-j*p*wmid`,
`delta_rk=[-Rk/Lk*(psi_rk_old-psi_s_old)+j*p*wmid*psi_rk_old+(Rk/Lk)*delta_s]/Dk`.
Подстановка этих точных выражений в stator voltage equation оставляет
2x2 реальную систему; radial divided difference, saturation и Gc сохраняются.
Все 1–4 клетки имеют свои R/L/потоки/токи, а не сводятся к одной клетке.
Используются scalar complex arithmetic и аналитический 2x2 Jacobian вместо
построения полной Norton gain matrix для неизвестного voltage port.
Newton имеет line search/лимит итераций; электромеханическая итерация также
ограничена. Невязка Newton <=1e-10 V, итоговая constitutive <=1e-8 V,
согласование midpoint speed <1e-11 rad/s. Несошедшийся шаг выдаёт исключение;
входные flux/passport не изменяются. Адаптивного выбора h этим API не добавлено.

Входной вектор — `[psi_s_alpha, psi_s_beta, psi_r1_alpha, psi_r1_beta, ...]`
в Vs, напряжение — complex alpha-beta peak V, скорость — mechanical rad/s,
шаг — s. Возвращаются новые потоки/скорость, midpoint токи, момент, нагрузки,
раздельные copper/core powers, source power и diagnostics. Поддержаны
постоянный load torque, fan/viscous load и locked shaft при speed=0.
При motor.thermal обязательны **явно заданные** midpoint `[Ts,Tr]`;
R(T) учитывается, но RC-состояния самим этим методом не интегрируются.
Внешнее сопряжение температуры — ответственность вызывающего solver.
Некорректные температуры, неполные потоки и nonfinite inputs отклоняются; токи не clipping.

result = voltage_step(passport, flux_ab_vs, speed_rad_s, 230+40j, 20e-6)

## R06.11 — оптимизация неизвестного сетевого Norton/MNA-пути

Оптимизирован `SwitchingDrive` с неизвестным терминальным напряжением: это
**фиксированный 8-node source/RL/rectifier/DC/PWM/motor профиль**, а не общий
sparse DAE/phase-network решатель. Порт заданного напряжения R06.10 сюда не
подставлялся. Сетевое напряжение по-прежнему находится из связанных уравнений,
source/DC/motor back-reaction и переключения сохранены.

Профилирование nominal .008 s показало 916 electrical-affine вызовов,
1766 линейных коррекций и 12152 вычисления residual; основная часть CPU
приходилась на `_electrical_affine`. Сделано:
- Предвычислены постоянные cap/DC/channel incidence stamps; 64 gate-mask
  матрицы покрывают 27 допустимых состояний трёх half bridges. Это примерно
  32 KiB gate-table на модель плюс небольшие служебные матрицы.
- Материал R/drop не зашит в таблицы: electronics temperature/R/drop читаются
  для каждого trial. Source phase offsets постоянны; для одноточечного
  envelope убраны лишние array/interpolation. Source midpoint вычисляется
  один раз и используется одинаково для KCL и power audit.
- `_network_context` собирает неизменные network terms один раз **на candidate**.
  Shaft/winding-temperature/magnetic iterations заново рассчитывают motor
  offset/gain, но используют тот же network context. Каждый новый шаг,
  откат/thermal bisection создаёт новый context. После возврата он не хранится
  в модели. Нет кэша active diode masks или численной факторизации между шагами.
- Симметричная часть матрицы и smooth gradient не пересчитываются в каждом
  backtracking trial. Критерии Newton/line search/KCL не изменены.

Если каждая motor phase соединена с DC через включённый канал или активный
body diode, применяется diagonally scaled direct solve. Перед принятием
коррекции проверяются finite values и обратная невязка scaled linear system
<=5e-12*(1+max|rhs|). При LinAlgError/неfinite/плохой невязке используется
прежний scaled least-squares/SVD с rcond=1e-14. Во всех остальных topology
active sets, включая floating isolated-star gauge, сохраняется SVD. Эти
состояния не обязательно все сингулярны: выбор намеренно консервативен.
Не добавлены шунт, численное заземление или диагональная регуляризация.

Новые additive metrics: `linear_direct_solves`, `linear_least_squares_solves`,
`linear_direct_fallbacks`. Они учитывают computational trials, включая
повторные Newton/thermal localization, а не только принятые physical steps.
На измеренном corpus direct fallback failures=0; искусственные failure
сценарии проверены тестами. Для nominal было 13724 direct и 2042 SVD solves;
для saturated four-cage —91670/15276. При initial trip/cooling direct=0,
SVD=47224: корректный floating-star путь не был заменён на regularization.

### Воспроизводимое сравнение предыдущего и нового пути

source, electrical assembly/coupling и candidate методы. Добавлены лишь
счётчики для совместимости diagnostics; magnetics/control общие и в этом
блоке не менялись. Это before/after reference собственного алгоритма,
**не** независимый физический эталон и не внешний симулятор.

`benchmarks.mna_network_acceptance` фиксирует 8 сценариев: nominal, grid sag,
PWM recovery, precharge (.04 s), warm winding, saturated four-cage thermal,

## R06.12 — независимая расширенная замкнутая траектория

`benchmarks.extended_closed_loop_reference` независимо решает сеть, все
потокосцепления, вал и температуры обмоток в смешанных неизвестных через
SciPy root. Production Norton elimination, motor RHS, FOC, PWM и winding RC
реализации не импортируются. Номинальный current-model observer/PWM отдельно
выражены в benchmark reference R06.9; observer получает измеренный ток и
скорость, а не истинные потокосцепления/температуры расширенной машины.
Обе реализации используют одну математическую midpoint/discrete-gradient
схему: это проверка реализации уравнений, не независимый непрерывный эталон.

Зарегистрированы четыре 40-ms исследования: насыщенная одноклеточная машина
с Gc; двухклеточная; насыщенная четырёхклеточная с Gc, провалом напряжения и
блокировкой/восстановлением gates; нагретая четырёхклеточная с двухузловым
тепловым балансом и Rs/Rr(T). Статические JSON доступны в
`cases/closed-loop-extended-independent/`. Параметры добавочных клеток,
насыщения и тепловых RC — авторские, не идентифицированные паспорта OEM.

Сверяются все клетки, наблюдаемый ток, source currents, DC, вал, observer,
температуры и gates. Накопленная энергия потерь стали, статора и ротора
проверяется отдельно: core heat входит в stator heat, поэтому их нельзя
суммировать ещё раз. Для обмоток энергия хранится в RC, наружу уходит только
ambient heat. Endpoint Gc-ток заново находится из отдельной трёхузловой
пассивной сети при текущих gates; предыдущий ток через переключение не
переносится. Проверены все 27 допустимых gate-состояний, включая floating star.

Между реализациями на одинаковом шаге установлены caps: DC 0.02 V, shaft
0.002 rad/s, motor current 0.005 A, source current 0.01 A, flux 1e-5 Vs,
температура 0.001 °C, интегральные motor heat 1e-5 J, gates/events точно.
Каждая траектория дополнительно проверяет свой energy/KCL/magnetic residual;
малое расхождение между двумя нарушающими баланс решениями не засчитывается.

`extended_closed_loop_refinement` добавляет третий шаг 5 us к 20/10 us;
сравнивает уменьшение нормированной разницы отдельно для сети,
machine/observer и тепловых состояний. Это не доказательство порядка
сходимости. `extended_temporal_budget` сохраняет каждую попытку на
2.5/1.25/0.625 us и требует одновременно уменьшающуюся разницу и попадание
изменений всех физических каналов в те же единичные caps у обеих реализаций.
Это Cauchy/self-consistency критерий, не абсолютная оценка ошибки относительно
непрерывного решения. Шаг нельзя переносить на произвольное оборудование.

Артефакты защищены SHA-256 manifest. При numerical replay конечные floats
имеют абсолютный допуск 5e-10 без относительного ослабления, время — 5e-13 s;
структура, типы дискретных данных, integer counters, события и pass/fail
совпадают точно. Учтён JSON round trip NumPy float64. Первичный физический
acceptance этот replay-допуск не использует. Побитовая воспроизводимость
SciPy root не утверждается; целостность сохранённых файлов проверяется точно.

Открыты независимые полные switching-energy jumps/thermal-trip localization,
variable semiconductor R(T), multicage observer, общая DAE-сеть, внешний
continuous-time oracle и физическая калибровка. Этот блок не устанавливает
превосходство над другими симуляторами и не меняет прежние speedup claims.


В дополнительной декомпозиции `double_cage` немонотонность machine/thermal
разностей сохранилась при замороженных командах **и** duty/edge расписании
ШИМ (число gate edges одинаково). Следовательно, объяснение «только ошибка
observer/FOC» не подтверждено. Это не доказывает конкретную причину: дальше
нужно отдельно исследовать сетевые коммутации, жёсткие внутренние интервалы
и временную схему при фиксированном gate schedule. Исходный closed-loop
negative result сохраняется; diagnostic не используется для его замены.


Финальный R06.12 receipt: 466 selected tests (81 новых), без skip;
24 траектории и 24 numerical replay, 4 installed-wheel/ZIP проверки на том же
host. Общий temporal-budget passed=false, дополнительно выполнено
24 траекторий; отрицательные результаты сохранены. Перечень по
сценариям и дальнейшая очередь — `plans/CURRENT_STATUS.md`, точные hashes —
`reports/extended-closed-delivery-2026-11-11/delivery.json`. Полный release suite,
внешняя ОС и absolute-error qualification не заявлены.

Дополнительный frozen-command/PWM diagnostic: 21 production-траектория. Voltage-only tape сохраняет DC-зависимый PWM; voltage+PWM tape фиксирует duty/edge clock, но оставляет реальную сеть, диоды, вал, температуры и enable/block logic. Это диагностическая декомпозиция, не независимый oracle и не замена непрошедшего temporal pass.


## R06.13 — пользовательская проверка временной самосогласованности

`power_grid_env.switching_convergence` переносит Cauchy-проверку из benchmark
в публичный API и CLI. `switching-drive qualify` последовательно делит
`max_step_s` пополам. Нужно три последовательных аудированных траектории,
попадание разностей двух последних в физические caps и уменьшение
нормированных разностей в network, machine/observer и thermal группах.
Последовательность не обязана быть монотонной с первого грубого шага: все
ранние непрошедшие попытки сохраняются и не подменяются успешным результатом.

Default caps сохранены: DC 0.02 V, motor current 0.005 A, source current
0.01 A, flux 1e-5 Vs, shaft 0.002 rad/s, temperature 0.001 °C. Отдельно
проверяются все 1–4 клетки и winding/electronics temperatures, собственные
energy/KCL/magnetic audits каждой траектории, физические discrete actions
и event kind/component/cause/timestamps (1e-8 s). Voltage-limiter metadata
проверяются при включённых gates; неактивные limiter roundoff snapshots
не считаются изменением физического действия. `last_midpoint_*` не являются
общей временной сеткой и в Cauchy channel test не участвуют. Интегральный heat
не получает абсолютного error certificate от этого workflow; он остаётся
частью собственного energy audit и отдельной независимой R06.12 сверки.

Входные limits строго положительные/конечные и сохраняются в protocol JSON.
Пользовательские limits — отдельный явно записанный профиль, не результат
при default caps. Reduction factor по умолчанию 0.85, floor 1e-8 от unit cap
для roundoff-only групп; доказательство асимптотического порядка не заявлено.
`qualified=true` означает только описанную temporal self-consistency:
`absolute_error_certified=false`, `independent_reference=false` сохраняются
даже при успешном результате. Это не industrial/OEM certification.

Новый явный `step_budget` ограничен 1000..2000000 accepted steps. Default
300000 и прежний planned guard 200000 сохранены (план резервирует треть
бюджета для PWM/sample/event границ). Нестандартный бюджет присутствует в
каноническом study; default поле опускается, поэтому прежние JSON не меняются.
Фактическое исчерпание теперь отвергается до следующего physical advance,
без дополнительного изменения потокосцеплений, токов, температур или latch.
Плановая оценка не гарантирует завершения: фактический guard действует всегда.

Границы ресурсов, solver failure, неполные/нефинитные каналы, неверный clock,
отсутствующие клетки и провал physics audit не дают ложного qualified.
История уровней и причины отказа входят в sealed artifact. CLI возвращает
0 для qualified и 2 для unqualified/rejected; `completed=true` само по себе
не означает, что критерии пройдены. `verify`/ZIP подтверждают целостность
артефакта, не заменяют numerical replay.

Дополнительные пробные source/motor zero-current brackets не устранили
немонотонность и не включены в runtime. Уравнения, Norton port, midpoint,
регулятор и модель потерь остались прежними. 8 default-budget траекторий
R06.12 и R06.13 совпали по всем сохранённым numerical values в точности.
Сходимость при очень мелком шаге не устанавливает единственную причину
предыдущей немонотонности. Следующая численная задача — уменьшить стоимость
прошедших profiles с проверяемым error control, не ослабляя caps.


Финальная R06.13 проверка: 537 selected tests (71 новый), failures/errors/
skips=0. 21 workflow + 9 deep + 16 independent-comparison protocol runs;
для 21+16 выполнен numerical replay. Deep numerical replay не выполнялся.
После исправления JSON-сериализации NumPy audit bool финальный scorer
переоценил 21+9 сохранённых траекторий; это не новые numerical runs.
`benchmarks.switching_qualification_reassessment` требует исходный wheel с
совпадающим recorded code hash и byte-identical numerical Python modules;
различаться может только qualification scorer. Сохраняются waveform и
assessment producers, source manifest и флаг numerical_replay=false.

Default-budget double-cage по-прежнему отрицателен; его отдельный повышенный
budget=2000000/max-levels=9 профиль прошёл на 39.0625 ns, 1024754 accepted
steps в последней 40-ms траектории. Уменьшение разностей не устанавливает
абсолютную continuous-time accuracy или единственную причину немонотонности.
Стоимость профиля остаётся открытой инженерной задачей. Матрица, hashes,
ограничения и дальнейшие критерии находятся в CURRENT_STATUS и delivery JSON.


## R06.14 — повторное использование Newton evaluations и hot-path allocations

Профилирование bounded double-cage случая показало повторную работу в
`_electrical_affine`, magnetic port и NumPy index-concatenation. Изменения:

- Уже вычисленные residual/diode/forward значения принятого Newton trial
  используются в следующей итерации той же неизменной электрической системы.
  Кэш не переносится между шагами, magnetic/shaft/temperature итерациями,
  rollback или переключениями.
- Сохраняется исходное OR-правило line search: сначала проверяется уменьшение
  residual; при его отсутствии вычисляется прежняя potential merit. Symmetric
  matrix и gradient строятся только когда нужны. Условия/пороги не ослаблены.
- Постоянная для этого linearized trial часть roundoff threshold вычисляется
  один раз; зависимость threshold от текущего напряжения сохранена.
- Для beta=0 radial gradient вычисляется той же линейной формулой без
  ненужных radius/power/outer операций. Насыщенная ветка сохраняется.
- `np.r_` в горячих magnetic paths заменён эквивалентным concatenate;
  повторное `matrix @ old + offset` заменено локальным результатом одного
  вычисления. Rs/Rr(T), Gc, все клетки, torque и heat equations сохраняются.

`benchmarks.switching_hotpath_reference` содержит frozen R06.13 constructor,
network solve и magnetic methods до изменений. Это собственная прежняя
реализация, а не независимый physical oracle. `switching_hotpath_acceptance`
проводит paired before/after: четыре 40-ms случая на 10 us и отдельный
40-ms double-cage на 39.0625 ns; по три fresh workers на реализацию/случай,
чередующийся порядок. Общие imports/BLAS warm-up вне clocks, constructor и
полное формирование результатов внутри, JSON serialization вне clocks.
BLAS/OMP/MKL=1; Linux ru_maxrss, CPU/wall/min/median/max сохраняются.
CPU affinity/frequency и сторонняя нагрузка OS не изолируются.

Same-step сравнение охватывает physical channels, circular frame angle,
дискретные действия, events, energy integrals и собственные physics audits
обоих провайдеров. Last-interval snapshots описаны отдельно; они не являются
общей физической временной сеткой. Exact-value совпадение и повторяемость
результатов фиксируются отдельно, не подменяют физические caps.
Четыре 10-us workload не объявляются temporally qualified этим timing test.

Шаг и число accepted steps не уменьшаются. Ускорение относится к исполнению
прежних уравнений, не к adaptive integration и не к сравнению со сторонним
симулятором. Контрольный deep профиль по-прежнему требует около миллиона
шагов; независимый continuous-time accuracy bound не заявлен.


Финальный R06.14 protocol: 30 paired full trajectories, old/new exact values
во всех парах и exact repeated values у обоих implementations. Median ratios
на пяти workloads — 1.1416..1.2221; deep 267.8255 → 219.1555 s при прежних
1024754 steps. 760 selected tests (223 новых), без failures/errors/skip.
Fresh three-mesh CLI qualification сохранила 39.0625 ns и точные original
fine values; 16 independent-comparison trajectories прошли и повторены.
Полный 30-run benchmark `--verify` отдельно не выполнялся. Source/current
producers, timings, manifests, raw values, profiler counts, wheel и границы
собраны в `reports/switching-hotpath-delivery-2026-11-11/`.

### R06.15: адаптивный switching — отдельный протокол

Уменьшение `max_step_s` при активном адаптивном оценщике может не изменить
фактическую сетку. Поэтому fixed-mesh qualification запрещает `adaptive`.
Новый `benchmarks.switching_adaptive_acceptance` уменьшает
`error_budget_fraction`: 0.2 → 0.1 → 0.05. До запуска закрепляются физические
допуски, SHA256 архивных траекторий и fingerprint текущего пакета. Каждый
полный результат, отказ и соседняя разность сохраняются; успешность требует
всех физических audits и сравнений с архивом и соседним бюджетом. Протокол
не утверждает монотонность, порядок сходимости или абсолютную точность.

Оценщик принимает два native midpoint полушага без Richardson correction.
Пробные состояния изолированы; стоимость грубых, отвергнутых и root-search
проб входит в счётчики. Нулевая поверхность тока источника требует restart:
коррекция ограничена declared current tolerance и отдельным энергетическим
лимитом. Она записывается отдельно, не прибавляется к физическим потерям;
баланс энергии результата продолжает проверяться без сокрытия этой поправки.
Число принятых шагов само по себе не доказывает выигрыш CPU. Для performance
сравнения нужны повторные изолированные запуски на одном host.

Первое ужесточение бюджета выявило честный отказ double-cage: 0.2 проходит,
0.1/0.05 достигают min_step_s. Это делает общий итог false, даже если другие
семейства проходят. Диагностический повтор 0.1 на t≈0.0289197603 s показывает
разность flux 1.99e-8 Vs между грубым и двумя полушагами при h=1e-10 s;
источниковый current delta ≈1.78e-15 A, событие source-zero не обнаружено.
Следующая работа — исследовать алгебраические потенциалы/переключения и
обусловленность midpoint на этой поверхности, а не повышать допуски задним
числом. Эти наблюдения сами по себе не доказывают причину отказа.

### R06.16: точечная сверка Newton на переключении body diode

Зафиксирован исходный state в `tests/fixtures/switching_adaptive_hinge.json`:
авторские параметры, t≈28.9197603 ms, h=1e-10 s. У слабого motor pole
после выключения диода Newton-direction достигает ≈9 kV, тогда как следующая
диодная граница находится в нескольких microvolts. Legacy roundoff threshold
всей матрицы допускает unresolved motor row; простое ужесточение всех строк
вызывает line-search failure. Пробный all-row вариант отклонён.

В `motor_scaled` external/rail rows сохраняют прежний roundoff-aware порог,
а motor rows получают отдельную componentwise шкалу. Начальный Newton trial
ограничивается ближайшей положительной диодной границей с малым пересечением;
обычные residual/potential merit и backtracking остаются обязательными.
Это не изменение физических допусков temporal-протокола и не добавление
сопротивления, ёмкости или искусственного демпфирования.

Проверка frozen legacy воспроизводит flux difference >1e-8 Vs. Новый coarse/
two-half estimator на этом же state ≈1.33e-5 (ранее 19.9). Четыре стадии
h=0.05/0.1/0.2/1 ns сверены с независимыми mixed equations: flux atol1e-10 Vs,
потенциалы motor poles atol1e-3 V. Это точечная независимая проверка, не
независимая полная adaptive-траектория. Параметры не являются натурными.

Fresh full 0.2 matrix: четыре модели проходят прежние physical-unit caps и
physics audits. Fresh double 0.1/0.05 завершаются без solver failure, но
machine/observer caps относительно исторического fine result превышены.
Не следует переименовывать это в passed: solver robustness и глобальная
точность являются разными критериями. Между tighter adaptive budgets есть
близкое совпадение, но оно не заменяет независимый эталон. Fixed-mesh refinement
с новым solver также сохраняет все отрицательные оценки.

Fresh 39.0625 ns run даёт qualification extension к ранее сохранённым
156.25/78.125 ns meshes. Latest-pair normalized errors: network0.03554,
machine/observer0.66918, thermal7.13e-6; reduction/audits passed.
`benchmarks.switching_hinge_tail` воспроизводит оценку без пересчёта:
требует одинаковый fingerprint и всю study кроме halved max_step_s,
проверяет input manifests и использует исходные limits. Это production
Cauchy self-consistency; полный adaptive 0.1/0.05 по-прежнему не passed.

### R06.17 — нулевой ток двигателя и совпадающие события

Отдельное событие motor_current_zero контролируется только на фазах с обоими
выключенными управляемыми каналами. Грубый шаг и полушаги локализуют событие
до согласования времени и идентичности; принимаются native states, без
проекции/обнуления потокосцеплений. Остаток тока записывается в event log,
`flux_projection=false`; энергия не списывается в искусственные потери.
`motor_event_current_a` задаёт current tolerance (стандартно 1e-7 A, оценщик
может использовать меньшую величину с учётом бюджета). `min_step_s`
ограничивает обычные trial steps; локализованный остаток до события может
быть короче. Это не обход ошибки и не изменение global physical caps.

При исчезновении всего вектора тока изолированной звезды последние
проводящие ветви выключаются совместно. Signed roundoff сам по себе может
дать разные номера фаз для coarse/fine. Распознавание canonical vector-zero
использует тот же current tolerance и одинаковый набор исходно проводящих
свободных фаз; физическое состояние не изменяется. Отдельный regression
fixture воспроизводит прежний отказ signed-only распознавания.

`switching_motor_zero.json` и `switching_motor_coincident.json` в
`tests/fixtures/` содержат два авторских состояния. Независимые mixed
уравнения проверяют четыре принятых native pieces. Free motor common-mode
является gauge: проверяются AB voltage, а не произвольный общий потенциал.
Flux cap1e-10 Vs, network/AB voltage1e-3 V, source current1e-7 A,
reference equation residual2e-6. У reference та же midpoint/DG схема;
это не independent continuous-time trajectory и не натурные измерения.

`benchmarks.switching_motor_zero_stages` воспроизводит stage-проверку;
`benchmarks.switching_motor_zero_ablation` выполняет intervention: только
adaptive driver заменяется закреплённым собственным R06.16 исходником
`benchmarks/switching_adaptive_r0616.py`. SHA256 старого driver проверяется
до исполнения; это собственный frozen baseline, не внешний oracle.
Текущий и старый driver используют одинаковые электрические уравнения,
параметры, scheduler, audits и caps. Historical-result check необязателен;
при наличии архива требуется точное совпадение, с исключением нового
нулевого telemetry counter motor_boundaries. Reference SHA256 закреплён
protocol-файлом current run. Полная матрица R06.17 сохраняет ранние отказы,
а не подменяет их результатами после исправления coincidence.

Итог R06.17: fresh final matrix **12/12 passed**; отдельный
`benchmarks.switching_adaptive_budget_qualification` подтвердил decreasing
adjacent differences по прежнему reduction_factor0.85 для всех network,
machine/observer и thermal групп. Он требует три half-budget уровня с
неизменной study, закреплённые reference hashes, неизменные default caps,
producer identity и sealed input. Проверяются также numerical event residuals,
отсутствие flux projection, resource/event counters и source correction sum.
Выбранный qualified budget0.05 относится к этим четырём studies; это не
универсальная рекомендация и не absolute error certificate.

Frozen-driver ablation: baseline точно совпал с архивным R06.16 failed
результатом; только замена adaptive driver меняет failed → passed при тех же
электрических уравнениях и caps. До coincidence fix первая полная matrix
сохранила 11/12 passed с одним честным solver rejection; затем выполнена
новая полная matrix на другом fingerprint. Эти серии не смешиваются.

Numerical root labels не являются полным перечнем физических diode mode
transitions: integration_event_log содержит события, потребовавшие явной
локализации solver mesh. Если более мелкая сетка уже пришла в допустимую
окрестность нуля, дополнительная root label может отсутствовать. В warm-four
budget0.2 содержит такую motor label около33.485728 ms, отсутствующую при0.1;
все physical caps/actions и reduction остаются passed. Это наблюдение
сохранено отдельно; certificate не утверждает идентичность numerical mesh
labels при изменении бюджета. Для SFT/GRPO нельзя трактовать отсутствие
такой label как доказательство отсутствия физического переключения.

### R06.18 — full continuous reference с внешним motor RHS

Четыре зарегистрированных 40-ms studies: linear-core start, saturated-core
start, saturated sag/gate block/recovery и warm single-cage RC/R(T) start.
Параметры авторские; measured/OEM accuracy не заявлена. Профиль требует
single cage, положительный Gc, nominal observer, нулевые switching energies,
постоянные semiconductor resistances и отсутствие active brake/thermal trips.

Внешний RHS: оригинальный `motulator.drive.model.InductionMachine` 0.23.1,
wheel SHA256 `dc184858cead49aa31c2e9f4bfbb149b6489850aad2360f1005b012fa3218000`.
До импорта проверяются version, все installed Python bytes и source inventory
против wheel. В отдельном процессе запрещён любой power_grid_env import;
заранее загруженный production module также вызывает отказ.

Сеть, source hybrid guards, passive bridge active sets, FOC, observer,
PWM/dead time и thermal storage записаны отдельно. Не используются runtime
stamps, Norton port, midpoint/discrete-gradient или production event engine.
Внешняя машина не модифицируется; Rs/Rr получают температуру как параметры.
Gc feedthrough позволяет решить instantaneous bridge KCL, включая gate block;
free common mode выбирается как gauge без дополнительного resistor/capacitor.
Это НЕ весь converter simulator пакета motulator.

Эталоны:

- DOP853: rtol1e-12, atol1e-14, max_step25us;
- Radau: rtol3e-11, atol3e-13, max_step25us.

Их disagreement должен быть <=0.01 каждого неизменённого physical cap;
оба проходят energy/KCL/constitutive audits. Primary budgets0.2 и0.05
сравниваются с обоими полными reference trajectories. 4×2 primary и4×2
reference =16 используемых trajectories, не16 схем. Performance ranking
не выполняется; case workers могли исполняться параллельно.

Все8 primary прошли. Максимальный normalized primary error0.2722962,
максимальный reference disagreement6.62501e-5 (0.006625% physical cap).
Энергетические балансы учитывают DC/earth capacitance, source inductance,
magnetic/shaft/thermal storage, core/copper/semiconductor heat и ambient/load.
Source zero reset в continuous reference ограничен root solve и записан
отдельно как tiny energy correction; искусственный motor flux reset отсутствует.

Независимый reference нашёл sample-clock дефект: repeated-addition время
оказывалось наulp раньше24/28ms, из-за чего gates_enabled сообщал старую
сторону окна. Исправление меняет только report(): canonical sample time и
permission на нём. Электрический state/current — pre-switch snapshot;
permission — right-hand eligibility. Строгий AST/wheel comparator допускает
только эти две report locals и две time substitutions; любой RHS, control,
Newton, current или clock-scale mutation отвергается. Все остальные runtime
Python files совпадают с previous wheel побайтно.

Full before/after comparison: все8 физических output matrices, ledgers,
controls и work counters совпадают в точности. Четыре gate labels изменены
на24/28ms в двух recovery budgets. Это исправление данных, не ослабление
сравнения: flags по-прежнему требуют точного совпадения. Initial failed
recovery artifacts сохранены; sealed historical data не переписывались.

независимого reference source, solver controls и native wheel. Primary данные

source hashes. Отсутствие production imports делает reference независимым от
report-only изменения runtime package. Это явно отмечено в cache protocol.
