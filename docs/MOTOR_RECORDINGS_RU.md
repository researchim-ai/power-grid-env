# B16 — записи двигателя: CSV → проверенный вход → идентификация

Импорт позволяет готовить исследования без ручного редактирования массивов JSON.
Принимаются синхронные мгновенные измерения напряжения, тока и механической
скорости. Пример из открытых синтетических наблюдений уже включён в репозиторий:

```sh
python -m power_grid_env.cli motor-recordings import \
  --input cases/motor-recordings/protocol.json --out /tmp/motor-recordings
python -m power_grid_env.cli motor-recordings verify /tmp/motor-recordings
python -m power_grid_env.cli identify-dynamic-motor \
  --recordings /tmp/motor-recordings --out /tmp/motor-identified
```

Оба выходных каталога должны быть новыми. Откройте `report.html` внутри первого
для просмотра наблюдений, происхождения, частоты, диапазона шагов и проверок
последовательностей. Второй содержит обычный отчёт B15 и принятый `passport.json`
**только при успешной идентификации**. Успех импорта означает подготовку данных,
а не численную приёмку двигателя. Все действия локальны; сеть, GitHub и CI для
этих команд не нужны.

## Протокол

`power-grid-env.motor-recordings/v1` содержит:

- `identification`: исходный паспорт и настройки B15, без `fitting`/`validation`;
- `recordings`: 1–4 тренировочные и 1–4 проверочные записи;
- для каждой записи: `id`, `source`, `provenance`, `origin` (`synthetic` либо
  `measured`), `split`, `frequency_hz`, формат координат и явные единицы;
- общий для всех каналов `time_column`, `time_unit` (`s`, `ms`, `us`) и
  `delimiter` (запятая, точка с запятой, табуляция);
- `initial_stator_flux_vs` и `initial_rotor_flux_vs`, заданные явно в тех же
  неподвижных αβ-осях, и масштабы `current_sigma_a`/`speed_sigma_rad_s` в SI.

Путь `source` задаётся относительно каталога протокола. Абсолютные пути,
выход за каталог и символьные ссылки на файл не допускаются. CSV — UTF-8,
возможен BOM, первая строка содержит уникальные заголовки. Числа записываются
с десятичной точкой, заголовки сопоставляются буквально. Незаполненные строки,
неконечные значения, дубли времени, недостаточные/лишние поля отвергаются.
Дополнительные колонки разрешены, но не используются и не интерпретируются.
Метаданные и поля каналов вне схемы запрещены. JSON Schema выгружается командой
`schemas` в `motor-recordings.schema.json`.

Для `coordinates: alpha_beta` нужны каналы `ua`, `ub`, `ia`, `ib`, `speed`.
Для `abc_phase_to_neutral` нужны `u_a`, `u_b`, `u_c`, `i_a`, `i_b`, `i_c`, `speed`.
Ключи обозначают физическую величину, `column` — её заголовок в конкретном CSV.
Например, описание инвертирующего токового датчика:

```json
"i_a": {"column": "CT_A", "gain": 2, "polarity": -1, "offset": 17}
```

Преобразование строго: **(raw − offset) × gain × polarity**, затем перевод
единиц. Offset задаётся в исходных единицах канала, gain положителен, polarity
равен ±1. Это объявленная пользователем калибровка, не автоматически найденный
коэффициент датчика. Единицы напряжения — V/kV, тока — A/mA/kA, скорости —
rad/s/rpm. Потокосцепления всегда в Vs; масштабы ошибок всегда в A и rad/s.

## Координаты и проверка применимости

Три напряжения должны быть **мгновенными фазными относительно нейтрали на
выводах двигателя**, токи — фазными, порядок фаз a,b,c. Линейные напряжения,
RMS, огибающие, фазоры, электрическая скорость вместо механической и неизвестные
начальные потоки в этот профиль не входят. Их нельзя подставлять с другим
названием единиц.

Применяется амплитудно-инвариантное преобразование Кларка:

`xα = (2/3)·(xa − xb/2 − xc/2)`;
`xβ = (2/3)·(√3/2)·(xb − xc)`.

Для симметричной системы модуль αβ-вектора равен **амплитуде фазного** сигнала,
поэтому 400 V line-line RMS соответствует √(2/3)×400 V в αβ. Масштаб sqrt(2)
не применяется к уже мгновенным данным. Скорость rpm переводится через 2π/60.

Для abc вычисляется отношение максимума нулевой составляющей к максимуму
модуля вектора отдельно для напряжения и тока. Порог по умолчанию 0.001,
максимально разрешённый — 0.01 (`maximum_zero_sequence_ratio`). Для αβ нулевая
составляющая не наблюдаема и не считается проверенной.

По всему окну напряжения методом наименьших квадратов оцениваются комплексные
коэффициенты `exp(+jωt)`, `exp(−jωt)` и DC. Отношение обратной основной
последовательности к прямой должно быть не выше
`maximum_negative_sequence_ratio` (по умолчанию 0.01, верхняя граница 0.05).
Прямая составляющая должна быть разрешима. Этот ограниченный скрининг
выявляет, например, перестановку фаз и сильную несимметрию; он **не доказывает**
симметрию всех переходных составляющих, отсутствие гармоник, правильность
частоты или исправность датчиков. Модуляция напряжения и короткое окно могут
влиять на оценку. Обратная последовательность тока не используется как
запретительный критерий: пусковые переходные составляющие требуют отдельного
анализа.

## Время, ограничения и независимый набор

Поддерживается один общий строго возрастающий числовой clock на запись.
Из всех времён вычитается первый отсчёт; его исходное значение в секундах
сохраняется в диагностике. Это перенос начала координаты, **не выравнивание
разных датчиков**. Значения сигналов и начальные потоки при этом не вращаются.
Фильтры, интерполяция, восстановление пропусков, подбор задержки и обрезка
участка не выполняются. Известное начальное состояние относится именно к
первому отсчёту. Неизвестный остаточный поток нулём автоматически не заменяется.

Ограничения: 33–20001 отсчёт, минимум три периода для скрининга, максимум две
секунды, наибольший промежуток между отсчётами ≤0.1 периода. Допускается
неравномерный общий clock. До 12 MB на CSV, 64 MB суммарно, до 64 колонок.
После преобразования действуют ограничения амплитуд и объёма JSON B15.
Переполнение при калибровке и преобразовании времени отвергается.

Повторное использование одного возбуждения и начального состояния проверяется
без учёта выходного тока: переименование или изменение только измеренного тока
не создаёт независимый опыт. Дополнительно ловятся повторы с округлением после
перевода единиц и abc/αβ: одинаковые размеры, частота в пределах 1e-9 Hz,
начальная скорость в пределах 1e-9 rad/s, время/напряжения/начальные потоки
с `rtol=1e-10`, `atol=1e-9` в SI. Это защита от численных дублей; она не ищет
произвольные сдвиги времени и не подтверждает статистическую независимость.

Физический профиль решателя не расширен импортом: одна клетка, фиксированная
температура, нулевой Gc, известная частота и потоки; ограничения и критерии B15
описаны в [DYNAMIC_MOTOR_IDENTIFICATION_RU.md](DYNAMIC_MOTOR_IDENTIFICATION_RU.md).

## Сохранность и перенос

Пакет содержит исходные CSV без изменений (`sources/00.csv` и далее), протокол,
подготовленный `study.json`, `result.json`, автономный HTML и манифест SHA-256.
Поле `source_time_origin_s` относится к числовому clock, не к календарной дате.
Происхождение и хеш исходных байтов входят в каждую трассу решателя.
`origin: measured` — заявление автора, а не подтверждённое измерение/OEM-паспорт.

`verify` проверяет и инвентарь байтов, и **заново выполняет преобразование** из
сохранённых CSV с точным сравнением входа, диагностики и отчёта. Простая подмена
`study.json` или утверждения об успехе с новым манифестом не проходит проверку.
Вход `identify-dynamic-motor --recordings` вызывает её до запуска физического
решателя. Для переноса доступны `study_artifacts.export_zip`/`extract_zip`;
после извлечения выполните `motor-recordings verify`. SHA-256 обеспечивает
контроль целостности, не подпись и не подлинность внешнего источника.

## Приёмка и следующие расширения

```sh
OPENBLAS_NUM_THREADS=1 python -m benchmarks.motor_recording_acceptance \
  --out /tmp/new-recording-acceptance
python -m pytest tests/test_motor_recordings.py
```

Корпус использует закреплённые хешами **сохранённые** B15-наблюдения исходного
motulator 0.19.0: линейный/насыщенный вентилятор, насыщенный вязкий привод,
заторможенный двигатель. Для каждого формируются αβ и abc CSV в kV/mA/rpm/ms,
с началом clock=2 s, инверсией, смещением и масштабом одного датчика. Проверяются
обратное преобразование с абсолютной погрешностью <1e-9, перенос ZIP, повторная
проверка и идентификация с отдельным свободным hold-out. Параметры сравниваются
с истинным паспортом с относительным допуском 5e-5 на бесшумной синтетике.
Это восемь сквозных сочетаний, а не восемь новых натурных двигателей. Генератор
CSV не вызывает физические уравнения основного решателя. Сам приёмочный скрипт
не запускает motulator заново; исходники генерации и предыдущая независимая
приёмка сохранены в B15. Отдельные тесты B15 могут запускать закреплённый
motulator при наличии его wheel.

Следующий отдельный блок — ограниченная идентификация с шумом/ошибками датчиков:
отдельная приёмка разрешимости, невязок и переноса на hold-out. Затем можно
расширять работу с разными clock, неизвестным остаточным потоком и задержками.
Эти возможности текущим импортом не заявляются.
