# B20 — независимая DC-опора сопротивления статора

```sh
python -m power_grid_env.cli anchor-dynamic-motor \
  --input cases/anchored-identification/locked-dc-anchor.json \
  --out /tmp/anchored-motor
```

Это **новый условный протокол**, требующий дополнительных независимых данных.
Он не объявляет прежний подбор четырёх неизвестных параметров успешным.
Входные динамические U/I/ω, паспорт-seed остальных параметров, sigma, hold-out,
численный метод и физические допуски остаются прежними. Вместо оценки Rs только
по пусковым записям используется отдельная опора установившегося DC U/I.

Включённый пример синтетический: DC-точки созданы по опубликованному постоянному
Rs=3.7 Ω модели Aalto и авторским абсолютным погрешностям. Это не измерения
оборудования и не характеристики реального прибора. Собственное оборудование
для повторения численной приёмки не требуется.

## Почему дополнительная информация нужна

В locked-rotor опыте B19 исходный raw-fit, ранг и свободный hold-out проходят,
но сетевые потери отличаются от истинного паспорта примерно на 0.776/0.796 W
при лимите 0.5 W. Полный ранг не гарантирует требуемую точность каждого
производного инженерного показателя на шумных данных.

Приёмка B20 повторяет старый опыт и разделяет причины:

- forward сравнивается с DOP853 при в 1000 раз более строгих допусках;
- первичная сеть и исходный motulator/MNA сравниваются **при одинаковом
  найденном паспорте**; численная ошибка потерь должна быть ≤0.005 W;
- затем найденный паспорт сравнивается с истинным паспортом в том же сетевом
  исследовании. Прежний предел 0.5 W остаётся обязательным.

Это отделяет численную согласованность решателей от ошибки параметров. Метод
не оценивает доверительный интервал и не доказывает общую статистическую
идентифицируемость расширенной задачи с неизвестными датчиками.

## DC-измерение: единицы, подключение и предпосылки

`power-grid-env.anchored-dynamic-identification/v1` содержит исходный `audit`
B17, обязательное `stator_resistance_measurement` и суммарные рабочие лимиты.
JSON Schema экспортируется как `anchored-dynamic-identification.schema.json`.

Измерение задаёт:

- `points`: 2–64 различных по уровню тока установившихся DC-точки;
  `voltage_v`, `current_a`, `voltage_absolute_error_v`,
  `current_absolute_error_a`, все в SI. U/I положительны и должны превосходить
  свои абсолютные погрешности;
- `connection`: `phase_to_neutral` или `wye_line_to_line`;
- `settled_dc_confirmed: true`: индуктивный переходный спад отсутствует;
- `voltage_is_winding_only: true`: напряжение относится к обмотке, без
  неизвестного падения на проводах/контактах;
- одинаковые `measurement_temperature_c` и `trace_temperature_c`;
- `origin`, непустое `provenance`, отдельные `voltage_reference` и
  `current_reference`. Для `origin: measured` обе опоры должны быть
  `declared_external_calibration`, а не `synthetic_known`.

Для звезды при измерении между двумя фазами сопротивление пути равно 2Rs,
поэтому используется коэффициент 2. Требуется симметричная обмотка модели.
Треугольник, неизвестное подключение, неизвестные контакты, неустановившийся
DC и автоматическая температурная коррекция не поддерживаются. Протокол
исходит из постоянного одинакового AC/DC Rs данной Γ-модели; это не доказано
для произвольного оборудования с частотными/температурными эффектами.

Данные об установившемся режиме, температуре, калибровке и падениях напряжения
являются заявленными предпосылками. Программа не удостоверяет прибор или
сертификат. Отсутствие измерения не заменяется seed-значением или истинным
паспортом из benchmark.

## Детерминированный диапазон Rs

Для каждой точки строится:

`Rlow = (U − ΔU) / (I + ΔI) / connection_factor`;
`Rhigh = (U + ΔU) / (I − ΔI) / connection_factor`.

Пересечение всех диапазонов должно быть положительным, конечным и непустым.
Номинал — середина пересечения. Относительная ширина
`(Rhigh − Rlow)/Rnom` не выше `maximum_relative_interval_width` (по умолчанию
0.0001, максимально 0.01). Слишком слабая/противоречивая опора отклоняется до
подбора. Никакого обучения этих пределов по hold-out нет.

В примере токи 0.5/1/1.5 A, напряжения 1.85/3.7/5.55 V, заявленные погрешности
10 µV и 1 µA. Получается примерно **3.699990867…3.700009133 Ω**, ширина 4.94 ppm.
Это авторский высокоточный синтетический профиль, а не утверждение о достижимой
точности обычного производственного измерения или точности Rs из паспорта OEM.
Менее точные реальные данные требуют отдельной приёмки и могут получить отказ.

Диапазон — условное множество допустимых сопротивлений при заданных границах
ошибок. Он **не** является статистическим доверительным интервалом. Ненулевые
погрешности иных каналов и корреляции ошибок этим вычислением не оцениваются.

## Три условных подбора и выдача паспорта

Для nominal/lower/upper создаются отдельные копии исходного аудита. В каждой
Rs фиксируется по опоре и исключается из списка неизвестных; остальные
параметры подбираются с прежних seed. Наблюдения, в том числе hold-out, не
меняются. Все три случая проходят исходные условия сходимости/разрешимости,
условного fit и свободного raw-replay. Если после исключения Rs неизвестных
электрических параметров не остаётся, данная постановка отклоняется.

Для успеха нужны все три завершённых положительных результата. Завершившийся
отказ любого одного значения уже доказывает отказ общего контракта: оставшиеся
значения не рассчитываются, `skipped_cases` перечисляет пропуски,
`completed: true` означает завершённое решение об отказе, а
`bracket_completed: false` — неполный набор проб. Ресурсный обрыв без такого
завершённого отрицательного свидетельства остаётся `completed: false`.

Только общий успех разрешает **номинальный** `passport.json` в корне. Условные
кандидаты концов сохраняются в `result.json`, без отдельных одобренных файлов
паспортов. Три успешных значения не доказывают прохождение всех критериев на
непрерывном диапазоне и не дают автоматической гарантии потерь любой сети;
`continuous_interval_verified: false` сохраняется явно.

`maximum_total_rhs_evaluations` (по умолчанию 10 млн, максимум 30 млн) разделён
между всеми аудитами; каждый дополнительно ограничен собственным бюджетом B17.
В счётчик входят отброшенные численные шаги и все raw-replay.
`maximum_total_wall_s` (360 s, максимум 1800 s) проверяется кооперативно перед
подборами и через их внутренние RHS-лимиты. Это не жёсткий ОС-таймаут всей
публикации; для внешних ограничений используйте campaign worker.

Артефакт содержит исходный протокол/измерение, диапазон, три фактических входа,
входы после явной обработки скорости, кандидаты, raw-критерии, графики и
манифесты. Отчёт показывает исходные DC-числа и предпосылки. Хеши контролируют
целостность, не подтверждают внешнего автора. Для переноса доступны стандартные
`study_artifacts.export_zip`/`extract_zip`.

В `campaign` добавлен `kind: anchored_dynamic_identification`. Worker выполняет
три аудита последовательно внутри своего процесса. Приёмка проверяет общий
успех, полный набор nominal/lower/upper, вычисленный DC-диапазон и согласованность
суммарного RHS. Противоречивые флаги или три копии одного nominal не проходят.
Вложенная/корневая выдача паспорта происходит только при успехе всего контракта.

## Воспроизводимая независимая приёмка

```sh
OPENBLAS_NUM_THREADS=1 PYTHONPATH=.:/path/to/pinned-motulator \
python -m benchmarks.anchored_identification_acceptance \
  --wheel /path/to/motulator-0.19.0-py3-none-any.whl \
  --out /tmp/new-anchor-acceptance
python -m pytest tests/test_stator_resistance_anchor.py
```

До первого подбора сохраняются оригинальный аудит, новые DC-точки, все
пределы и отрицательные входы. Исходные пусковые наблюдения — закреплённый
корпус motulator B19 с авторским шумом напряжения 0.01 V. DC-точки получены
из опубликованной константы Rs по закону Ома, без вызова основного winding RHS.
Они помечены authored/synthetic, не натурными и не проверенным OEM-измерением.

Старый unanchored протокол и новый anchored проверяются отдельно. Три
условных паспорта сравниваются с заново выполненным истинным motulator/MNA
при прежних допусках B15, включая 0.5 W потерь. Параметрический критерий 0.02
не изменяется. Диагностика при одинаковом паспорте изолирует численную ошибку.
Ошибочная DC-опора (+20% U) должна получить физический отказ без паспорта;
противоречивые DC-точки — отказ до решателя. Также проверяются ZIP, исполнение
в изолированном worker и точное продолжение успешного результата.

Исходный сценарий без DC-информации остаётся непройденным. Успех нового
условного протокола нельзя переносить на него, на любые DC-погрешности,
неизвестную температуру, AC/DC-различие сопротивления или произвольные сети.
Самостоятельное оборудование, GitHub и CI для этой локальной приёмки не нужны.

## Итог приёмки 8 ноября 2026

`reports/anchored-identification-qualified-2026-11-08/summary.json` принят.
Исходный unanchored raw-fit по-прежнему проходит, а его перенос потерь — нет:
stator/rotor 0.7962/0.7757 W при пределе 0.5 W. При одинаковом найденном
паспорте разные сетевые реализации расходятся по потерям лишь на 5.23e-6 W;
sample_rk4 и ужесточённый DOP853 расходятся по току на 3.56e-8 A. Это
подтверждает границу оценки параметров, а не ошибку численного forward.

Новый условный протокол требует опубликованной дополнительной DC-опоры.
При nominal/lower/upper статора потери расходятся на 0.0497/0.0680/0.0609 W,
ротора — 0.0661/0.0878/0.0653 W. Все три сравнения проходят прежние критерии.

Ошибка остальных параметров не обязана монотонно уменьшаться после добавления

с точным продолжением успешного результата проверены.
