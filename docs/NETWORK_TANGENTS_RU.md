# NA-11: прямые сетевые касательные и произведение J·v

## Что реализовано

NA-09 убрал полную плотную сборку якобиана, но оставил плотную матрицу
чувствительности между портами машин. NA-11 добавляет точное решение
`Y dV = sum(y_port dE_port)` непосредственно через текущую сетевую LU.
Временные сетевые RHS ограничены восемью столбцами. Инъекции устройств на
одном узле суммируются, включая совместное расположение генератора и двигателей.
Никакие ненулевые элементы не отбрасываются и топологическая разреженность
редуцированного якобиана не предполагается.

Явный входной режим:

```json
{"jacobian_format": "csc", "jacobian_network": "direct_solve"}
```

Параметры входят в `induction` или `coupled`. По умолчанию остаётся
`cached_ports`; это поле исключается из канонической сериализации, сохраняя
прежние StudySpec SHA-256. `direct_solve` требует CSC. Если аналитический
профиль не поддерживается, расчёт явно отклоняется с
`direct_network_tangent_requires_analytic_profile`, без скрытого перехода к FD.
Отчёт содержит `integration.jacobian_network_response`.

Двигатель, GENCLS, GENROU/TGOV1/SEXS, PSS, ESST1A, PI OEL, UEL, тепловые
защиты и поддерживаемые OEL2C получают прямые сетевые производные в CSC-пути.
Уравнения физических моделей и гибридные правила не меняются.
При поиске загруженного начального режима двигателя CSC собирается тем же
прямым маршрутом. Для проверки локальной устойчивости только активный
динамический блок преобразуется в dense и вычисляются собственные значения;
портовая матрица при этом не создаётся. Эта отдельная ограниченная спектральная
операция не является matrix-free и сохраняет прежний критерий устойчивости.

## API без сборки якобиана

```python
from power_grid_env.jacobian_product import product
jv = product(model.integration_jacobian(), time, state, vector)
jv_many = product(model.integration_jacobian(), time, state, vectors)
```

Вектор имеет форму `(n,)`, матрица направлений `(n, k)`. Результат имеет ту же
форму. Направления обрабатываются блоками не более восьми; полная identity,
матрица портовых связей и полный якобиан не создаются. Входы не изменяются.
Внешний callback без `jacobian_actions` явно отклоняется: dense/FD fallback нет.
Произведение использует текущий дискретный режим; контекст получается заново
при каждом вызове. Сохранённого оператора со старой топологией здесь нет.

Производные относятся к текущим непрерывным уравнениям и выбранным ветвям
ограничителей. В точках переключения сохраняется принятая политика наклонов;
производные скачков, saltation и градиенты сквозь события не заявляются.

## Проверки и воспроизведение

```bash
python -m pytest tests/test_network_tangents.py -q
python -m benchmarks.network_tangent_validation --out /tmp/pge-network-tangents
python -m benchmarks.network_tangent_native_validation --root /tmp/pge-native --out /tmp/pge-network-tangent-native
```

Алгоритмический протокол: 15 сценариев, два повторения, два маршрута в отдельных
процессах (60 интегрирований и 30 отдельных сравнений). Сохраняются все каналы,
стороны событий, последовательности команд, исходы и физические балансы.
Дискретные каналы сравниваются без допуска. Прямой worker запрещает вызов
`port_response`, поэтому положительный отчёт подтверждает фактический маршрут.

Нативный протокол: четыре физических входа NA-10, включая 6-секундный сценарий
и тепловое отключение с блокировкой включения; меняется только явная численная
политика `jacobian_network`. Сохраняется отображение старых/новых SHA-256.
По два нативных расчёта на вход (1e-12, 1e-13), отдельные производственные
процессы и процессы сравнения. Все восемь PSS и ограничители остаются в контуре.
UEL — независимый SI circle/lag, а не нативный MNLEX2 FMU; это не полный stock
сетевой решатель Dynawo/OpenIPSL. Зависимости закреплены прежними hash-locks.

Отдельно измеряются алгебраические производные на `(2000 узлов, 400 портов)`
и `(20000 узлов, 2000 портов)`, два повторения, отдельные процессы для обоих
маршрутов. Эти синтетические линейные схемы не являются динамической
квалификацией тысяч машин. Память учитывает построение портовой матрицы;
выгода прямого пути при её первом построении не означает общего выигрыша
скорости: кешированный маршрут может быстрее обслуживать повторные вызовы.

Текущие свидетельства:

- `reports/na11-qualified-v2-2026-11-05/{protocol,summary}.json`;
- `reports/na11-native-v2-2026-11-05/{protocol,summary}.json`;
- `reports/na11-final-2026-11-05/delivery.json`.

Первый алгоритмический запуск `reports/na11-qualified-2026-11-05` сохранён
как отрицательный: проверка обнаружила скрытое построение портовой матрицы
в инициализации загруженного двигателя. Оно исправлено без изменения физических
входов. Первый нативный запуск относится к прежнему производителю; новые
отчёты v2 повторяют всю матрицу для исправленного кода.

Квалификация существует только при `passed: true` и совпадении производителя,
входов и закреплённых эталонов. Рабочие и отрицательные отчёты не повышают статус.
Workflow `.github/workflows/network-tangents.yml` подготовлен; состоявшийся
удалённый запуск проверяется отдельно.

## Границы и следующий этап

Radau по-прежнему получает CSC и использует SuperLU. Итоговая матрица может
оставаться плотной по числу ненулевых. Это не matrix-free интегратор и не общий
DAE-решатель. Размеры полных динамических моделей остаются ограничены текущими
паспортами и квалифицированными случаями; API не снимает эти ограничения.
Память LU также зависит от заполнения. Пользовательские вход/выход `(n, k)`
сами требуют O(n k) памяти, даже при ограниченных временных блоках.

Следующий этап NA-12: индекс-1 DAE residual, согласованная инициализация,
блочный Newton/Schur и предобуславливание, затем интегрирование и независимые
траектории с возмущениями. Подписанный независимый release-host EX-04 остаётся
отдельным условием промышленной поставки.
