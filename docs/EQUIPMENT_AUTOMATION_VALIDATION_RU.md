# Блоки 6–8: обмоточная физика, сетевая автоматика и внешняя проверка

Это расширение объявленных профилей, а не завершение всех семейств оборудования
и не подтверждение универсального промышленного моделера.

## Блок 6 — связанная полная обмоточная модель

`StudySpec(study="flux_network", backend="scipy", flux_network=...)` связывает
насыщенную Γ-модель двигателя с физической RL-сетью в мгновенных SI αβ-координатах.
Состояния — токи всех обмоток, токи индуктивных ветвей, механическая скорость
и, при включении теплового паспорта, две температуры. Динамика статора сохранена.
Напряжения определяются из производной KCL; исходный KCL отдельно контролируется.
Искусственных ёмкостей и заземляющих проводимостей нет.

Поддержаны монотонное насыщение, 1–4 пассивные клетки ротора, температурные
сопротивления, медные потери, теплообмен статора/ротора/среды, вентиляторная и
вязкая нагрузка. Контролируется полный баланс магнитной, индуктивной,
механической и тепловой энергии с учётом источников и потерь.

Паспорт требует происхождение электрических, магнитных, механических и
используемых тепловых параметров. Опубликованные электрические параметры
[насыщенной машины Aalto](https://aalto-electric-drives.github.io/motulator/drive_examples/current_vector/plot_2kw_im_sat_cvc.html)
не превращают авторские теплоёмкости или дополнительные клетки в измеренные данные.
Многоклеточная схема — дискретная RL-аппроксимация, а не непрерывная модель
вытеснения тока. Потери в стали пока не реализованы в этом профиле.

Сеть: симметричные RL-линии, индуктивные constant-Z нагрузки, линейные
двухобмоточные трансформаторы с коэффициентом трансформации/группой/ответвлениями,
1–8 источников и ступени их напряжения. Ограничения входа: до 64 узлов,
128 индуктивных ветвей, 16 двигателей, 512 состояний и 5 с.
Это защитные пределы API, а не измеренная квалификация всех сочетаний размеров.
Ёмкости, несимметрия, дуга выключателя, генераторы и преобразователи этого
обмоточного профиля явно отклоняются. При превышении бюджета расчёт завершается
с диагностикой. Величина `current_amplitude_rms_equivalent_a` — амплитуда
пространственного вектора / √2, не скользящее RMS переходного сигнала.

Независимые проверки:

- Исходные электромагнитные и механические RHS motulator 0.19.0, отдельные
  потокосцепленные координаты, DOP853 против нашего Radau: насыщенный и линейный
  пуск, заторможенный ротор, провал питания с тепловой обратной связью.
- Точное решение расширенной линейной системы через матричную экспоненту:
  RL-фидер, заторможенный ротор, одна, две и четыре клетки.
- Сетевые проверки KCL и полной энергии на радиальной/кольцевой схеме с двумя
  двигателями; непрерывность состояний при ступенях напряжения.
- Проверка пересчёта сопротивления трансформатора при различающихся паспортных
  напряжениях и номиналах шин; отдельное сравнение с OpenDSS.

Нативная сверка насыщения пока одноузловая и одноклеточная. Нелинейная кольцевая
сеть проверяется инвариантами, но ещё не независимым сетевым transient-решателем.

## Блок 7 — RMS-автоматика и физическое изменение топологии

Опциональное поле `coupled.network_automation` добавляет:

- Выключатели линий, генераторов и внешнего источника: раздельные команда,
  задержка, фактическое положение и отказ. Подтверждение отказа по реальному
  току и положению, резервное отключение, ограниченное число попыток АПВ.
- МТЗ с definite-time или IEC inverse-time, минимальная направленная мощность,
  порог достоверности напряжения, гистерезис и сброс накопления. Потеря измерения
  блокирует решение; достоверность выводится отдельно от величины измерения.
- Односторонний АВР: выдержка по провалу первичного питания, проверка реального
  отключения основного ввода, пауза, проверка резерва и взаимная блокировка.
- Проверка синхронизма в момент фактического включения: напряжения, угол,
  частоты и допустимые параметры входящего источника. Неизвестная частота
  запрещает синхронизацию двух живых частей. Включение на обесточенную сторону
  разрешается только паспортом и при допустимом входящем питании.
- Остров с генератором/остаточным потоком двигателя; пассивная необусловленная
  часть имеет нулевое напряжение без добавления физического шунта.
- Ручное отключение подавляет уже поставленное в очередь автоматическое
  включение. При совпадении событий отключения обрабатываются раньше включений.

Поддержанный профиль: симметричная RMS-сеть, Radau, cached_ports,
`coincident_roots_v1`. Якобиан расширенной системы сейчас вычисляется численно;
совместная квалификация этой автоматики с DAE/аналитическим якобианом не заявлена.
Начальная схема должна быть связана с внешним источником; острова образуются
в ходе расчёта. Генератор резерва можно инициализировать отключённым при Pg=0.

Независимый эталон отдельно решает физические SI-уравнения двух узлов и
уравнения качаний GENCLS. Начальный режим ищется без вызова нашей инициализации.
Времена МТЗ/выключателей заданы протоколом заранее; нижняя аналитическая оценка
тока подтверждает непрерывное превышение уставки при любом угле ротора.
Проверены остров/воссоединение, МТЗ, отказ/резервное отключение, подавление АПВ
ручной командой, потеря измерения. Дополнительные регрессии проверяют АВР,
неисправность основного ввода, частотную блокировку и порядок оборудования.
Это не сертификация конкретного терминала защит.

## Блок 8 — воспроизведение и оставшийся EX-04

`requirements/motulator-reference.lock` фиксирует исходное колесо по SHA-256.
Проверяются версия и байты импортируемых Python-исходников относительно колеса.
Эталон запускается раньше основного решателя и не получает его траекторию.
Протокол фиксирует входы и допуски до расчёта; сырые траектории, сравнения,
отпечаток пакета и хеши артефактов сохраняются. Отсутствующие каналы,
нечисловые значения и лишние защитные действия не допускаются.

```bash
python -m pip install --require-hashes -r requirements/pilot-linux-py312.lock
python -m pip install --require-hashes -r requirements/ex02-andes-linux-py312.lock
python -m pip download --no-deps --only-binary=:all: --require-hashes \
  -r requirements/motulator-reference.lock --dest /tmp/pge-independent-wheels
python -m pip install --no-deps --require-hashes -r requirements/motulator-reference.lock
export PGE_MOTULATOR_WHEEL=/tmp/pge-independent-wheels/motulator-0.19.0-py3-none-any.whl
export OPENBLAS_NUM_THREADS=1
python -m benchmarks.extended_equipment_validation --out /tmp/pge-equipment-reference \
  --wheel "$PGE_MOTULATOR_WHEEL"
python -m benchmarks.network_automation_reference --out /tmp/pge-automation-reference
python -m benchmarks.ex04_preflight --source . --out /tmp/pge-ex04-preflight.json
```

Каталоги результатов должны быть новыми. Workflow
`.github/workflows/equipment-automation-reference.yml` сохраняет сырые результаты,
JUnit и исходное колесо с лицензией. Новые тесты входят в обязательный release
профиль; отсутствие нативной зависимости не может открыть квалификацию пропуском.

`ex04_preflight` только читает Git/CLI/API: не создаёт коммит, не публикует
ветку и не запускает workflow. Даже готовый preflight не является доказательством
внешнего прогона. EX-04 требует опубликованного точного коммита, реально
выполненного hosted workflow и проверки подписанного происхождения через
существующий `benchmarks.release_remote`. Локальный повтор этого не заменяет.

## Следующая очередь

Связать насыщенные многоклеточные/тепловые сети с независимым transient-эталоном;
добавить подтверждённые потери в стали и идентификацию клеток; расширить
семейства машин/регуляторов по источникам; проверить совместную работу автоматики
с DAE и большим числом островов; расширить несимметричные КЗ/последовательности.
Публикация и фактическое выполнение EX-04 остаются отдельным обязательным шагом.

Готовые входы CLI находятся в `cases/studies/flux-saturated_dol.json`,
`flux-thermal_sag.json`, `flux-exact_two_cages.json`,
`automation-matched_island.json`, `automation-breaker_failure.json`.
Например:

```bash
python -m power_grid_env.cli run-study cases/studies/flux-thermal_sag.json \
  --isolate --wall-timeout 60 --out /tmp/flux-thermal-report.json
python -m power_grid_env.cli run-study cases/studies/automation-breaker_failure.json \
  --isolate --wall-timeout 60 --out /tmp/automation-report.json
```

Отдельные схемы входов: `flux-network.schema.json` и
`network-automation.schema.json`; они выгружаются общей командой schema.
