# NA-06: непрерывный сетевой якобиан OEL2C

Добавлен `piecewise_analytic_OEL2C_network_reduction` для одного OEL2C в совместимой
сети GENROU/SEXS. Остальные машины могут использовать прежние поддержанные модели,
PSS MODE=1, ESST1A, абсолютный PI takeover; поддерживаются MNLEX2, motor cages,
статорная и роторная тепловые реплики. Допустимость физической комбинации по-прежнему
проверяет исходная схема входных данных. Уравнения RHS, пороги, параметры сценариев,
правила сбросов и clocks не менялись.

## Восемь строк и сетевые связи

Производные включают измеритель `abs(Ifd)/Irated`, интегратор перегрузки,
интегратор опорного тока, фильтр уставки, PID integral, derivative memory и обе
ступени limited lead-lag. Полная производная Ifd учитывает сетевую редукцию,
положение ротора, насыщение и токи остальных машин. Для `abs` при нуле принят
нулевой обобщённый наклон. Для clip принят нулевой внешний наклон на точной границе.

Anti-windup PID дифференцируется вместе с разностью ограниченного и свободного
выходов. Производные lead-lag учитывают оба собственных ограничителя. Выход OEL2C
поступает в SEXS с тем же знаком, что в существующем RHS. Sw1-полиномиальный ramp
учитывается только при активной непрерывной ветви.

Контекст таймеров читается, но не изменяется вызовом якобиана. Активные `timer_bound`
и `reference_bound` зануляют целую соответствующую строку. У заблокированной строки
не вычисляется скрытая дробно-степенная сингулярность. Если свободная активная
производная степени при нуле бесконечна либо степень невещественна, возвращается
явная ошибка: скрытого повторного решения с FD нет.

Это якобиан непрерывного RHS текущей топологии и текущего clock/active set.
Производные моментов событий, reset maps и saltation matrices не заявляются.

## Сохранённый отрицательный пример и граница маршрутизации

Первый строгий прогон всех 65 исходных профилей остановился на `cold__two_limiters`:
аналитический и FD пути дали одинаковые 14 переходов, но два независимых события
разных машин поменялись местами около t=1/6 s. Расхождение часов порядка 1e-13 s.
Строгий контракт требует той же последовательности и сторон событий; этот результат
сохранён как отрицательный, а не превращён в успешный сортировкой или интерполяцией.
Артефакты: `reports/na06-qualified-2026-11-05/` (исторический producer первого прогона).

Автоматический выбор нового якобиана поэтому ограничен **одним OEL2C**. Все восемь
исходных профилей с несколькими OEL2C явно исключены из положительного траекторного
корпуса и сохраняют FD. Для них отдельно проверяются полные координатные производные
непрерывных уравнений; это не квалификация гибридных траекторий.

Исключения: cold two_limiters/four_machines, loaded two_limiters, active two_limiters/
mixed_modes, regulating two_regulators/mixed_modes, selected two_selected.
Следующая работа для снятия ограничения — отдельный контракт пакетирования
совпадающих событий и проверка независимости/коммутативности переходов. Просто
увеличивать допуски или скрывать промежуточные стороны событий нельзя.

## Проверка и воспроизведение

Положительный алгоритмический протокол: 57 неизменённых single-OEL профилей пяти
семейств (cold startup, loaded inactive, active limited, current regulating,
selected stationary). Два повтора, два свежих процесса на пару: 114 сравнений,
228 процессов. Пределы прежние: 2e-5 состояния, 100 W/var мощности, 1 µs часы,
1e-8 баланс. Проверяются также имя перехода OEL2C и булево значение ветви.
Same-RHS analytic/FD является алгоритмической, а не независимой физической проверкой.

Нативный протокол: десять профилей, по два допуска (1e-12, 1e-13), двадцать свежих
FMU-процессов. Используются закреплённый Dynawo-derived OEL2C с **явно именованными**
cap-guard-v1/equilibrium-guard-v2, MSL 3.2.3 и независимая физическая SI-сеть.
Это не целиком stock Dynawo network и не сертификация каждого внутреннего clock.
Проверки включают cold inverse ramp/field trip, UEL coordination, zero enable delay,
active release/authority, current regulation/scaling и selected timer/voltage cases.
Собственная лаборатория для этих воспроизводимых проверок не нужна.

```bash
OPENBLAS_NUM_THREADS=1 python -m pytest tests/test_oel2c_jacobian.py -q
OPENBLAS_NUM_THREADS=1 python -m benchmarks.oel2c_jacobian_validation --out reports/na06-algorithm
python -m benchmarks.modelica_reference_setup --root /tmp/pge-oel-native --fetch
python -m benchmarks.dynawo_reference_setup --root /tmp/pge-oel-native --fetch
OPENBLAS_NUM_THREADS=1 python -m benchmarks.oel2c_jacobian_native_validation --root /tmp/pge-oel-native --out reports/na06-native
```

CI закрепляет runtime/test dependencies по hashes, actions по commit SHA, права —
read-only. Нативный job запускается явно через workflow_dispatch. Результат конкретной
версии устанавливается по её `summary.json` и fingerprint, не наличием этого документа.
Промышленный release и независимый подписанный хост EX-04 остаются отдельными воротами.
Крупномасштабная эффективность и произвольные конфигурации из этих опытов не следуют.

Грубый native-прогон `reports/na06-native-2026-11-05/` сохранён как отрицательный: для regulating voltage-up при 1e-10 начало enable timer отличалось примерно на 24 µs. При 1e-12 исходный критерий 1 µs прошёл; окончательный протокол использует 1e-12 и 1e-13 без изменения primary или порогов. Изменение native-протокола меняет inventory benchmark-кода, поэтому окончательный алгоритмический корпус запускается заново в `reports/na06-qualified-v3-2026-11-05/`; промежуточный v2 не является итоговой квалификацией.
