# OEL2C: выбор стационарной ветви и явная нейтральная память

Дата: 2026-11-03. Продолжение EX-01 после [токового регулирующего равновесия](OEL2C_CURRENT_REGULATION_RU.md).

## Назначение

`selected_equilibrium` решает алгебраические условия стационарности восьми состояний OEL2C при фактическом начальном токе совместной загруженной PV-сети. Выбираются холодная/горячая ветвь, состояние теплового таймера, токовая уставка, часы и anti-windup PID. Поддерживаются нулевой ramp, промежуточная тепловая зона, касание предела таймера со свободной производной ноль, нулевая ошибка PID и граничные выходы PID/lead-lag.

В стационарной системе могут оставаться свободные координаты. При `ramp=0` токовая уставка не восстанавливается из уравнений: требуется `equilibrium_reference_current_pu`. При ошибке PID в пределах `1e-10 pu` требуется `equilibrium_pid_output_pu`. Это физически существенная начальная память: разные её значения могут давать разные выходы регулятора при одной сетевой точке. Алгоритм её не угадывает. Отсутствие памяти, противоречие направлению ramp/anti-windup или выход за пределы завершаются отказом без частично успешной траектории.

При положительном ramp выбирается верхний предел уставки, при отрицательном — нижний. При ненулевой ошибке PID выбирается соответствующий предел выхода и решается уравнение anti-windup. Оба lead-lag и память производной инициализируются из своих стационарных уравнений. Удерживаемая координата должна иметь направленную наружу либо нулевую свободную производную. Часы активной ветви имеют явно заданную выдержанную предысторию; неактивные часы не запускаются.

## Явная политика и границы устойчивости

```json
{
  "generator_id": "g2",
  "model": "OEL2C_Dynawo_equilibrium_guard_v2_SEXS_summation",
  "rated_field_reaction_pu": 1.5,
  "initialization": "selected_equilibrium",
  "avr_reference_initialization": "derive_from_operating_point_with_OEL",
  "equilibrium_stability_policy": "stationarity_only",
  "Kru": 0,
  "equilibrium_reference_current_pu": 1.4
}
```

Политика `stationarity_only` обязательна и не является значением по умолчанию. В этом режиме не заявляется полная устойчивость OEL. Обычная проверка машин и их регуляторов сохраняется, но `operating_point.full_OEL_stability_qualified=false`, а `stationary_stability_scope` прямо ограничивает её объём. Нейтральная память и точки излома ограничителей требуют отдельного анализа гибридной устойчивости; обычный гладкий спектр не заменяет такой анализ. Прежний `current_regulating_equilibrium` сохраняет свою более строгую проверку условного замкнутого контура.

PV-задания начальной сети сохраняются. Вход AVR выводится из решённой точки и фактического воздействия OEL по явно выбранной политике; это записывается в `oel2c_AVR_reference_initialization`. Для неизменяемого заданного входа AVR и решения напряжения по токовому ограничению нужно использовать отдельный `current_regulating_equilibrium`.

`operating_point.oel2c_selected_equilibrium` содержит для каждого OEL выбранные активные ограничения, свободные производные, наличие нейтральной памяти, выходы и максимум исходных производных. Все восемь производных проверяются до `1e-8 1/с`. Аудит сериализуется в обычный JSON, включая изолированный worker.

## Примеры и независимая проверка

```bash
python -m power_grid_env.cli run-study cases/studies/generator_oel2c_selected_deadband_memory.json --out reports/selected.json
PGE_DYNAWO_REFERENCE_ROOT=/tmp/pge-reference-ex01 python -m pytest tests/test_oel2c_selected.py
python -m benchmarks.generator_oel2c_selected_validation --root /tmp/pge-reference-ex01 --out reports/oel2c-selected
```

Эталон отдельно решает SI-сеть, отдельно строит начальные алгебраические состояния и исполняет нативный Modelica OEL2C через FMI/CVODE. Производственный selector, восстановление поля, инициализатор и RHS эталоном не используются; это дополнительно проверяется запретом вызовов. При удержании пределов native LimIntegrator используется прежний явно объявленный выбор внешней ветви одним ULP; внутренние уставки этим не сдвигаются. Версия уравнений — уже объявленный equilibrium-guard-v2, без новых поправок физики. Адаптированные стационарные формы в `power_grid_env/oel2c_stationary.py` сохраняют MPL-2.0; файл и текст лицензии включены в wheel.

Корпус из 16 случаев включает обычные неактивную/активную точки, нулевой ramp с верхней и внутренней уставкой, горячую память, промежуточную тепловую зону, оба касания таймера, нулевую ошибку с нулевым/нижним/внутренним PID и downstream-ограничением, шаги AVR в обе стороны, провал напряжения с достижением верхнего предела таймера при сохранении заданной токовой уставки и два OEL. Нейтральная уставка `0.7307761564612826 pu` зафиксирована из самостоятельного SI-расчёта объявленной PV-схемы, при неизменной нормировке поля `1.5`; это вход начальной памяти, а не подгонка переходной характеристики.

Каждый случай сверяется при трёх нативных допусках `1e-8/1e-10/1e-12`; критерии сравнения каналов, комплексных узловых напряжений и физических событий сохраняются от предыдущего OEL2C-корпуса. Дополнительно проверяются идентичность выбранной пользователем памяти и начальная политика AVR. Десять отрицательных задач проверяют обязательные политики, отсутствующую/противоречивую память, неверные пределы и отсутствие загруженной точки.

## Что остаётся в EX-01

Этот блок расширяет множество допустимых стационарных точек. EX-01 остаётся открытым до отдельной сверки совпадений нескольких переключающих поверхностей и правил выбора их начального режима. Общая устойчивость граничных гибридных режимов этим блоком не доказывается и относится к дальнейшему анализу взаимодействий. Приёмка тока за весь переходный процесс, takeover AVR и совместная OEL/UEL/PSS/fault-матрица остаются следующими задачами. Нативная сверка относится к компоненту в независимой SI-сети, а не к целой штатной сети Dynawo. Успешное численное воспроизведение не является приёмкой тока за весь интервал: в случае провала напряжения ток превышает тепловую уставку, что сохраняется в диагностике.
