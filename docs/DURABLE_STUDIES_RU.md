# Воспроизводимые исследования и длительный QSTS

## Реализовано

Общий `StudySpec` запускает `power_flow/opendss` и `qsts/opendss`.
PF возвращает фазные напряжения, токи и мощности терминалов, острова,
отпайки, диагностику и версии backend. Наличие результата отделено от
успешного завершения: численная несходимость возвращает ненулевой код CLI.

QSTS использует production `Engine`, независимые P/Q profiles и его модели
событий/устройств. В этой поставке runner исполняет политику **hold**, а не
произвольный внешний контроллер. Он доходит до конца горизонта, не прекращая
study при достижении цели восстановления. Специальные SolveOptions для QSTS
пока отклоняются: выбор опций решателя принадлежит event engine.

Каждый интервал записывается в `intervals.jsonl`: инженерный trace, полные
результаты solve без DSS script и execution events. Это **привилегированный**
журнал; его нельзя передавать AI-контроллеру как публичное наблюдение.

В памяти сохраняются два trace-интервала, последняя команда, последние
доступные измерения и ещё не доставленные измерения. Последние ограничены
задержками и sampling из сценария. Интегралы сохраняются независимо от trace.
Объём дискового журнала растёт с длительностью и количеством каналов;
автоматические дисковые квоты и Parquet-компрессия ещё не реализованы.

## Запуск

Из checkout:

```bash
python -m power_grid_env.cli run-study cases/studies/qsts_runtime.json \
  --out /tmp/pge-study --max-steps 2
python -m power_grid_env.cli run-study cases/studies/qsts_runtime.json \
  --out /tmp/pge-study --resume
```

`--out` — каталог для QSTS, файл JSON для PF.
`--max-steps` ограничивает число интервалов текущего вызова, не всего study.
`--checkpoint-every` задаёт период checkpoint в интервалах (по умолчанию 96).
Для отмены передайте `--cancel-file /tmp/pge.cancel` и создайте этот файл.
Проверка отмены происходит между интервалами. Удалите файл перед продолжением.

Коды завершения: `0` — завершённый успешный расчёт; `2` — отклонение/ошибка;
`3` — пауза или отмена с сохранением checkpoint. Физические нарушения
напряжения/перегрузки отражаются в результатах и интегралах; успешное
вычисление не означает отсутствия инженерных нарушений.

`python -m power_grid_env.cli schemas --out /tmp/pge-schemas` экспортирует
в том числе `study.schema.json`.

## Checkpoint и восстановление

Checkpoint содержит состояние Engine, число интервалов, hashes study/кода,
длину и SHA-256 закоммиченного префикса журнала, собственную checksum.
Сначала fsync журнала, затем атомарная замена checkpoint и fsync файла/каталога
на поддержанной Linux filesystem. Пауза/отмена также фиксируют checkpoint.

Resume проверяет совместимость study/кода и checksum, затем отбрасывает
только незакоммиченный хвост. Изменённые строки закоммиченной части или
повреждённое состояние отклоняются. Контрольные суммы защищают от повреждения,
а не от злоумышленника, способного переписать bundle вместе с hashes.

Один каталог имеет одного писателя: `.lock` создаётся эксклюзивно.
После принудительного завершения процесса lock может остаться. Удалять его
можно только убедившись, что предыдущий писатель остановлен. Автоматического
«перехвата» активного каталога нет. Новая попытка не перезаписывает чужой run.
При ошибке открытия CLI сохраняет `error.json`, не заменяя успешный `result.json`.

Результаты должны воспроизводиться в том же окружении зависимостей/backend.
Текущий source fingerprint не является lockfile окружения; обновление native
библиотеки требует отдельной регрессии и повторной квалификации.

## Параллельные независимые расчёты

```python
from power_grid_env.worker_pool import SolverPool

with SolverPool(size=2, timeout_s=60) as pool:
    for result in pool.solve_many(networks, retries=1):
        inspect_result(result)
```

Пул удерживает не более `size` запросов/результатов одного batch, выдаёт их
в порядке входа и сериализует доступ к каждому worker-протоколу.
Восстановление процесса разрешено только для независимого идемпотентного
solve. Численная несходимость остаётся результатом, не подменяется повтором
или результатом другой сети. Stateful Engine пока не распределяется этим API.

## Квалификация по артефактам

```bash
python -m power_grid_env.cli qualify --profile industrial-network-studies \
  --evidence /path/to/bundle/evidence.json --out /tmp/pge-qualification
```

Индекс — список записей с `id`, `network_class`, `state`, `code_sha256`,
`equipment` и `artifacts`. Каждый artifact задаёт относительный `path` и
`sha256`. JSON артефакта содержит совпадающие id/class/code, `verdict: pass`
и измеренные `result`. Метрики берутся из артефакта, не из индекса.
Пути за пределами bundle, отсутствующие или изменённые файлы отклоняются.

NaN/Inf, bool, отрицательные error metrics, дубликаты claims, failed verdict,
устаревший код и неполные gates не открывают профиль. Dynamic/advanced профили
дополнительно требуют сетевые gates. Hash корректного JSON не доказывает
независимость reference: происхождение и scope evidence требуют квалификации.
Доступные профили остаются закрытыми без обязательных внешних результатов.

## Длительная проверка runtime

```bash
python -m benchmarks.qsts_runtime --days 30 --out /tmp/pge-30day-probe
```

Две небольшие синтетические топологии, по 2 880 интервалов на 30 суток,
раздельные P/Q profiles, полный прогон и повтор с середины. Проверяются
аналитический интеграл спроса, финальный cold solve, byte-identical journal
и ограничение retained trace/history. Модуль требует checkout с benchmarks.
Это не SMART-DS, не корпус реальных площадок и не измерение превосходства.

## Что остаётся

Общий ANDES adapter из Network, сетевой нормативный SC в полном заявленном
subset, два внешних фидера с их CSV через этот runner, дисковые квоты,
service/job API и изоляция недоверенного кода, независимые trajectories,
полевые измерения и matched comparative studies. Текущие улучшения runtime
не заменяют эту квалификацию и не открывают промышленный релиз автоматически.
