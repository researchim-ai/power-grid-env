# Проверка и полный повтор серии самозапуска

Исследование прямого пуска и самозапуска теперь имеет два разных инструмента:
проверку сохранённого пакета и новый запуск всех его кандидатов. Ни один из них
не подтверждает натурное происхождение данных или промышленную приёмку.

## Проверка сохранённого исследования

```bash
python3 -m power_grid_env.cli motor-restart-check /tmp/dol-restart-study \
  --out /tmp/dol-restart-check.json
```

Команда не запускает интегратор и не изменяет исходный каталог. Она проверяет
строгий список файлов и каталогов, хеши именно прочитанных байтов, отсутствие
ссылок/посторонних файлов, конечные числа и отсутствие дублированных JSON-ключей.
Требуется завершённая серия со всеми кандидатами, совпадающий хеш кода и
зафиксированная среда Python/ОС/зависимостей. Для исторической серии нужен
соответствующий архивный wheel и её версии зависимостей; новый код не маскируется
под старую версию исследования.

Проверяющий заново строит варианты из исходных StudySpec и протокола и сравнивает
каждый сохранённый вариант с этим определением. Затем проверяются идентичность,
каналы, дискретные значения, невязки численного результата. Из сырых результатов
повторно считаются моторные критерии, окна напряжения, отклонения от базового
варианта, диапазоны метрик и список прошедших кандидатов. Сохранённый run.json
должен совпасть с этой оценкой, включая типы данных: true не подменяется числом 1.
При изменении пакета, кода или среды во время проверки результат не принимается.

Статическая проверка подтверждает соответствие выводов сохранённым числам.
Она **не доказывает физическую подлинность траектории**: согласованно изготовленные
данные и манифест не становятся настоящими измерениями от наличия SHA-256.
Для проверки воспроизводимости самой траектории применяется полный replay.

Полностью рассчитанный набор, где ни один кандидат не прошёл критерии, является
корректным отрицательным исследованием и может пройти проверку пакета. Отменённый,
частичный или усечённый набор не проходит как завершённое исследование. Успех
команды проверки означает проверенный пакет, а не наличие разрешённых уставок.

## Полный повтор всех кандидатов

```bash
python3 -m power_grid_env.cli motor-restart-replay /tmp/dol-restart-study \
  --out /tmp/dol-restart-replay
```

Допуски `protocol.repeatability` сохраняются при создании исследования. При
отсутствии явных значений исходный протокол получает фиксированные defaults:
время 1e-6 с, pu 1e-6, угол 1e-6 рад, тепловая величина 1e-6, мощность 1 Вт/вар.
Они записываются в protocol.json и его хеш до расчёта. Параметров ослабления
допусков у replay нет; инженерные критерии отбора кандидатов остаются отдельными.

В новом каталоге создаётся независимая серия experiment/ с теми же входами и
полной повторной инициализацией каждого кандидата в прерываемом процессе.
Проверяются обе серии, все временные сетки и стороны событий, **все** каналы,
вложенные журналы событий и решения по каждому кандидату. Дискретные каналы и
счётчики сравниваются точно, углы — с приведением к периоду, остальные величины
— по своим единицам и сохранённым допускам. Сводка сохраняется в replay.json,
файлы нового пакета перечисляются в replay-manifest.json.

Изменение координаты ЭДС, не влияющей на вычисляемые по сохранённым I/U/скорости
критерии, может пройти статическую проверку этих критериев после пересчёта хешей.
Но полный повтор обнаружит расхождение ЭДС. Это специально проверяется тестом:
проверка целостности и пересчёт критериев не выдаются за повтор физической модели.

Выходной каталог должен быть новым/пустым и не пересекаться с исходным, включая
родительский или дочерний каталог. Запись JSON проверки внутрь исходного пакета
также запрещена. Исходный пакет повторно контролируется после расчёта, а
сравниваемые байты сверяются с его проверенным манифестом.

Отмена или неудача одного запуска не становится repeatable=true. Изменение
исходного пакета в ходе повтора даёт отрицательный результат. Даже совпадающие
решения по кандидатам не скрывают несовпадение отдельного канала или события.

## Ограничения и поставка

Сохраняется максимум 32 кандидата, 32 двигателя, 16 окон напряжения и общий
бюджет не более 512 МБ на исследование. StudySpec ограничен 32 МБ, отдельный
артефакт — 64 МБ; эти ограничения применяются и при создании, и при чтении.
Сводка replay ограничена 128 КБ. Полная повторная серия использует прежние
временные и дисковые квоты; её компактная сводка и манифест добавляются отдельно.
Здесь нет обещания ОС-песочницы или исполнения недоверенного пользовательского кода.

CLI проверки возвращает 0 для проверенного полного пакета и 2 при отказе.
CLI повтора возвращает 0 только для завершённого repeatable=true, 3 при отмене
или общем deadline, иначе 2. Сырые результаты нового расчёта сохраняются и при
несовпадении, чтобы причина была проверяемой.

Промышленный профиль по-прежнему не выпущен. Для него нужны целевые паспорта,
OEM-данные, откалиброванные синхронные измерения, отложенные случаи и независимая
инженерная приёмка на другой машине. Повтор синтетического примера на одном
хосте подтверждает воспроизводимость программного кандидата в этой области.

## Артефакты кандидата

Полная регрессия: **614 тестов, 0 ошибок, 0 пропусков**.
Отчёты — `reports/motor-restart-audit-2026-10-31/`: XML, независимая SI-проверка
четырёх вариантов, экспорт схем, статическая проверка серии и манифест хешей.
Два wheel совпали побайтно. Две чистые офлайн-установки прошли pip check,
OpenDSS smoke и тепловой replay. Первая установка создала полную серию, вторая
проверила её без симуляции и выполнила полный повтор всех четырёх вариантов.
Расхождения каналов в этом повторе равны нулю, события и решения совпали,
байты исходного пакета остались неизменны. Это синтетическая схема и один хост.
