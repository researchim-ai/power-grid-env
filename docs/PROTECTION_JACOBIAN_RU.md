# NA-05: производные MNLEX2 и тепловой модели ротора

Решатель `coupled_rms` выбирает `piecewise_analytic_MNLEX2_field_I2_network_reduction`
для совместимых профилей с MNLEX2 или `field_i2_replica`. Поддерживаются GENROU,
TGOV1, SEXS, ESST1A, IEEEST MODE=1, авторский droop OEL и абсолютный PI takeover OEL.
Существующие более узкие профили NA-01…NA-04 сохраняют свои идентификаторы.
Физический RHS, параметры сценариев и правила событий не изменяются.

## Производные

Круг MNLEX2 вычисляется на собственной базе машины:
`e = P² + (Q − Q0 |V|²)² − Radius² |V|⁴`.
Здесь P,Q получены из терминального комплексного напряжения и тока, включая
полную зависимость от сетевого решения, угла и потоков всех машин.
Используется производная квадрата модуля `d|V|² = 2 Re(conj(V) dV)`;
сама формула круга не требует деления на модуль напряжения.

Ограниченный выход MNLEX2 имеет нулевой внешний обобщённый наклон на обеих
точных границах. Его необрезанное состояние продолжает изменяться вне границ:
строка производной не блокируется памятью региона. Производные двух состояний
включают обратную связь washout. Для SEXS выход входит в сумматор AVR;
для ESST1A — до ограничения ошибки и выбора порта UEL2.

Тепловой уровень ротора: `dθ/dt = ((Ifd/Irated)² − θ)/T`.
Производная источника нагрева равна `2 Ifd dIfd / Irated²`: она корректна для
положительного, отрицательного и нулевого signed field reaction.
После реального срабатывания статор отключается, impressed field voltage
становится нулевым; производные обратной связи ротора и тепловой памяти
сохраняются. Производные состояний AVR и PI продолжают вычисляться по их ODE.

Это производные непрерывных уравнений при текущей топологии и дискретном
состоянии. Производные сбросов, моменты скачков PSS и saltation matrices не
вычисляются. OEL2C с его восемью состояниями и часами сохраняет FD для всего
совместного профиля. Тепловая реплика не означает OEM кривую или температуру.

## Воспроизведение

```bash
OPENBLAS_NUM_THREADS=1 python -m pytest tests/test_protection_jacobian.py -q
OPENBLAS_NUM_THREADS=1 python -m benchmarks.protection_jacobian_validation --out reports/na05-algorithm
OPENBLAS_NUM_THREADS=1 python -m benchmarks.generator_underexcitation_validation --out reports/na05-independent-si
python -m benchmarks.esst1a_reference_setup --root /tmp/pge-native --fetch
OPENBLAS_NUM_THREADS=1 python -m benchmarks.protection_jacobian_native_validation --root /tmp/pge-native --out reports/na05-native
```

Алгоритмический корпус: все 11 существующих MNLEX2-сценариев, ESST1A field trip
и UEL summation, 14 сценариев EX-02 (без `two_limiters_sensitive`). Это 27
различных физических профилей, два повтора и два отдельных процесса на пару:
54 сравнения и 108 процессов. UEL не удаляется из исходных EX-02. Допуски:
2e-5 для состояний, 100 W/var для мощности, 1 µs для времени событий,
1e-8 для балансов. Сравнение analytic/FD проверяет алгоритм, а не независимую физику.

Независимый SI-корпус MNLEX2 дополнительно проверяет непрерывность потоков,
тепловую защиту и часы сбросов. Native-корпус содержит шесть профилей ESST1A /
MNLEX2 / PI / PSS, по два допуска CVODE (1e-12, 1e-13). Он использует закреплённые
OpenIPSL и независимую SI-схему; PI и I² представлены авторскими MSL blockgraphs.
Нативное сравнение не сертифицирует каждый внутренний clock селекторов ESST1A.
Все проверки выполняются без собственного лабораторного оборудования.

CI: `.github/workflows/protection-jacobian.yml`. Успех локального корпуса не
подменяет подписанный запуск на другом хосте EX-04 и не подтверждает
произвольные масштабы, OEM-соответствие, EMT или несимметричные режимы.
Результаты каждого запуска следует читать из его `summary.json`; этот документ
описывает протокол, а не автоматически присваивает квалификацию будущим версиям.
