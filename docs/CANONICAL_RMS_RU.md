# RMS из канонической сети: первый исполняемый subset

Общий `StudySpec` теперь поддерживает `study: rms`, `backend: andes`.
Adapter строит ANDES из переданного `Network`, а не загружает фиксированный
пример Кундура. Кундур остаётся отдельной регрессией регуляторов.

## Область применения

- Одна связная симметричная сеть, включая разные уровни напряжения через поддержанные трансформаторы.
- Одна внешняя опора за явно заданным индуктивным сопротивлением источника.
- ABC-линии с симметричными циркулянтными матрицами R/X/B. Используется
  эквивалент прямой последовательности; несимметричные матрицы отклоняются.
- Двухобмоточные трансформаторы с фиксированными taps/clock и явным нулевым магничиванием.
- Симметричные постоянные PQ-нагрузки. Во временном расчёте нет скрытого
  перехода нагрузки на Z/I: соответствующие ANDES weights заданы явно.
- PV-генераторы с отдельными паспортами классических машин GENCLS.
- Фиксированная коммутация топологическими трёхфазными аппаратами.

Шунты, нейтраль, заранее заданные КЗ, моторы, converters,
спектры, omissions и динамическая коммутация switches пока отклоняются.
Отключение линии разрешено, только если сеть остаётся связной. Повторный
trip того же объекта отклоняется: ANDES Toggle иначе включил бы его обратно.

## Паспорт и единицы

`rms.machines` содержит ровно один паспорт для каждого генератора:
`generator_id`, `rated_va`, `inertia_s`, `x_d_prime_pu`, `damping_pu`.
`x_d_prime_pu` — переходная реактивность на базе rated_va и номинального
напряжения машины. Она не выводится автоматически из поля `x_d_pu` режима.
Конфликт явно заданных H в Network и паспорте отклоняется.

ANDES получает M=2H, собственную MVA-базу машины и отдельную базу системы.
Изменение системной базы не должно менять физическую траекторию.
Пределы Q проверяются в исходной рабочей точке. Без exciter GENCLS сохраняет
внутреннюю ЭДС; теперь доступны явные TGOV1/SEXS/IEEEST passports. Динамический
Q limiter всего агрегата этим не заявлен.

`duration_s` ограничена 60 с, число обычных шагов — 200 000; output budget
ограничен двумя миллионами scalar channel samples по предварительной оценке.
Это защитные ограничения текущего serial adapter, не промышленный envelope.
Resume RMS пока не реализован. Отмена и wall deadline доступны в отдельном
worker: [регулируемый RMS и исполнение](REGULATED_RMS_AND_FAULTS_RU.md).

## События

- `mechanical_step`: добавка механического момента в pu **на базе машины**.
  Adapter переводит её на системную базу перед ANDES Alter.
- `load_scale`: множитель текущих P и Q нагрузки. Изменяются Ppf/Qpf,
  которые действительно используются в TDS, а не только исходные p0/q0.
- `generator_trip`: отключение соответствующей GENCLS.
- `line_trip`: отключение линии при сохранении связности сети.

События лежат строго внутри горизонта. Вывод содержит фактические timestamps,
в том числе точки непосредственно перед/после события. Их порядок проверяется.
Ширина event bracket уменьшается с квадратом шага; после инициализации
перестраивается весь switch schedule, а не дописываются новые времена к старым.
Это проверено для используемого ANDES 2.0.0; при обновлении нужна регрессия.

## Запуск и результат

```bash
pip install -e '.[rms]'
python -m power_grid_env.cli run-study cases/studies/rms_classical.json \
  --out /tmp/rms-result.json
python -m benchmarks.rms_mapping cases/studies/rms_classical.json \
  --out /tmp/rms-reference
```

Второй пример требует checkout с benchmarks; первый работает с установленным
пакетом и явно переданным файлом study. Для wheel должен быть установлен RMS extra.

Результат содержит mapping стабильных canonical IDs в ANDES IDs, PF
напряжения/углы, DAE init residual, фактические времена и каналы:
угол/скорость ротора, P/Q машины, механический/электрический момент, ЭДС,
напряжение/угол каждой canonical bus. Скорость выражена в pu синхронной,
P/Q — W/var, углы — rad. Сохранены паспорт, source hash и network hash.

Незавершённый горизонт, busted solver, нечисловые состояния или
неупорядоченные времена не считаются успешным study. CLI возвращает nonzero.
Неустановленный ANDES даёт `backend_unavailable`; unsupported scope
отклоняется до построения backend. `industrial_profile_qualified` и
`field_validated` остаются false.

## Что проверено

- Сохранённый JSON → общий runner → RMS result → CLI JSON.
- Рабочая точка SMIB против аналитического lossless PF.
- Полные δ/ω траектории механической ступени против независимого SciPy RK45
  и сходимость при h/h2/h4 без ослабления допусков.
- Инвариантность при изменении системной MVA-базы вдвое.
- Две машины, нагрузка и её ступень; исходный PF против отдельного PV/PQ Newton.
- Равновесие без событий, generator trip, trip параллельной линии.
- Отказы при missing passports, asymmetry, неизвестном target и islanding.

Raw numerical evidence: [RMS mapping reports](../reports/rms-mapping-2026-10-30/).
Это квалификация объявленных примеров и adapter regression, не произвольной
промышленной площадки и не upstream ANDES целиком.

## Историческое ограничение PF и его исправление

На небольшом mesh-case с двумя PV исходный OpenDSS-маршрут не сходился за
первый бюджет и оставлял reduced-load continuation. Исправлено ограниченными
PV refinements на полной нагрузке и обязательным восстановлением исходных
уставок. Теперь кейс проходит тот же PQ/KCL gate и сверку с ANDES.
Raw предыдущего аудита остаётся историей; новая регрессия — `test_pv_refinement.py`.

Поддержка двухобмоточных трансформаторов и результаты масштаба описаны в
[следующей поставке](MULTIVOLTAGE_AND_SCALE_RU.md).
