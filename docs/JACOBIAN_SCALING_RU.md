# NA-08: ограниченные сетевые RHS-блоки и точный CSC-путь Radau

## Реальные границы реализации

Исключение алгебраической сети делает динамические переменные глобально связанными.
Разреженная Y-сеть не означает разреженный reduced Jacobian. Этот блок не удаляет
малые элементы и не объявляет матрицу разреженной по структуре исходного графа.

1. Сетевые чувствительности вычисляются точными SuperLU-решениями блоками не более
   восьми Norton-портов. Временный RHS имеет размер `Nbus × min(8,Nports)`, вместо
   `Nbus × Nports`. Сохраняются только строки моторных и генераторных портов.
   Особенно это уменьшает постоянный GENCLS-cache: теперь это port×port, а не
   bus×port. Инвалидация по объекту LU при переключениях сохранена.
2. Явное `jacobian_format: csc` в `induction` или `coupled` передаёт точную CSC-копию
   аналитического якобиана в Radau, выбирая SuperLU вместо dense LU. Плотная сборка
   самого якобиана **остаётся**. Это не fully sparse assembly, DAE или matrix-free
   solver. Нулевые элементы не хранятся; все ненулевые, включая 1e-200, сохраняются.

По умолчанию остаётся `dense`. Сериализатор опускает только новое default-значение,
сохраняя прежние StudySpec hashes. Для CSC поле сохраняется в сериализованном входе
и входит в case identity. Отчёт содержит `integration.jacobian_format` и
`integration.jacobian_linear_solver`. Когда аналитический callback отсутствует,
сохраняется FD, а формат честно указывается как `finite_difference`.
Настройка относится к RMS Radau, не к отдельным small-signal или внешним FMU solvers.

CSC не гарантирует ускорения: для небольших или плотных reduced matrices накладные
расходы могут перевесить пользу. Точное представление и выбор факторизации
проверяются отдельно от wall time. Нет автоматического переключения по недоказанному
порогу размера и нет скрытого повторного решения в другом режиме после ошибки.

## Протокол

Девять физических профилей × два повтора dense/CSC: 18 сравнений, 36 свежих процессов.
Сценарии включают GENCLS thermal trip, GENROU limits, ESST1A/UEL field trips,
current-regulating OEL2C, четыре OEL2C с opt-in политикой NA-07, две сети с 512
узлами/32 моторами/4 генераторами и ESST1A-профиль на 2000 узлах/8 моторах/4 генераторах.
Исходные физические параметры и события не меняются. Проверяется прежний строгий
контракт полных каналов, сторон и последовательности событий, времени и балансов:
2e-5, 100 W/var, 1 µs, 1e-8 соответственно.

Отдельный линейный memory probe использует 2000 и 20000 неизвестных, 40 портов,
два повтора и legacy/blocked методы: восемь свежих процессов. Проверяются побитовое
равенство ответов, максимум восемь RHS-columns и меньший NumPy/tracemalloc peak.
Измеряется также current-exec VmHWM (RSS), включающий imports и factorization;
getrusage lifetime high-water mark сохраняется отдельно, поскольку может включать
пик до exec и не должен подменять измерение данного запуска. Это
**синтетическая линейная система**, не квалификация 20000-узловой динамической сети
и не доказательство любых масштабов. Tracemalloc не охватывает все внешние аллокации;
для прозрачности приводятся обе метрики.

Независимый native-корпус использует CSC primary для single current-regulating OEL
и четырёх OEL2C. Закреплённые Dynawo-derived FMU в независимой SI-сети запускаются
при 1e-12 и 1e-13, всего четыре процесса. Проверяется фактический CSC metadata.
Unit tests дополнительно перехватывают реальный `Radau.splu`, подтверждая выбор
факторизации для motor-only и coupled режимов.

```bash
OPENBLAS_NUM_THREADS=1 python -m pytest tests/test_jacobian_scaling.py -q
OPENBLAS_NUM_THREADS=1 python -m benchmarks.jacobian_scaling_validation --out reports/na08-scaling
OPENBLAS_NUM_THREADS=1 python -m benchmarks.jacobian_scaling_native_validation --root /tmp/pge-native --out reports/na08-native
```

Для native runtime действуют прежние hash-pinned setup-команды OEL2C. CI сохраняет
протокол, случаи, метрики, traces, notices и результаты тестов. Реальный результат
версии определяется `summary.json` с code/source identity, не наличием документа.

Остаются: построение якобиана без плотных промежуточных state×state массивов,
структурная/DAE формулировка для больших чисел машин, более широкие scale families
и подписанный remote release gate EX-04. Saltation и OEM/полевые утверждения из
этой численной оптимизации не следуют.

Итоговый корпус с раздельными VmHWM/lifetime полями: `reports/na08-qualified-v2-2026-11-05/`. Итоговый native-корпус с той же source identity: `reports/na08-native-v2-2026-11-05/`.
