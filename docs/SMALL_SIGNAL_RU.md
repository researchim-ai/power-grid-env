# Малосигнальная устойчивость канонической сети

Добавлен исполняемый study `small_signal` с backend `andes`. Он инициализирует
рабочую точку через тот же адаптер, что RMS, и линеаризует систему DAE:
`A = T^-1 (fx - fy gy^-1 gx)`. Алгебраические переменные исключаются;
состояния с нулевыми постоянными времени обрабатывает редукция ANDES.
Результат содержит матрицу A, имена состояний, собственные значения,
частоты, коэффициенты демпфирования и участие состояний.

## Запуск

Из корня репозитория:

```bash
python3 -m power_grid_env.cli run-study cases/studies/small_signal_genrou.json --out /tmp/modes.json --isolate --wall-timeout 30
python3 -m benchmarks.small_signal_reference --out reports/small-signal-2026-10-30
python3 -m pytest -q tests/test_small_signal.py
```

Примеры: [GENCLS](../cases/studies/small_signal_classical.json),
[GENROU](../cases/studies/small_signal_genrou.json),
[GENROU с насыщением](../cases/studies/small_signal_genrou_saturated.json).
Паспорта машин и регуляторов совпадают с [каноническим RMS](CANONICAL_RMS_RU.md).
Поддерживаются GENCLS/GENROU и существующие TGOV1/SEXS/IEEEST MODE=1.
Сохраняются ограничения balanced positive-sequence адаптера.

## Интерпретация

Собственное значение задано как `real_per_s + j*imag_rad_per_s`.
Частота равна `abs(imag)/(2*pi)`, демпфирование — `-real/abs(lambda)`;
для почти нулевой моды демпфирование не определяется.
`completed=true` означает успешный расчёт, включая случай неустойчивости.

- `asymptotically_stable_linearized`: все действительные части ниже −1e-8 с⁻¹.
- `unstable`: есть действительная часть выше 1e-8 с⁻¹.
- `marginal_or_numerically_near_axis`: спектр около мнимой оси.
- `inconclusive_at_controller_boundary`: начальная точка на границе либо в активном режиме ограничителя/переключателя; гладкий спектр не даёт окончательного вывода.

Участие вычисляется из правых собственных векторов V и строк V⁻¹:
`abs(V[k,i] * inv(V)[i,k])`, с нормировкой суммы по состояниям до единицы
для каждой моды. Это атрибуция состояния, не энергия. При совпадающих
собственных значениях (относительный порог 1e-7) либо обусловленности
базиса выше 1e10 участие не выдаётся. Проверяется невязка собственных пар.
Имена машин привязаны к каноническим ID; вспомогательные состояния без
такого соответствия имеют префикс `backend:` и исходное имя ANDES.

## Проверка и границы результата

[Численные доказательства](../reports/small-signal-2026-10-30/reference.json):
спектр GENROU сравнивается с Якобианом независимой шестимерной ODE,
полученным центральными разностями с шагом 1e-6. Фиксированный допуск
составляет 1e-5 с⁻¹; соответствие мод определяется оптимальным сопоставлением.
Проверяются режимы без насыщения и с квадратичным насыщением.
GENCLS отдельно проверяется аналитической частотой качаний и затуханием
при ненулевом D. Тестируются вырожденные матрицы, масштабирование координат,
границы регуляторов, CLI и отдельный worker.

Это локальный анализ одной рабочей точки. Временная траектория не считается
(`time_domain_simulated=false`); duration/step остаются полями общего паспорта,
но не задают интегрирование спектра. Events и faults отклоняются.
Плотное разложение ограничено 8 машинами и 256 динамическими состояниями.
Большая сетевая алгебра всё ещё может требовать значительных ресурсов;
worker обеспечивает deadline и отмену, но не квоту памяти или OS sandbox.

Результат не доказывает переходную или глобальную устойчивость и не заменяет
натурную валидацию. Промышленная квалификация остаётся открытой.
GENSAL отсутствует в установленном backend: её реализация, независимый эталон,
двигатели, преобразователи, внешний динамический корпус и разреженный поиск
критических мод остаются следующими этапами. Актуальный перечень моделей
backend следует проверять в [официальной документации ANDES](https://docs.andes.app/en/stable/reference/models/index.html)
и в фактически установленной версии.
