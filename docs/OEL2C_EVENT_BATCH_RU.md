# NA-07: независимые совпадающие below-clock события OEL2C

В паспорте OEL2C добавлена явная политика
`coincidence_policy: independent_below_clock_batch_v1`.
По умолчанию остаётся `legacy`: прежние многолимитерные входы сохраняют FD и прежнюю
обработку событий. Автоматический аналитический маршрут разрешён для нескольких OEL2C,
только если **все** их паспорта явно выбирают новую политику. Смешанный выбор сохраняет FD.
Новая политика — часть модели входных данных и её hash, не скрытая настройка решателя.

## Правило пакета

Пакет создаётся только после фактически локализованного корня `branch_below`.
Другой OEL2C может присоединиться, если его below-контекст совпадает с исходным,
смещённая поверхность guard находится в полосе машинного округления и текущая
производная поверхности направлена в сторону перехода. Дополнительно локальная
оценка времени `abs(shifted_guard / guard_rate)` должна быть не больше
`64 * eps * max(1, abs(event_time))`. Это защищает от почти горизонтальных guards,
которые близки по состоянию, но далеко по времени. Полоса состояния равна
`64 * eps * max(1, |Ireference|, |KAct * Imeasured|, IThOffPu)`; это полоса в
координатах guard, а не произвольное окно времени и не допуск ODE.

Используется существующее смещение guard на `64*eps`. Его пороги и направление
не меняются. Производная below-поверхности вычисляется из собственных reference
и sensor ODE с фактическим текущим полевым током. Это не предположение о равновесии
датчика. Измерения сети вычисляются один раз для исходного состояния пакета.

Непрерывные состояния не переставляются и не сбрасываются. Все добавляемые корни
определяются до изменения контекстов; затем независимые лимитеры применяются в
порядке `generator_id`. У каждого собственные состояния/контекст. Переключение
clock не меняет мгновенные GENROU flux states, а значит и сетевой ток, использованный
для принятия решения о пакете. Unit tests проверяют коммутативность clock updates
и отсутствие сбросов состояния. В журнале сохраняются все переходы каждого устройства.
Экспортированные стороны событий не сортируются и не вырезаются после расчёта.

Другие guards не могут создавать пакет. Близкие события на расстоянии 1e-10,
1e-8 или 1e-4 по поверхности не объединяются тестовыми случаями. Противоположное
направление, другой контекст и смешанные политики исключают присоединение.

## Квалифицируемая область

Восемь **явно отличающихся** от legacy профилей: cold two_limiters/four_machines,
loaded two_limiters, active two_limiters/mixed_modes, regulating two_regulators/
mixed_modes, selected two_selected. Физические коэффициенты, команды и длительности
исходных сценариев сохраняются; меняется только заявленная политика совпадений и id.
Два повтора analytic/FD дают 16 сравнений в 32 свежих процессах. Проверяются исходные
полные каналы, стороны, порядок/имена переходов и часы при прежних допусках.

Шесть профилей дополнительно проверяются в независимой SI-сети с закреплёнными
Dynawo-derived cap-guard-v1/equilibrium-guard-v2 FMU, при 1e-12 и 1e-13:
12 нативных процессов. Это проверка экспортной сетки, физических событий и состояний,
не сертификация всех внутренних clock эталона. Нативный master сохраняет собственную
обработку событий; Python policy не экспортируется как выдуманный Modelica parameter.

Исторический отрицательный пример NA-06 остаётся отрицательным для legacy policy.
Новая политика не задним числом квалифицирует его. Общий диспетчер всех совпадающих
guard, saltation matrices и произвольные комбинированные события остаются отдельной
работой. Квалификация относится к конкретным отчётам, fingerprints и указанным входам.

```bash
OPENBLAS_NUM_THREADS=1 python -m pytest tests/test_oel2c_batch.py -q
OPENBLAS_NUM_THREADS=1 python -m benchmarks.oel2c_batch_validation --out reports/na07-algorithm
OPENBLAS_NUM_THREADS=1 python -m benchmarks.oel2c_batch_native_validation --root /tmp/pge-native --out reports/na07-native
```

Для подготовки Modelica runtime используются прежние hash-pinned setup-команды
из `OEL2C_JACOBIAN_RU.md`. Воспроизводимая локальная поставка не подменяет EX-04:
подписанный запуск на независимом хосте по-прежнему необходим для соответствующего
release-статуса. Ни OEM-квалификация, ни произвольные масштабы не заявляются.

Первый предварительный корпус `na07-qualified`/`na07-native` не является итогом после добавления защиты от shallow guards. Окончательные корпуса: `reports/na07-qualified-v2-2026-11-05/` и `reports/na07-native-v2-2026-11-05/`.
