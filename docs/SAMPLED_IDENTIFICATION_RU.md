# B19 — интегрирование на узлах записи и шумное входное напряжение

Новый `replay_method: sample_rk4` предназначен для ограниченного профиля
динамической идентификации B15/B17. Он работает с теми же физическими
уравнениями, измерениями, интерполяциями и начальными состояниями; напряжение
не сглаживается. Старый `dop853` остаётся методом по умолчанию.

```sh
python -m power_grid_env.cli calibrated-motor \
  --input cases/sampled-identification/study.json --out /tmp/sampled-motor
```

Пример в репозитории самодостаточен: в нём опубликованы исходные CSV и
прежний отказ B18. Для численного запуска сеть и оборудование не нужны.
Источники синтетические, с фиксированным Gaussian шумом напряжения std=0.01 V
и тока std=0.0001 A, по прежнему seed. Это не паспорт измерительного устройства.

## Почему изменён шаг интегратора

Напряжение интерполируется линейно **во вращающихся осях**, как прежде. У
такого входа производная меняется на каждом отсчёте. При шуме адаптивный DOP853
может тратить много RHS около этих узлов; результаты также чувствительны к
его точностным допускам. Это не дискретное событие электрической сети и не
изменение схемы: речь только о численном воспроизведении заданного временного ряда.

Новый алгоритм не пересекает границу входного интервала одним шагом:

1. На каждом интервале используются его точная линейная формула напряжения
   и прежняя cubic not-a-knot интерполяция условной измеренной скорости.
2. Сравниваются один RK4-шаг и два половинных. Оценка локальной ошибки —
   `(fine − coarse)/15`, с покомпонентным масштабом
   `2e-11 + 2e-9·max(|x_left|, |x_fine|)`.
3. При нормированной ошибке ≤1 принимается Richardson-коррекция
   `fine + (fine − coarse)/15`. Иначе интервал делится пополам.
4. Все RHS, включая отброшенные пробы, учитываются в общем бюджете. Глубина
   деления ограничена 14, неразрешимый/неконечный шаг отклоняется.

Локальная оценка сама по себе не является гарантией глобальной ошибки.
Приёмка отдельно проверяет точное скалярное решение, уменьшение шага и
электромеханические траектории против другого алгоритма. `sample_rk4` не
подключается автоматически к RMS/DAE/EMT сети, защитам или произвольным машинам.
Профиль B15 — одна клетка, фиксированная температура, нулевой Gc, известные
частота и начальные потоки — остаётся прежним.

## Как выбрать метод

В `identification` протокола записей либо документа аудита задайте
`"replay_method": "sample_rk4"`. Поле присутствует в JSON Schema. Допуски
интегрирования по умолчанию не ослаблены; максимальные ошибки raw-replay,
sigma, ограничения параметров и сетевые критерии тоже не изменены.

Для чистого/слабо меняющегося входа шаг по каждому отсчёту может потребовать
больше работы, чем DOP853. Метод выбирается явно; всеобщего ускорения нет.
Для проверки сходимости внутренний `replay` позволяет ужесточить точность
через `accuracy_factor ≤ 1` и задать 1/2/4 начальных деления интервала.
Это инструменты проверки, а не дополнительные параметры принятого JSON-профиля.

`optimizer` теперь сохраняет `nfev`, `njev`, полное число residual-evaluations
и число дополнительных вызовов для численного якобиана. Число RHS остаётся
полным счётчиком, включая механический подбор и свободные replay. Эти
показатели не складываются повторно: residual-evaluations уже включает
численные производные. Аудит B17 добавляет свои raw-replay в общий RHS.

Старые B16-пакеты без нового поля метода проверяются с семантикой default
`dop853`; отсутствие явного значения по умолчанию не делает их подменёнными.
Манифест байтов по-прежнему обязателен, остальные различия входа не игнорируются.

## Проверки и ресурсы

```sh
OPENBLAS_NUM_THREADS=1 PYTHONPATH=.:/path/to/pinned-motulator \
python -m benchmarks.sampled_identification_acceptance \
  --wheel /path/to/motulator-0.19.0-py3-none-any.whl \
  --out /tmp/new-sampled-acceptance
```

Исходные CSV первого линейного случая побайтно совпадают с неуспешным B18;
их SHA-256 закреплены в benchmark. Исходный преобразованный протокол также
сравнивается целиком, кроме метода и более строгих рабочих лимитов:
4000000 RHS/120 s вместо 10000000 RHS/600 s. Выбор параметров, паспорт,
источники калибровки, массивы, sigma, hold-out и пороги не меняются.

Forward и центральный численный якобиан измеряются отдельно по три раза на
одной трассе/паспорте: log-step=1e-4, четыре столбца, два forward на столбец.
Сохраняются RHS, CPU time и wall time каждого прогона. Критерий ресурсного
выигрыша — сокращение RHS минимум вдвое в обоих опытах. Ускорение времени
измеряется, но не служит флуктуирующим обязательным порогом. Расход памяти
этим опытом не сравнивается; результат относится к данной задаче на данном host.

Для каждого профиля проверяются условный и свободный forward. Контрольный
DOP853 работает при в 1000 раз более строгих rtol/atol. Пределы сравнения:
5e-7 A, 5e-7 rad/s, 1e-8 Vs, 1e-6 Nm. При делении интервалов 1→2→4 разность
токов должна уменьшаться минимум вдвое, если она выше 1e-8 A; ниже этого
уровня применяется абсолютный порог 1e-8 A. Проверка не выдаёт расхождение
с конечной точностью контрольного решателя за ошибку только одного метода.

Квалифицируемый корпус — линейный/насыщенный вентилятор и насыщенный вязкий
привод с std напряжения 0.01 V. Все три паспорта должны пройти исходный
raw-аудит, критерий параметров 0.02 и сетевой перенос против заново выполненного
motulator/MNA с истинными параметрами. Сетевые допуски B15 сохранены:
0.01 A, 0.01 V, 0.0001 Vs, 0.025 rad/s, 0.02 Nm, 0.5 W. Отрицательный случай
с неверным gain U в hold-out должен остаться отказом без паспорта. Два
положительных случая повторяются в изолированной параллельной серии, переносятся
через ZIP и повторно используются с точным сохранением результата.

## Непройденное расширение: заторможенный двигатель

С новым интегратором заторможенный двигатель при 0.01 V шуме успешно
идентифицируется в пределах raw-аудита и критерия параметров. Его forward
проходит сравнение с ужесточённым DOP853 и сходимость по шагу. Однако в
сетевом переносе расхождение потерь ротора/статора около 0.776/0.796 W
превышает прежний предел 0.5 W. Этот расширенный профиль **не квалифицирован**.
Успех интегратора не заменяет точность обратной задачи на шумных измерениях.

```sh
# Включает непройденное расширение; ожидаемый общий статус — отказ:
python -m benchmarks.sampled_identification_acceptance \
  --wheel /path/to/motulator-0.19.0-py3-none-any.whl \
  --include-locked --out /tmp/extended-sampled-acceptance
```

Исходный `reports/sampled-identification-trial-2026-11-08/summary.json` с четырьмя
семействами сохранён с passed=false. Для трёх подтверждённых семейств проводится
отдельный полный прогон. Предел потерь не увеличивается ради успеха. Следующий
блок должен отдельно исследовать достижимую точность параметров при шумном U,
разрешимость и перенос потерь, сохранив независимый hold-out.

## Итог локальной приёмки 8 ноября 2026

`reports/sampled-identification-final-2026-11-08/summary.json` принят в явно
названном профиле трёх семейств. Прежний не завершившийся линейный случай
успешен при **1527168 RHS** и 46 residual-evaluations в бюджете 4000000.
Насыщенный вентилятор — 2485488 RHS, вязкий привод — 2149200 RHS. Параметры,
raw-невязки и независимые сетевые переносы прошли прежние критерии.

Три парных измерения на одной зафиксированной трассе: forward 89894→15480 RHS
(5.81 раза), центральный якобиан 743686→123840 RHS (6.01 раза). Все CPU/wall
пробы сохранены; эти отношения не объявляются ускорением любого исследования.
Три сетевых переноса, шесть conditional/free сравнений и уменьшение шага,
отрицательный gain hold-out, параллельная серия двух исследований и точное
продолжение из ZIP прошли. Максимальная относительная ошибка параметров
в принятом корпусе — 1.59e-5 при неизменном критерии 0.02.

Полный обязательный профиль: 1460 тестов, ноль ошибок/отказов/пропусков.
2082 теста вне профиля не выполнялись. Снимок исходников точно соответствует
инвентарю прогона; последующие заметки статуса сохранены отдельно. Wheel
проверен вне репозитория на принятом и отрицательном физических случаях;
venv использует доступные системные зависимости. Данные, исходники, JUnit,
wheel, метрики и непройденное locked-расширение сохранены в
`reports/sampled-identification-delivery-2026-11-08/delivery.json`, `manifest.json`.

Следующий B20 относится к точности обратной задачи/потерям locked-расширения,
а не к объявлению этого отказа пройденным. Статистические гарантии, натурная
валидация, универсальная промышленная квалификация и преимущество на всех
масштабах не заявляются. GitHub/CI не использовались.
