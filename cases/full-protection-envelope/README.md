# Полный пуск и восстановление на крайних сочетаниях допусков

Продолжение [inverse protection](../inverse-protection/README.md). Здесь ранний
пусковой фрагмент заменён исходными полными нормальными сценариями: пуск4с,
повторные провалы4с, выбег/самозапуск4с. Сохраняются исходные criteria, события,
minimum_final_speed=.9, токовые/тепловые и напряженческие ограничения.
Три отдельных аварийных опыта имеют прежние apply0.1/clear0.8/horizon1с
и явно заданные критерии отключённой установки. Они не подменяют нормальные
требования успешного разгона.

## Матрица

Standard Inverse основной и резервной ступеней, два решателя Radau/network_dae.
В каждом случае все16 сочетаний ±5% pickup/±10% TMS плюс nominal. Один вариант:
6сценариев ×3сетки =18 интегрирований. Один решатель:306. Оба:612.
Семейства Very/Extremely Inverse пока не входят в **этот полный corner-профиль**.

```sh
python -m power_grid_env.cli protection-envelope-store --input cases/full-protection-envelope/radau.json --out /tmp/full-si-radau
python -m power_grid_env.cli protection-envelope-store --input cases/full-protection-envelope/network_dae.json --out /tmp/full-si-dae
python -m power_grid_env.cli verify-protection-envelope-store /tmp/full-si-radau --input cases/full-protection-envelope/radau.json
python -m power_grid_env.cli verify-protection-envelope-store /tmp/full-si-dae --input cases/full-protection-envelope/network_dae.json
python -m benchmarks.full_protection_envelope_reference --radau /tmp/full-si-radau --dae /tmp/full-si-dae --owner-radau cases/full-protection-envelope/radau.json --owner-dae cases/full-protection-envelope/network_dae.json --out /tmp/full-si-reference
```

Последняя команда проверяет306 пар case/grid и SI-алгебру обеих траекторий,
то есть612 сохранённых результатов. Допуски сравнения и clock audit не
увеличены. Дополнительно проверяются времена/стороны событий, измерения,
действия аппаратов, motor audits, recipe и точное исходное задание.
SI oracle условен относительно сохранённых EMF-состояний двигателя: это
не независимый решатель полной дифференциальной динамики.

Проверку можно запустить одновременно с расчётами, добавив `--wait-for-studies`.
Она ждёт только запечатанные дочерние исследования и проверяет готовые пары
по мере появления. Итоговый положительный протокол публикуется лишь после
полной проверки обоих17-study индексов. Отдельный готовый corner reference
не является положительным результатом всей незавершённой матрицы.

## Фактическая аварийная нагрузка

```sh
python -m benchmarks.full_protection_duty --radau /tmp/full-si-radau --dae /tmp/full-si-dae --owner-radau cases/full-protection-envelope/radau.json --owner-dae cases/full-protection-envelope/network_dae.json --out /tmp/full-si-duty
```

Для306 аварийных grid traces отдельно вычисляются время от приложения КЗ до
действительного размыкания, I²t кабеля, RMS-ток непосредственно перед открытием
и максимальный sampled RMS-ток трансформатора. Квадрат линейного интерполянта
тока интегрируется точно; pre/post-скачки не сглаживаются. Для fine pair
проверяются относительное изменение I²t<=.002 и изменение clearing<=1e-7с.

Основная защита должна уложиться в исходный owner clearing budget. Резервные
сценарии проверяются по фактическому времени, адиабатической стойкости кабеля
и заданным токовым/временным пределам трансформатора; бюджет основной защиты
не приписывается резерву. Ток перед открытием сопоставляется с параметром
соответствующего аппарата. Эти расчёты используют уже проверенные трассы,
а не заменяют токи одним первоначальным значением КЗ.

Остаются фиксированные R/X, предположение о начальной температуре и
неподтверждённые owner ratings. Это не связанная тепловая модель кабеля,
не учёт апериодической составляющей/ударного тока и не OEM-подтверждение.
Нормальный длительный нагрев/повторные пуски кабеля этой fault-only проверкой
не квалифицируются. Дополнительный флаг `--wait-for-stores` позволяет начать
этот анализ до завершения обоих stores, но положительный итог требует их
полной проверки.

## Составное хранение

Длинная матрица больше лимита одного обычного study artifact. Лимиты
study_artifacts.MAX_FILE/MAX_TOTAL/MAX_FILES остаются прежними. Новый store:

```text
store/
  index/
    plan.json
    entries.json
    result.json
    manifest.json
  studies/
    nominal/
    corner-0000/
    ...
    corner-1111/
```

Каждый дочерний пакет — обычный bounded artifact со своим manifest. Индекс
содержит фиксированные имена, рецепты, hashes manifests/results, объёмы и
число завершённых grid runs. Верификатор не доверяет этим числам: пересчитывает
их, сверяет source plan и заново проверяет физику/часы/действия каждого пакета.
Неизвестные/пропущенные/переставленные исследования, дополнительные файлы
в index, несовпадающие hashes и символьные ссылки отвергаются.

**Верхний store не является обычным sealed study artifact.** Проверка только
`index/manifest.json` не проверяет содержимое всех исследований; используйте
verify-protection-envelope-store. Для переноса копируйте всю директорию
с index и studies, сохраняя внутренние имена. Для обычного ZIP можно отдельно
экспортировать каждый studies/<name> и index стандартными artifact tools.
Единый oversized ZIP не требуется. Это организация большого набора независимых
ограниченных пакетов, а не отмена ограничений чтения файлов.

Существующая выходная директория не перезаписывается. Во время расчёта index
ещё не запечатан. Отмена/ошибка может оставить частичные данные для разбора,
но не даёт complete verified positive store. Автоматическое resume в этом
профиле не реализовано: для повторного исполнения выбирайте новую директорию.
Работающая проверка предполагает, что пользователь не изменяет проверяемые
данные одновременно с чтением; manifest не является блокировкой файловой системы.

## Границы результата

Это один authored single-cage двигатель75кВА/400В и двухузловая радиальная
сеть с условиями каталожного примера. Холодная инициализация, фиксированные
задержки аппаратов, reset/dropout и конкретное downstream КЗ. Неподтверждённые
параметры исходного оборудования не становятся OEM-паспортами после расчёта.

Все16 крайних сочетаний не доказывают пригодность внутренних точек диапазона.
Не заявляются cold/hot envelope, CT saturation, instantaneous stages,
произвольные типы/положения КЗ, схемы и масштаб, OEM-эквивалентность или
нормативное одобрение. `reward=null` и `continuous_uncertainty_qualified=false`.
Полный DES-04 остаётся открыт за пределами этого явно объявленного профиля.
