# Подпитка КЗ двигателями: фазовое разложение и токи аппаратов

## Что реализовано

`power_grid_env.motor_fault_contribution` решает симметричный снимок радиальной
сети с одним источником, кабелем, постоянным Z нагрузки и несколькими
асинхронными двигателями. КЗ может находиться в любой точке кабеля, в том
числе точно на его концах. Поддержаны конечное R+jX КЗ и точный болт без
замены на маленькое сопротивление. Источник и двигатели можно отключать.

Двигатель представлен сохранённой внутренней ЭДС за Rs+jXprime; паспортные
pu параметры пересчитываются на собственную базу каждого двигателя.
Потокосцепления, скорость и время затухания этим расчётом не интегрируются.
ЭДС примера авторская; происхождение и условия обязательно передаются.

Каждое возбуждение решается отдельно: внешняя сеть и каждый двигатель.
При подавлении ЭДС остальные внутренние сопротивления **сохраняются**.
Для физического отключения двигателя его ветвь, напротив, удаляется.
Компоненты складываются комплексно, с фазой, а не по модулям. Отдельно
публикуются реальные токи ветвей: это другой объект, чем компонента возбуждения.

`source_a` — ток порта источника; `motor:<id>_a` — ток от двигателя к шине;
`fault_a` — полный ток в КЗ. `feeder_from_a` и `feeder_to_a` направлены
от питающего конца линии к моторному. При внутреннем КЗ они различаются.
`upstream_segment_a` и `downstream_segment_a` направлены источник→КЗ→двигатели;
при нулевой длине соответствующего сегмента это граничный баланс, а не
дополнительный аппарат. Используйте feeder-порты для линейных датчиков.
Длины сегментов явно сохранены в `segment_lengths_pu`.

Выход содержит комплексные напряжения, токи, вклад каждого возбуждения,
проверки KCL, невязки узловых уравнений и суммы компонентов. Проверка алгебры
не означает прохождение защит, достаточность выключателя или пригодность сети.
Награда для обучения и нормативное одобрение не выдаются.

## Запуск

Из корня репозитория, выходной каталог должен отсутствовать:

```bash
python -m power_grid_env.motor_fault_contribution \
  --input cases/motor-fault-contribution/snapshot.json \
  --out reports/my-motor-fault

python -m benchmarks.motor_fault_star_reference \
  --input cases/motor-fault-contribution/snapshot.json \
  --out reports/my-motor-fault-star

python -m benchmarks.motor_fault_contribution_reference \
  --plan cases/closed-loop-protection/radau.json \
  --out reports/my-motor-fault-dynamic

python -m benchmarks.motor_fault_branch_duty \
  --source reports/my-motor-fault-dynamic \
  --out reports/my-motor-fault-duty
```

`verify_contribution(root, expected_snapshot=...)` требует исходный снимок
владельца и пересчитывает артефакт. Хеш и seal удостоверяют целостность,
а не подлинность паспорта. `snapshot_from_report(study, report, index)`
извлекает реальную ЭДС, состояние контакторов и источник из поддержанного
двухузлового coupled trace, фиксирует хеш полного отчёта и сторону события.
Открытая линия, несколько активных КЗ, двухклеточные двигатели, неподдержанная
топология и некорректные дискретные каналы явно отклоняются. Это извлечение
данных, а не полноценная верификация переданного отчёта.

## Выполненные проверки, 13 ноября 2026

- 216 независимых сравнений через скалярное исключение ветвей, без матрицы
  производителя: разные фазы ЭДС, 1/3 двигателя, питание включено/отключено,
  болт/резистивное КЗ и три точки линии. Max ошибка около3.1e-12A.
- 24 динамических расчёта: четыре сценария ×Radau/DAE ×три сетки.
  Три секунды реального разгона до КЗ, затем fault3..3.15с и восстановление
  до3.3с. Сценарии: холодный кабель; горячий с0.95U; КЗ на питающем конце;
  отключение двигателя в3.05с. Нагрузка и двигатель остаются авторскими.
- 168 срезов, включая post-apply/pre-clear, сверены по напряжениям, току КЗ,
  двигателя и физическим CT источника/линии; все прошли. 12 пар Radau/DAE
  согласованы на всех временных точках, с отдельными сторонами событий.
- Из тех же24 траекторий рассчитаны I²t источника, обоих портов кабеля,
  двигателя и КЗ. Интегрируется квадрат линейной интерполяции RMS, без
  размазывания скачков. Все8 fine-grid сравнений проходят0.2%; фактический
  max относительный сдвиг7.084e-5 (около0.0071%). Это sampled I²t, не EMT.
- 206 целевых тестов, включая43 теста разложения/trace-адаптера и8 тестов
  интегрирования, без ошибок/пропусков. Полный репозиторий не перепроверялся.

КЗ на питающем конце показывает важность раздельных портов: на мелкой
Radau-сетке sampled максимум источника около5974A, кабеля481A, КЗ6425A.
Нельзя назначать кабелю полный ток КЗ или считать I²t компонентов аддитивным:
у квадрата суммы комплексных токов есть перекрёстные члены.

Первый диагностический прогон сохранён в
`reports/motor-fault-contribution-2026-11-13`: он выявил ошибку именно
эталонной привязки линейного CT к источнику при upstream-КЗ. Она исправлена
с отдельным регрессионным тестом и полным повтором24 запусков.
Положительное свидетельство — только `reports/motor-fault-contribution-qualified-2026-11-13`.
Независимая статическая сверка — `reports/motor-fault-star-reference-2026-11-13`;
по-портовое I²t — `reports/motor-fault-branch-duty-2026-11-13`.

## Что ещё не закрыто

Это не независимый динамический эталон: снимки обусловлены ЭДС основной
траектории, а сравнение Radau/DAE использует общую физику. Тёплый пуск получен
интегрированием из холодного состояния, не новой нагруженной инициализацией.
Поддержаны только однотоковые single-cage машины с алгебраическим статором;
нет DC/пиков, saturation/skin-effect, несимметрии и температурной обратной связи.
Токи машин с меняющимися фазами не наследуют монотонные холодные/горячие
границы пассивного экрана. Для них нужны отдельные динамические исследования.
Защиты в новом бенчмарке измеряют токи, но pickup=1e8A намеренно подавляет
их действия: проверяется подпитка и датчики, а не успешная селективность.
Существующая квалификация защит остаётся отдельным профилем.

Локальная поставка `reports/motor-fault-delivery-2026-11-13` включает wheel,
исходники нового профиля, тестовый XML и6 точных повторов снимков из
установленного wheel с повторной проверкой артефактов. Python запущен с `-I`
вне checkout, reference imports запрещены; host и библиотеки общие. Полные
траектории не продублированы в поставке, их manifest-хеши закреплены отдельно.
