# DES-04: замкнутые реле и выключатели в моторной сети

В этом профиле измеренный ток участвует в дифференциальных часах реле,
trip запускает реальную команду аппарату, размыкание меняет сетевые уравнения,
а остаточные потокосцепления двигателя продолжают эволюционировать.
Это следующий шаг после [дискретного protection screen](../protection-screen/README.md).

## Запуск

```sh
python -m power_grid_env.cli closed-loop-protection --input cases/closed-loop-protection/radau.json --out /tmp/protected-radau
python -m power_grid_env.cli verify-closed-loop-protection /tmp/protected-radau --input cases/closed-loop-protection/radau.json
python -m power_grid_env.cli closed-loop-protection --input cases/closed-loop-protection/network_dae.json --out /tmp/protected-dae
python -m benchmarks.closed_loop_protection_reference --radau /tmp/protected-radau --dae /tmp/protected-dae --out /tmp/protected-reference
```

В plan включены исходное оборудование/выбор из [equipment-catalog](../equipment-catalog/README.md),
номинальные уставки, конкретные КЗ и отдельные owner-критерии аварийных режимов.
Планы двух решателей отличаются только integration_method. Исходные файлы
radau/network_dae скомпилированы из каталога Nexans/Trihal, их происхождение
сохранено в Source. Недостающие параметры каталога остаются допущениями.

Компилятор переносит параметры выбранного кабеля и трансформатора в общую
сеть и добавляет основную защиту линии и резервную защиту источника.
Нормальные критерии пуска, события провалов и повторного включения сохраняются.
Аварийные критерии заданы явно и отдельно: после правильного отключения
не требуется успешного разгона или сохранения напряжения на обесточенном узле.
Это не ослабление исходных нормальных требований.

## Проверяемые случаи

На каждом решателе выполняются шесть случаев на трёх сетках —18 интегрирований:

- Пуск, повторные провалы и выбег/самозапуск: защиты не должны отключать сеть,
  и должны выполняться исходные требования по скорости/току/напряжению/нагреву.
- КЗ downstream в момент0.1с: основная definite-ступень trip через0.04с,
  физическое открытие линии ещё через0.02с — в0.16с. Резерв не должен trip.
- Отказ основного выключателя: failed_to_operate в0.16с, подтверждение отказа
  через0.02с при сохраняющемся токе, открытие резервного аппарата ещё через
  0.03с — в0.21с. Самостоятельное реле резерва не используется вместо
  ожидаемой цепочки обнаружения отказа.
- Потеря измерения основной защиты во время расчёта, в0.05с: резервная ступень
  trip в0.35с, размыкание источника в0.38с.

КЗ сохраняется до0.8с в аварийных опытах; его удаление в схеме — отдельное
заданное событие после ожидаемого отключения. Это не команда, подменяющая
действие реле. При отсутствии ожидаемых событий или состояния аппаратов
профиль отклоняется.

Проверяется ровно ожидаемый набор размыканий, время события, отсутствие
нежелательного trip, нулевое состояние closed после открытия и электрическая
изоляция (ток разомкнутой линии или disconnected source). Дополнительно
выполняются штатные моторные shaft/algebra/I²t/thermal audits и согласие сеток.
Итог с неполными расчётами или ошибочными действиями пройти не может.

## Изменение решателя и независимые проверки

CoupledSettings теперь допускает явно указанный пустой список синхронных
машин: motor-only профиль с внешним источником. Фиктивный генератор не добавляется.
Пустой массив индексов генераторов имеет целочисленный dtype; холодное
начальное состояние создаётся без фиктивного PV-решения. Loaded motor-only
инициализация пока явно запрещена. Генераторные сети всё ещё требуют
соответствующих паспортов. Формулы существующих генераторов не менялись.

Сверка benchmark включает независимые SI-узловые уравнения двухузловой сети
с источником, кабелем, Z-нагрузкой, КЗ и Norton-ветвью двигателя. Выходные
EMF-состояния двигателя используются как входы этого oracle: это **независимая
проверка алгебры и измерений, не независимая дифференциальная траектория**.
Нативный stamping/электрический решатель и constants() не вызываются;
production topology используется только для идентификации каналов шин.
Radau/DAE сравниваются по одинаковым временам и отдельно по pre/post samples,
без интерполяции через скачки. Времена definite-действий проверяются аналитически.

## Границы

Номинальные definite-уставки. Допуски из RelaySetting не варьируются в этих
динамических опытах; их отдельный screen не доказывает устойчивость полной
замкнутой системы к неопределённости. Проверенный пример — один single-cage
двигатель75 кВА/400 В, радиальная двухузловая сеть, положительная последовательность,
алгебраические статоры, холодная инициализация. Не заявлены произвольный масштаб,
все положения/виды КЗ, CT saturation, мгновенные отсечки или OEM-эквивалентность.
Вклад остаточного EMF двигателя в эти связанные сетевые уравнения присутствует;
это не полная квалификация short-circuit duty для всех машин и температур.

`reward=null` всегда. Положительный passes_declared_profile — ограниченная
приёмка перечисленных действий, не нормативное одобрение или пригодность
проекта для автоматической выдачи. Полные DES-02/03/04 остаются открытыми.
