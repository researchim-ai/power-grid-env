# Проверка уставок пуска и координации двух защит

Отдельный инженерный **screen**, использующий проверенные физические результаты
[catalog-design](../equipment-catalog/README.md). Он не подключает реле к
интегратору и не меняет траектории двигателя. Положительный результат означает
прохождение перечисленных дискретных проверок, а не завершение DES-04.
`reward=null` всегда: этот screen не выпускает меток пригодного проекта для SFT/GRPO.

## Запуск

Сначала нужен каталожный пакет от текущей версии решателя:

```sh
python -m power_grid_env.cli catalog-design --catalog cases/equipment-catalog/catalog.json --input cases/equipment-catalog/brief.json --proposal cases/equipment-catalog/selection-250.json --out /tmp/protection-source
python - <<'PY'
from pathlib import Path
from power_grid_env.study_artifacts import read_json,encoded,verify
p=read_json('cases/protection-screen/settings.json')
p['catalog_manifest_sha256']=verify('/tmp/protection-source')
Path('/tmp/protection-plan.json').write_bytes(encoded(p))
PY
python -m power_grid_env.cli protection-screen --input /tmp/protection-plan.json --study /tmp/protection-source --out /tmp/protection-screen
python -m power_grid_env.cli verify-protection-screen /tmp/protection-screen --input /tmp/protection-plan.json
```

Нулевой hash в `settings.json` — намеренный незаполненный anchor: исходный
шаблон не может пройти проверку с произвольным пакетом. Доверенный план содержит
manifest hash уже проверенного исследования. Передавая `--input` в verifier,
владелец обнаруживает подмену уставок и самого anchor. Пакет копирует исходное
исследование внутрь, поэтому переносится без зависимости от первоначального пути.
Запись внутрь исходного пакета запрещена. CLI exit0 только при прохождении
screen, exit2 при отказе или ошибке.

## Что вычисляется

Для каждого сценария на трёх сетках восстанавливается ток фидера:
I=abs((Vfrom−Vto)/Zline), фазные напряжения в вольтах. Это общий ток, включая
вспомогательные нагрузки, а не просто сумма модулей токов двигателей.
Проверяется изменение sampled peak на двух тонких сетках. Консервативное
условие **отсутствия pickup**: maximum_sampled_current·margin меньше уставки
с отрицательным допуском. Короткий pickup может не вызвать trip в реальном реле,
но этот профиль сознательно отвергает такое решение. Скрытого расчёта интеграла
срабатывания или сброса реле нет. Между отсчётами максимум не доказан.

Основная защита расположена в начале кабеля, резервная — последовательно выше;
в рассматриваемом радиальном эквиваленте они видят один ток КЗ после основной
защиты. Положение0 означает начало кабеля сразу после основной защиты,
а не КЗ шин перед её выключателем. В примере пять положений вдоль кабеля и
три множителя напряжения дают15 дискретных условий КЗ. Импедансы выбраны
из одного рабочего температурного состояния. Это не полный cold/hot envelope.

Кривые: definite, standard_inverse, very_inverse, extremely_inverse. Используется
существующая реализация IEC-кривых в `protection.py`. Уравнения и коэффициенты
также опубликованы в [официальной документации ABB](https://techdoc.relays.protection-control.abb/r/REX610-Technical-Manual/1.1/en-US/Standard-inverse-time-characteristics).
Для раннего trip берутся низкий pickup и короткое время; для позднего clearing —
высокий pickup, длинное время и максимальная задержка выключателя.
Необнаруживаемое КЗ даёт null вместо бесконечного времени и отрицательный verdict.

В каждой точке проверяются: pickup обеих защит; запас от позднего clearing
основной до раннего trip резервной; основной clearing в пределах owner budget;
отключающая способность; I²t кабеля при основной и резервной защите;
паспортные/заданные ток и длительность стойкости трансформатора при отказе
основной защиты. Адиабатическая проверка не экстраполируется за5 секунд.
Не подтверждённые OEM параметры исходного каталога остаются допущениями.

## Матрица и независимая сверка

```sh
python -m benchmarks.protection_design_acceptance --study /tmp/protection-source --input cases/protection-screen/settings.json --out /tmp/protection-matrix
```

Восемь наборов: два допустимых (definite и inverse primary), pickup на пуске,
недостаточный запас времени, медленная основная защита, отсутствие pickup КЗ,
недостаточная отключающая способность, слишком поздний резерв.
Их физическая основа одна: девять интегрирований трёх сценариев на трёх сетках;
восемь postprocessing-проверок не объявляются72 новыми интегрированиями.

OpenDSS независимо решает15 схем КЗ. Сохраняются команды, фазные токи и версия,
допуск2e-6. Matrix verifier повторяет вычисление времён, решений и внешней
сверки; summary и отрицательные результаты проверяются так же, как положительные.
Это не внешняя валидация динамической работы реле. В unit tests времена
дополнительно сверены с отдельными аналитическими выражениями всех трёх кривых.

Остаются: замкнутое действие на выключатель, CT saturation, instantaneous
stages, полный возврат реле, вклад двигателей в КЗ, ударный ток, земляные КЗ,
все положения КЗ и температурные/топологические варианты, серийные OEM curves.
DES-02/04 целиком этим screen не закрываются.
