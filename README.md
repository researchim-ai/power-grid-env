# power-grid-env

Зарегистрированные внешние сравнения AC/pandapower, RMS/ANDES и
full-winding/motulator с явным coverage: [протокол R01.1](docs/COMPARISON_PROTOCOL_RU.md).

Пуск и самозапуск с аудитом энергии вала, I²t, тепловой реплики и проверкой
трёх шагов: [инженерный пакет](docs/MOTOR_ENGINEERING_RU.md).

Генерация проверяемых LLM-задач, SFT-диалоги, физические награды GRPO и локальное
обучение/оценка checkpoint: [руководство](docs/LLM_TRAINING_RU.md).
Первый профиль — восстановление питания; обучение инженерного LLM и превосходство
над другими моделерами пока не заявляются.

[English](README.en.md)

[Текущий статус, открытые блоки и очередь работ](plans/CURRENT_STATUS.md)

Проверки и поставка выполняются локально. CI отключён; агент не выполняет действий на GitHub.

![Промышленная подстанция и завод, поверх оборудования — граф нейросети](docs/assets/power-grid-env-banner.jpg)

Платформа инженерной проверки алгоритмов управления распределительной сетью. Первая поставка — квазистационарный несимметричный фидер: импорт, preflight, внешний контроллер, набор сценариев восстановления, сравнение с baseline, отчёт и повтор.

Симуляция запускается локально. Кластер, Kubernetes и управление реальной сетью в этот проект не входят.

Симуляция не является допуском к управлению реальной сетью, real-time-режимом или полным EMT.

DAE-решатель, расширенные сети и пакет пуска/самозапуска: [пять реализованных блоков и ограничения](docs/DAE_AND_DOL_BLOCKS_RU.md).

Независимая сетевая сверка расширена на кольцевые схемы с насыщенными двигателями, трансформаторами и несколькими источниками; АВР сверяется с отдельным SI-эталоном.

Полная обмоточная физика двигателей, RMS-защиты/АВР/острова и независимые эталоны: [блоки 6–8, воспроизведение и ограничения](docs/EQUIPMENT_AUTOMATION_VALIDATION_RU.md).

Дополнительно реализованы аналитическая автоматика с DAE, сетевые многоклеточные эталоны, вихретоковые потери, идентификация параметров и фазное КЗ с общей точкой заземления.

## Что проверено и что только реализовано

Статусы лежат в `power_grid_env/capabilities.py`.

Проверено численно на авторских схемах, без натурных осциллограмм:

- фазный режим через OpenDSSDirect / DSS-Extensions: линии, трансформаторы `Dyn11` и `YNd11`, ZIP, КЗ, остров без источника, редукция Крона при явной твёрдой нейтрали;
- импорт DSS площадки 110/10/0.4 кВ: два ввода, LineCode, конденсатор, генератор, накопитель, PV, профиль и Redirect;
- симметричная цепочка этой площадки сходится с фазным OpenDSS лучше чем на 1e-5 о.е. по модулю;
- симметричный AC Ньютона и локальный AC OPF с пределом перетока;
- классическая машина, две машины, ЭДС первого порядка и статизм;
- переходные RL/RLC и сравнение шага dt с dt/2;
- DC-поток, PTDF и линейный WLS на малых схемах.

Реализовано и прогнано сценариями, но не объявлено `validated_for_declared_scope`: восстановление, блокировки, Gymnasium, инструменты LLM, холст VLM, локальный AC OPF. Distance, differential, полный EMT и hardware-in-the-loop остаются за пределами текущей поставки.

Документы требований: [техническое задание](AGENT_IMPLEMENTATION_SPEC_RU.md), [архитектура](IMPLEMENTATION_PLAN_RU.md). При расхождении приоритет у технического задания. Уравнения и допущения: [docs/physics](docs/physics/conventions.md).

## Установка

```bash
pip install -e ".[dev]"
```

Нужны Python 3.11+ и колёса `dss-python` / `opendssdirect.py`.
Для backend ANDES и полной регрессии установите `pip install -e ".[dev,rms]"`;
проверенный эталон ANDES закреплён в отдельном lock-файле EX-02.
`dev` сам по себе не устанавливает внешние моделеры.

## Команды

```bash
power-grid import --source cases/acceptance/feeder_north/feeder.dss \
  --sidecar cases/acceptance/feeder_north/pge-import.yaml \
  --out /tmp/feeder.json --report /tmp/import.json

power-grid preflight /tmp/feeder.json --report /tmp/preflight.json

power-grid suite cases/suites/restoration_v1.yaml --out reports/acceptance

power-grid validate
power-grid accept
power-grid schemas --out /tmp/pge-schemas
power-grid pilot cases/industrial/plant --out /tmp/pilot.json
```

`validate` пишет `reports/validation`. `accept` повторяет приёмку разделов 16–20: чужой DSS, отказ неполного файла, subprocess-контроллеры, suite, HTML, checksums, просмотр, replay, численные проверки, короткий Gymnasium rollout.

Внешний контроллер — отдельный процесс со строками JSON (`initialize`, `reset`, `act`, `close`). Примеры: `examples/controllers`. Subprocess не изолирует файлы и сеть недоверенного кода.

### Пределы на ветви AC-режимов

```bash
power-grid ac-envelope --input cases/ac-envelope/analytic-exits.json --out reports/my-ac-envelope
power-grid verify-ac-envelope reports/my-ac-envelope
```

Продолжение ветви с Q-ограничениями поддерживает мониторинг Vmin/Vmax,
полной мощности на обоих концах ветви и явно заданных токовых пределов в pu.
Сохраняются уточнённые интервалы входа/выхода, исходные нарушения и наихудшие
наблюдённые запасы. `completed=true` означает завершённое исследование;
допустимость точной цели указана отдельно в `target_within_monitored_limits`.
В этом аналитическом примере цель достигается с нарушениями.

IEEE14/30/118 проверены по независимым расчётам pandapower на двух шагах.
Демонстрационные токовые пороги в этих примерах — авторские, не паспортные
амперы оборудования. Монитор не отключает аппараты и не доказывает отсутствие
скрытых пересечений между точками. Подробности — в
[протоколе сравнения](docs/COMPARISON_PROTOCOL_RU.md).

### Распределённая балансировка P/Q

```bash
power-grid ac-dispatch --input cases/ac-dispatch/slack-q-limit.json --out reports/my-ac-dispatch
power-grid verify-ac-dispatch reports/my-ac-dispatch
```

Участники распределяют активный небаланс по явным весам с ограничениями P.
Q-предел прежнего slack может освободить напряжение, сохранив опорный угол;
угловую опору можно задать отдельно. Все исходные Pg должны быть указаны явно.
Тот же профиль подключён к CPF/envelope через `options.dispatch` при
`enforce_q_limits=true`. Динамика частоты и автоматическое образование островов
не моделируются.

### CPF и envelope с распределением нагрузки

```bash
power-grid ac-envelope --input cases/ac-dispatch-arc/analytic-entry.json --out reports/my-dispatch-envelope
power-grid verify-ac-envelope reports/my-dispatch-envelope
```

P-насыщение/возврат участников, Q-пределы всех регулирующих генераторов и сетевые
ограничения проверяются на одной ветви. Отчёт объединяет обнаруженные события
в `timeline_groups`; допустимость точной цели остаётся отдельным признаком.
Чистый CPF-пример: `cases/ac-pseudo-arc/distributed-participation.json`.

## Модель

Канонический JSON не подставляет заземление и группу соединений. Импорт DSS требует sidecar: иначе звезда не считается заземлённой, а `r1/x1` не становятся фазной матрицей. Формат выбран в [ADR 0002](docs/adr/0002-import-format.md).

Повреждённый участок в задаче восстановления известен алгоритму. Сопротивление КЗ, будущий профиль и скрытая метка сценария в наблюдение не входят.

## Длительные исследования

Общий runner возвращает полный фазный результат PF и исполняет QSTS с потоковым журналом, checkpoint и проверяемым продолжением. Подробности и ограничения: [воспроизводимые исследования](docs/DURABLE_STUDIES_RU.md).

```bash
python -m power_grid_env.cli run-study cases/studies/qsts_runtime.json --out /tmp/pge-study
```

RMS из сохранённой симметричной сети поддерживается через `rms/andes`: [модели, единицы и ограничения](docs/CANONICAL_RMS_RU.md).

Расширена поддержка многовольтного RMS и исправлены PV/clock-5 mapping: [результаты и границы масштаба](docs/MULTIVOLTAGE_AND_SCALE_RU.md).

Добавлены регуляторы TGOV1/SEXS/IEEEST, динамические КЗ с очисткой и RMS worker с дедлайном: [запуск, независимые эталоны и ограничения](docs/REGULATED_RMS_AND_FAULTS_RU.md).

GENROU с шестью состояниями и насыщением добавлен в общий RMS adapter: [паспорта, независимые эталоны и примеры](docs/GENROU_RMS_RU.md).

Малосигнальная устойчивость GENCLS/GENROU: матрица DAE, спектр и участие состояний, независимая численная сверка. [Возможности и ограничения](docs/SMALL_SIGNAL_RU.md).

Связанный с сетью динамический пуск асинхронных двигателей: одноклеточная модель третьего порядка, провалы напряжения, выбег/повторное включение и последовательный пуск группы. [Паспорта, примеры и независимая сверка](docs/INDUCTION_MOTOR_RU.md).

Добавлены тепловая память двигателя, отключение по порогу, блокировка повторного включения и строгая сверка I/U/скорости с CSV. [Модель, примеры и границы проверки](docs/MOTOR_THERMAL_AND_VALIDATION_RU.md).

Нагруженная инициализация работающих двигателей, вязкая/квадратичная нагрузка и сглаженное трение, скачки механического момента: [равновесие, независимые эталоны и ограничения](docs/MOTOR_OPERATING_POINT_RU.md).

Добавлен воспроизводимый анализ чувствительности motor study: OAT/Cartesian варианты, собственная инициализация, критерии пуска/восстановления, дедлайны и хешированные артефакты. [Протокол и границы результата](docs/MOTOR_SENSITIVITY_RU.md).

Совместная динамика GENCLS и асинхронных двигателей в одном сетевом решении: нагруженная инициализация, пуск, провал, изменение подачи генератора и моторный thermal trip. [Профиль, независимые проверки и ограничения](docs/COUPLED_GENERATOR_MOTOR_RU.md).

В совместном GENCLS/motor профиле доступны TGOV1 и SEXS: уставки, ограничители и восстановление, независимая SI-сверка и предельный случай ANDES. [Уравнения, воспроизведение и границы](docs/REGULATED_COUPLED_RMS_RU.md).

Совместный профиль расширен GENROU с шестью состояниями: переходные состояния ротора, Ra и насыщение, TGOV1/SEXS, смешанные группы GENCLS/GENROU и двигателей. [Уравнения и восемь независимых сверок](docs/GENROU_COUPLED_RMS_RU.md).

Добавлены конечные симметричные КЗ в совместной динамике и `fault-clearing`: заданные времена отключения, критерии восстановления, isolated worker и хешированные артефакты. [Паспорт, семь SI-сверок и границы вывода](docs/COUPLED_FAULTS_AND_CLEARING_RU.md).

Добавлены IEEEST MODE=1 в общей динамике и `coupled_small_signal`: локальные моды генераторов, моторов и регуляторов, независимая SI/tf2ss сверка и проверка неустойчивых рабочих точек. [Уравнения, примеры и ограничения](docs/COUPLED_PSS_AND_MODES_RU.md).

В совместной динамике доступны `line_open`/`line_close`: оба конца π-линии, зарядка, токи/мощности ветвей и атомарное снятие КЗ с открытием линии. Проверка связности заранее отклоняет острова. [Примеры и независимые проверки](docs/COUPLED_LINE_SWITCHING_RU.md).

Добавлен `generator_open`: электрическое отключение с нулевой сетевой инъекцией, продолжающими движение ротором/регуляторами и измерением AVR со стороны машины. [Семантика, независимые проверки и ограничения](docs/GENERATOR_ELECTRICAL_OPEN_RU.md).

Расширена независимая сверка общей сети с двигателями на 2–4 генератора GENROU/TGOV1/SEXS: индивидуальные команды, совместная инициализация, перестановки паспортов и смена базиса. [Модель, ограничения и воспроизведение](docs/MNLEX2_VALIDATION_RU.md).

Добавлен восьмисостоянийный **OEL2C** с выдержками, обратнозависимой ветвью,
anti-windup, восстановлением и суммирующей обратной связью в SEXS. Нативный
Modelica-блок через FMI 2 Model Exchange/CVODE замыкается на независимую
SI-сеть с генераторами и двигателями. Вариант `Dynawo cap-guard-v1` явно
отличается от исходника полосой распознавания верхнего предела; исходное
расхождение сохраняется отдельно. Адаптированный файл распространяется по

OEL2C теперь поддерживает явное `inactive_equilibrium` для загруженных
генераторов и двигателей: согласованы восемь состояний, anti-windup и
начальная память таймеров. Активные и пограничные начальные точки отклоняются.
[Нативная проверка и условия стационарного режима](docs/OEL2C_EQUILIBRIUM_RU.md).

Реализован `active_limited_equilibrium` OEL2C: загруженная точка при исчерпанном
воздействии PID, явная политика согласования задания AVR и отдельная диагностика
превышения тепловой уставки. Нативная проверка охватывает выход из ограничения
и защиту поля. [Уравнения, аудит задания и область применения](docs/OEL2C_ACTIVE_EQUILIBRIUM_RU.md).

OEL2C поддерживает совместное равновесие сети с заданным током возбуждения и фиксированным входом AVR: начальное напряжение определяется решением, PID остаётся внутри ограничений. Добавлены независимое SI/FMU-решение и сопоставление условных полюсов всего регулирующего контура. [Параметры, примеры и границы проверки](docs/OEL2C_CURRENT_REGULATION_RU.md).

Добавлен `selected_equilibrium` OEL2C: явный выбор стационарной ветви, нейтральная память уставки/PID и касание пределов таймера. Неоднозначные входы отклоняются; стационарность и полная устойчивость различаются в диагностике. [Параметры и независимая проверка](docs/OEL2C_SELECTED_EQUILIBRIUM_RU.md).

Добавлена конечная проверка совпадающих начальных порогов OEL2C: безопасные эквивалентные ветви принимаются, чувствительные точки отклоняются с набором свидетелей. Исходные пороги и физический ток сохраняются. Тепловое сравнение в Python теперь сохраняет исходный порядок операций Modelica, включая случаи чувствительного округления. Проверка включает независимые SI/FMU-точки и фактические производные нативного компонента. [Политика, ограничения и команды](docs/OEL2C_BOUNDARY_POLICY_RU.md).

Добавлен пятисостоянийный ESST1A с явными портами абсолютного takeover OEL,
UEL и дополнительного воздействия. Есть независимая сверка с исходной FMU
OpenIPSL в замкнутой сети, сценарии устранения КЗ и теплового отключения поля.
[Подключения, воспроизведение и границы EX-02](docs/ESST1A_VALIDATION_RU.md).

Для ESST1A добавлена [совместная нативная сверка с MNLEX2](docs/ESST1A_MNLEX2_JOINT_VALIDATION_RU.md):
обе исходные модели OpenIPSL работают в обратной связи общей сети.
Проверяются также сырые состояния и стороны сбросов; чувствительный случай
с двумя UEL выделен как отрицательное свидетельство.

Аудит проверяет весь журнал сбросов и физические каналы даже при ожидаемом
отрицательном результате. Доступна повторная проверка сохранённых доказательств
по закреплённому SHA-256 без повторной сборки FMU; предел событий остаётся 1 мкс.

Добавлена независимая проверка сгущения шага обоих решателей. При причинной
маршрутизации событий FMU подтверждён также стресс-сценарий двух активных UEL:
прежнее расхождение 0,173 с устранено в адаптере эталона. Непрерывные
атомарные корни устранили и оставшееся расхождение почти стационарного случая:
все 13 зарегистрированных сценариев согласуются на двух точностях при
прежнем пределе 1 мкс. Самосходимость не подменяет
сравнение с эталоном.

Причинный валидатор требует аудита исходных условий и обеих сторон каждого
нативного сброса. Запечатанные траектории можно повторно проверить по SHA-256
без исполнения FMU; чувствительность к округлению сохраняется как диагностика.

EX-02 расширен динамическим абсолютным OEL
`FieldCurrentPI_AbsoluteTakeover_v1`, явным подключением IEEEST к ESST1A и
локальным модальным анализом ESST1A/PSS/OEL. Независимые эталоны используют
SI-сеть и зафиксированные FMU OpenIPSL/MSL; реестр совместных воздействий
и модальных случаев — `benchmarks.ex02_cases`.
Это квалификация объявленных инженерных профилей; OEM-регуляторы,
произвольные гибридные моды и EMT этим не покрываются.

Примеры: `power-grid run-study cases/studies/ex02_overload_recovery.json
--out reports/ex02-example` и `power-grid run-study
cases/studies/ex02_modal_avr_pss_oel.json --out reports/ex02-modal`.
Контракт, воспроизведение и разделение зависимостей:
[ESST1A / EX-02](docs/ESST1A_VALIDATION_RU.md).

EX-03 добавляет 45-секундные случаи разгона, выбега, самозапуска и полного
охлаждения, 30-секундную сверку ESST1A и пять измеряемых конфигураций
динамической сети вплоть до `(2000 узлов, 8 двигателей, 4 генератора)`.
Независимая SI/MNA-модель проверяет состояния и комплексные напряжения
всех узлов. [Случаи, точные границы масштаба и воспроизведение](docs/EX03_LONG_RUN_AND_SCALE_RU.md).

Локальная поставка использует [воспроизводимый кандидат поставки](docs/EX04_REPRODUCIBLE_RELEASE_RU.md):
замороженные исходники, офлайн wheelhouse с хешами, лицензии зависимостей,
полный реестр собранных тестов и явные границы профиля Linux x86_64 / Python 3.12.
Прежний внешний EX-04 отменён пользователем; CI, публикация и внешняя подпись
не требуются. Локальные установки проверяют локальную воспроизводимость.

Для фиксированного поля GENCLS добавлен [аналитический якобиан совместной сети](docs/COUPLED_JACOBIAN_RU.md)
с одно- и двухклеточными двигателями и тепловыми репликами. Он учитывает взаимные
влияния машин и пересчитывает отклик после коммутаций. Развитие для GENROU и регуляторов
возбуждения описано в следующих этапах.


[Частично-гладкий аналитический якобиан GENROU/TGOV1/SEXS](docs/GENROU_JACOBIAN_RU.md)
расширяет этот путь на насыщение, непрерывные ветви ограничений регуляторов,
смешанные сети GENCLS/GENROU и тепловые отключения статора. Дальнейшие профили расширяют этот путь на PSS, droop OEL, ESST1A, MNLEX2 и защиту ротора I²; single-OEL2C описан ниже.


[Аналитический профиль IEEEST и droop OEL](docs/PSS_DROOP_JACOBIAN_RU.md)
включает семь состояний PSS, строгую блокировку по напряжению и двухсостоянийную
инженерную обратную связь по току возбуждения. Совместный контур отдельно
сверяется с физической SI-схемой и полиномиальной реализацией PSS.


[Аналитический ESST1A и абсолютный PI OEL](docs/ESST1A_JACOBIAN_RU.md)
добавляет производные пяти состояний возбуждения, селекторов, подвижных границ
выпрямителя и back-calculation. Профиль отдельно сверяется с закреплённым
OpenIPSL/MSL в независимой SI-сети. UEL и OEL2C в этот путь не включены.

MNLEX2 и тепловая защита ротора получили аналитические производные совместно с AVR/PSS/PI-OEL: [область поддержки и воспроизведение NA-05](docs/PROTECTION_JACOBIAN_RU.md).

[Аналитический OEL2C (NA-06)](docs/OEL2C_JACOBIAN_RU.md) добавляет восемь состояний ограничителя и сетевые связи при текущем clock/active set. Автоматический маршрут квалифицируется для одного OEL2C; несколько OEL2C сохраняют FD из-за зафиксированного случая перестановки совпадающих событий.

[NA-07: пакетирование независимых below-clock событий OEL2C](docs/OEL2C_EVENT_BATCH_RU.md) добавляет явную политику `independent_below_clock_batch_v1` для нескольких лимитеров. Legacy-входы сохраняют прежнюю обработку и FD; новый маршрут проверяется отдельными сценариями.

[NA-08: масштабирование сетевых чувствительностей и CSC](docs/JACOBIAN_SCALING_RU.md) ограничивает временные RHS восемью портами и хранит только нужные строки. Явное `jacobian_format: csc` включает точную CSC-передачу в Radau/SuperLU; по умолчанию сохраняется dense. NA-08 использовал плотную сборку; потоковая сборка добавлена в NA-09 ниже.

[NA-09: потоковая сборка CSC](docs/STREAMED_JACOBIAN_RU.md) строит встроенные аналитические якобианы блоками до 32 столбцов, без полной плотной identity/result при больших размерностях. Добавлены проверки 400/424 состояний: 8 генераторов, 32 double-cage двигателя и регуляторы. Итоговая CSC и портовые связи могут оставаться плотными.

[NA-10: независимый восьмимашинный эталон](docs/EIGHT_MACHINE_NATIVE_RU.md) добавляет проверку исходных сценариев NA-09 (8 генераторов, 32 двигателя, PSS и ограничители), токов обеих клеток и теплового отключения с блокировкой повторного пуска. Результат определяется связанным отчётом; общая промышленная квалификация остаётся отдельным вопросом; внешний EX-04 отменён пользователем.

[NA-11: прямые сетевые касательные и J·v](docs/NETWORK_TANGENTS_RU.md) добавляет явный `jacobian_network: direct_solve` для CSC и аналитическое произведение якобиана на векторы без полной матрицы. Портовая квадратная матрица в этих путях не строится; Radau остаётся CSC/SuperLU. Область проверки и ограничения приведены в документе.
